# 私域枢纽 PrivHub 部署说明

精简部署包。只含**本项目源码** + 一份声明底座依赖的 `package.json` + 启动器 `start.bat`。
不包含 `node_modules`，也不包含 DeepSeek Harness 的 70+ 个开发期源码包（`packages/`）。

## 组成

- `home/profiles/privhub/` —— profile 配置（声明挂载到底座的插件：`dsh-base` / `dsh-web-app` / `privhub-server`，并把 webserver 绑定到 `0.0.0.0`、禁用文件盘用不上的 AI 对话 UI）
- `privhub-app/server/` —— 咱们的后端接口插件（登录、目录、文件管理，复用底座 webServer）
- `privhub-app/frontend/` —— 前端静态文件（预编译，无需构建）
- `privhub-app/data/users.json` —— 账号（仅保留 `admin` / `user1`，测试账号已移除；`sessions.json` 不入库，运行时生成）
- `package.json` —— 声明三个底座发布包 + `privhub-server`
- `start.bat` —— 启动器

## 底座是什么

PrivHub 跑在"复制出来的一份独立底座"之上，底座是三个可发布的 npm 包：

- `@deepseek-ai/dsh` —— 启动器（提供 `dsh` 命令 / `lib/bin.js`）
- `@deepseek-ai/dsh-base` —— 底座核心（cordis 栈 + 工具/会话/权限等）
- `@deepseek-ai/dsh-web-app` —— 浏览器界面层

这三个包**互相依赖、并已发布**，运行时不需要 Harness 的 `packages/` 开发源码。
本仓库里那一大坨 `packages/dsh-*` 只是参考用的 harness 源码，部署时不打包。

## 宿主机运行步骤

1. 准备 Node：**>= 22.19.0 或 >= 24.0.0**（底座要求）。
2. 将本目录整包传到宿主机并解压。
3. 双击 `start.bat`：
   - 首次运行会自动 `npm install`，拉取上述三个底座包 + `privhub-server` + `tsx`；
   - 随后启动服务，监听 `0.0.0.0:3181`。
4. 浏览器访问：`http://127.0.0.1:3181`（局域网用 `http://<本机IP>:3181`）。

## 默认账号

- `admin` / `admin123`（系统管理员）
- `user1` / `user123`（普通员工）

## 注意事项（重要）

- **底座包需可从 npm 源获取**：公共源或你们的内部源均可。若宿主机无这些包，
  安装会失败——此时由宿主机侧配置正确的 registry，或提供本地包后重试 `npm install`。
- 端口固定为 `3181`，由 `start.bat` 的 `--port 3181` 与 profile 的 `cordis.patch.yml` 共同决定。
- 不修改任何源码；如需改前端/后端逻辑，改 `privhub-app/` 下对应文件后重传即可。

## 冒烟测试记录（已通过）

在开发环境借用已验证的 `node_modules`，把 `DSH_HOME` 指向本部署包的 `home`、把 `privhub-server` 用 junction 接到 profile 的 `node_modules`，以 `--host 0.0.0.0` 启动后逐项验证：

- `GET /` → **HTTP 200**，返回 dsh Web 外壳 HTML（含 `__DSH_BOOT__`，约 48KB）。
- `POST /privhub/api/login {"username":"admin","password":"admin123"}` → **HTTP 200**，返回 token + 用户信息（role=admin）。
- 错误密码 → **HTTP 401 `用户名或密码错误`**。
- 无 token 访问 `/privhub/api/me` → **HTTP 401 `未登录`**。
- 启动日志：`dsh web: http://127.0.0.1:3184 (LAN: http://<本机IP>:3184)`，证明 profile + 3 个底座包 + privhub-server 插件 + 前端 + 鉴权链路在 `0.0.0.0` 上全部打通。

结论：本部署包的 profile 装配、插件挂载、前端加载、账号鉴权均工作正常，可直接交付生产环境。

## 本次修复的两个真实部署缺陷

1. **`tsx` 必须放到 `dependencies`**：`tsx` 是运行期必需（用于加载 `privhub-server` 的 TypeScript 源码），原先误放于 `devDependencies`。生产机 `npm install` 会省掉它，导致启动即崩。已移入 `dependencies`。
2. **`start.bat` 入口需自适应**：原先硬编码 `lib/bin.js`（仅发布态）。已改为先探测 `lib/bin.js`，不存在再回退到 `src/bin.ts`，发布态/源码态都能起。

## 关键环境变量（勿删）

- `DSH_HOME` → 指向 `home`（profile 与运行时数据根）。
- `PRIVHUB_FRONTEND_DIR` → 指向 `privhub-app/frontend`（web-app 底座**必须**用它定位前端 dist，缺失会报 `frontend dist not built`）。
- `PRIVHUB_PORT` → 端口号（默认 3181）。
- 后端用 `process.cwd()` 定位 `privhub-app/data/users.json`，故 `start.bat` 以部署包根目录为 cwd 启动，**不要改成别的 cwd**。
