## 0. 怎么用这份契约（**改前端/契约代码前，先查这一节**）

### 0.1 五步走

| 步 | 动作 | 为什么 |
|---|---|---|
| 1 | 先在第 1 节查清「你要动的 `view` / `slot` 名，现在归谁声明、骨架在哪一行渲染它」 | 一个名字至少出现在 **3～5 处**（manifest 声明 / 骨架渲染分支 / `openBarItem` 分发 / 图标栏过滤 / 管理控制台路由表），漏改任何一处都**不报错** |
| 2 | 再在第 3 节确认「你要动的桥键，有没有插件在**模块顶层解构**它」 | 顶层解构 = 硬依赖。键不存在 → 该插件**整体 import 失败**，界面只表现为「某个入口不见了」 |
| 3 | 再在第 4 节确认「你要改的事件名，谁在发、谁在听」 | 前端 `bus` 与后端 `ctx.emit` 是**两套同名不同域**的总线；发出去没人听**不会有任何提示** |
| 4 | 动手前用第 6 节的反查表过一遍「改这里 → 会波及这些」 | 这张表就是本次讨论中「修订顶栏连撞两次」那类事故的对症清单 |
| 5 | 改完照第 7 节列出的**已有校验**跑一遍；第 8 节的已知缺陷表逐条对照 | 现有校验只覆盖 31 个插槽里的 2 个、26 个桥键里的 5 个，**大部分连线没有网** |

## 1. 视图 ↔ 插槽 ↔ 插件（**14 个 view 全覆盖**）

### 1.0 先记住这条：`view` 名和 `slot` 名**不是一回事**

一段完整的连线是 **5 环**：

```
插件 manifest 的 barItems[].view（点击标识）
   → 骨架 openBarItem 按 view 分发（frontend/index.html:748-764）
   → 骨架模板用 slotComps['某个 slot 名'] 渲染（frontend/index.html:1029-1094）
   → 插槽里的组件来自「插件 client/index.js 的 export default.slots 的键」
   → 该键是否被装配，取决于 manifest 顶层 slots 数组里有没有写（shell 服务端闸门）
```

`view` 名与 `slot` 名**有 6 处不一致**（`files`/`trash`/`search`/`favorites`/`rag`/`agent`），这是最容易连错的地方。
