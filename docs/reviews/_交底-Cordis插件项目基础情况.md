## 1. 技术底座与形态（**这是理解一切的前提**）

| 项 | 事实 |
|---|---|
| 底座 | **纯 Cordis**：仅依赖 `@deepseek-ai/cordis` 4.0.1 + `@deepseek-ai/schemastery` 3.18.1 + `tsx`，**无重型 Web 框架**，整个目录搬走即可运行 |
| 后端 | **自研 `node:http` webServer**（`privhub/src/web-server.ts`），**仅支持精确匹配路由**（`kind: 'exact'`），无 param/prefix、无中间件链 |
| 路由规模 | **112 条**后端路由，分布于 **31 个**插件 |
| 前端 | **Vue 单页骨架**（`privhub/frontend/index.html`，**1130 行单文件**）+ 手写 CSS，**无打包链** |
| 通信 | 骨架通过 **`window.PrivHub`**（骨架 26 个键 + 插件运行时追加）暴露给插件；另有**事件总线 `bus`** |

> ⚠️ **重要消歧**：这是 **PrivHub 自己的 Cordis 插件体系**，与 DeepSeek Harness 自身的插件体系**不是同一套东西**。判断插件语义时**以项目内文档与源码为准**，不要套用其他平台的插件模型：
> - `docs/PrivHub-插件架构（Cordis 原理重搭）.md`
> - `docs/PrivHub-架构与功能说明.md`
> - `docs/PrivHub-插件实现规则.md`

## 2. 插件架构：三层 + 自动发现

| 层 | 内容 | 装配方式 |
|---|---|---|
| **L1 六枢纽** | `core` / `auth` / `files` / `trash` / `admin` / `shell` | `privhub/src/main.ts` 里 **`CORE_PLUGINS` 硬编码 17 项**，有依赖顺序 |
| **L2 能力 Service**（10 个） | `storage` / `events` / `audit` / `acl` / `watermark` / `search` / `meta` / `collab` / `office` / `model` | 同上 |
| **L3 功能插件** | `CORE_PLUGINS` 清单**之外**的插件 | **目录扫描自动发现装配**（装卸 = 增删 `plugins/` 目录，无需改代码） |

**已知的架构瑕疵（不必重复报，已有条目）**：`CORE_PLUGINS` 硬编码清单 与 L3 自动发现**双源维护**；漏改时**不报错**，只表现为启动日志少一行（账本 `E1`）。

### 2.1 插件目录约定

```
privhub/plugins/<插件名>/
├── package.json
├── src/index.ts          ← 服务端（不是每个插件都有）
└── client/
    ├── manifest.json     ← 前端声明：id / title / icon / description / slots / barItems
    ├── index.js          ← 前端入口（export default { id, slots: {...} }）
    └── ...               ← 其他模块、样式、vendor
```

## 3. 前端装配机制：是「发现」，不是「注入」

**关键结论：插件前端代码从不写入主页面。`frontend/index.html` 在任何安装/卸载过程中都不会被修改。**

```
① 浏览器打开 index.html（骨架：只含宿主布局与桥）
② 骨架调一次 GET /privhub/api/shell/manifest
③ 服务端【现场扫描】plugins/*/client/manifest.json，返回清单（id/标题/图标/slot/entry）
④ 骨架对清单每一项 import('/privhub-plugins/<名>/index.js')
⑤ 卸载 = 删掉插件目录 → 下次扫描清单里没有它 → 骨架根本不会去 import
```

由此推出：**卸载零残留**（已实测：插件数 31→30、其前端资源 200→404，清单有 5s TTL 缓存）。完整卸载语义 = **删目录 + 重启服务**（已注册的路由属后端，需重启才真正卸载）。

**槽位渲染**：骨架用 `<component v-for="c in slotComps[slot]" ...>` 逐个渲染；`slotComps` 按**插件 manifest 顶层 `slots` 数组**填充（`frontend/index.html:841` `const arr = this.slotComps[slot] || (this.slotComps[slot] = [])`）。

> ⚠️ 两个**同名但不同义**的 `slot` 概念，极易搞混（此前已有评审者栽在这里）：
> - `barItems[].slot` —— 只管**这个图标进哪个桶**（`shell/client/index.js:75-77` 的过滤）
> - manifest 顶层 `slots[]` —— 才决定**渲染到哪个插槽**
> 二者**无关**。凡涉及 slot 的结论，必须两处都读，并回读渲染分支。

## 4. 核心概念与数据

| 概念 | 位置 | 可见性 | 智能体权限 |
|---|---|---|---|
| **项目** | `data-files/<项目名>/` | 按账号授权（管理员可见全部） | **只读** |
| **个人空间** | `data-files/<真实姓名>/` | **仅本人**（管理员亦不可见，只有审计记录） | 读写（即**智能体沙箱**） |

- 个人空间注册时按真实姓名自动创建，姓名全局唯一；**不进查重 / 向量化 / 全文索引**，**系统永不自动删除**。
- 智能体写入一律落到绑定的个人空间；写项目返回 `403 AGENT-4032`。
- 智能体用 `X-Agent-Key`，与网页登录（会话）**完全分离**。
- 落盘加密：AES-256-GCM（文件头 `PHENC1`）；密钥 `data/secret.key` 丢失 = 数据无法恢复。
- ⚠️ 例外：`settings.json`、`comments.json`、`publish.json`、`invites.json` 目前为**明文存储**。

## 6. 不可违背的既定约束（**违反 = 建议作废**）

1. **功能入口必须保持在左侧图标栏，不改交互布局**（用户明示）。
2. **无打包链是特性**，改完刷新即生效；不得默认引入构建步骤。
3. **每个插件的前端必须完全在自己的目录内** —— 卸载插件 → 其前端一并消失。
4. **前端保持一个主界面**：骨架只做容器与总线；各区域按功能拆独立文件（顶栏一个文件、侧栏一个文件、每个弹窗一个文件）。
5. **禁止插件用 DOM 类名操作别的插件的界面** —— 跨插件 `querySelector` 要改成插槽/事件契约。
6. **右侧详情面板里「收藏/权限/批注评论/生成页面/发布链接/版本历史/向量数据库」等按钮硬编码在 `explorer-v3` 的 `detail.js`，是【有意的临时代码】，不是缺陷**。待对应插件开发到那一步再迁回。**不要当缺陷提。**
7. **测试/示例数据保持原样**（含 `data-files/.agents/` 里的早期残留）。
8. 改动纪律：非示例数据随改动迁移并附说明；**写 `CHANGELOG.md` + 递增版本号**；人工确认无误后提交推送，同步项目说明文件。
