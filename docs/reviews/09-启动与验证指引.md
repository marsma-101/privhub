**关于"默认账号"这句话的核实结果**（主子特别交代要自行核实）：

- README.md 第 57 行原话：*"首次启动自动生成默认账号：`admin` / `admin123`（登录后请立即修改密码）；另有示例普通账号 `user1` / `user123`。"*

### A1 · RAG 检索入口——**这条最值得先验**

**背景（一句话）**：检索功能里有一段代码把"读语料清单"写在了"用清单"之后，导致每次调用都立刻报错，整个 AI 检索/问答入口等于废掉。修法只是把读取提前。

**怎么看（界面）**
1. 左侧图标栏点 **🤖 AI 工具**。
2. 顶部页签点 **🧰 语料治理**（管理员才有这个页签）。
3. 内层页签点 **💬 问答**。
4. 范围选 **全部可见项目**，输入框里打「合同」，点 **发送**。

**期望看到**
- **不会**出现 `Cannot access 'manifest' before initialization`。
- 本机**尚未接入模型**，所以会看到这句提示：**「模型未配置（请先在 RAG 界面/API 填写模型地址）」**。
  ⚠️ 这句话**恰恰证明检索已经修好**：程序是"先检索、再交给模型回答"，报的是模型这一步的错，说明前面的检索已经顺利跑完了。
- 如果主子想看到真正的回答：先到 **🤖 模型接入** 页签填一个本地/在线的模型地址，再回问答页提问，就会出现答案 + **📚 引用来源**列表。

**没修好会看到什么**
- 点发送后，输入框附近直接冒红字 `Cannot access 'manifest' before initialization`（旧代码是必现，不是偶发）；或接口直接 500。

**不想点界面？最硬的验法（浏览器地址栏一行）**
先用 `admin` 登录，然后**在同一个浏览器里新开一个标签页**，粘贴下面这行回车：

```
http://127.0.0.1:3180/privhub/api/rag/search?q=合同&collection=all&k=3
```

**[实测] 应看到（我用等效方式跑出来的原文）**：

```json
{"ok":true,"hits":[{"docId":"_TAG验证_mtfc8f3y::合同A.md","project":"_TAG验证_mtfc8f3y","path":"合同A.md","chunkId":"_TAG验证_mtfc8f3y::合同A.md#c0","snippet":"# 合同"},{"docId":"_TAG验证_mtfcj3hb::合同A.md", ... },{"docId":"_TAG验证_mtkrkias::合同A.md", ... }]}
```

看到 `"ok":true` 和 `hits` 里有一条条来源，就是检索通了。**若看到 `{"ok":false,"error":"未登录"}`，是登录态过期，重新登录再试。**

### A2 · 服务不再被打死（这条界面上验不了，说清为什么）

- **为什么验不了**：这条修的是"某次上传的文档解析失败时，会不会把整个服务连带弄死"。它只在**出现解析失败**的那一刻才表现出来，正常操作不会触发；而且真触发了，表现就是"网页突然全打不开"——那不是能"看着验"的现象，是事故。
- **它现在由什么保证**：一条可重复运行的自动断言 `privhub/tests/rag-resilience.mjs`（随测试脚本 `tests/run-all.mjs` 一起跑）。它故意注入一次摄取失败，然后检查服务是否还活着。
- **想间接看一眼**：进入 **🤖 AI 工具 → 🧰 语料治理 → 📊 语料总览** 时，后台接口 `/privhub/api/rag/status` 里多了一个字段 `ingestQueue.errors`。
  **[实测] 本次为 `0`**（意思是：没有任何文档摄取失败）。若它变成大于 0 的数字，含义是"有文档没能进语料库，**但服务还活着**"——这正是这次修复想要的效果。

### A3 · 点开头的名字被拒

**怎么看**
1. 进任意一个项目（比如 `公共`）。
2. 点 **新建文件夹**（或右键菜单里的同名项）。
3. 输入框里打 `.测试`（**前面那个点必须打**），确定。

**期望看到**
- 屏幕角落弹出**红色**提示：**「新建失败」**。
- 列表里**不会**出现任何新东西——包括"看不见但确实建了"的文件夹。

**没修好会看到什么**
- 提示 **「文件夹「.测试」已创建」**（绿色，像成功），但列表里找不到它；用搜索也搜不到。原因是"点开头"的条目被系统有意隐藏，于是数据看起来像丢了。
- 一句话区分：**修好后是"当场被拒"，修好前是"假成功 + 找不到"。**

**同一规则的另一个入口（顺手可再验一次）**
- 上传一个文件名以点开头的文件（例如 `.测试.md`）→ 期望红字 **「文件名无效」**。

**实测留痕**
- **[实测]** `.测试` → HTTP `400`，返回 `{"ok":false,"error":"新建失败"}`；随后确认 `data-files/公共/.测试` **没有被创建**。
- **[实测]** 为了防止中文编码干扰结论，我又用纯英文的 `.zzz` 试了一次 → 同样 `400 {"ok":false,"error":"新建失败"}`。所以"被拒"确实是因为**那个点**，不是因为中文。
- **[实测]** 对照：用带斜杠的非法名 `a/b` 也是 `400 {"ok":false,"error":"新建失败"}`，说明这条校验在正常工作。
- **[未测]** "合法名字能正常建出来"这一侧我没有实测——因为那会**真的在真实数据目录里建文件夹**，越界了。请主子在界面里用一个正常名字自建一个试试（比如 `临时验证`），验完删掉即可。
- **已知文案欠精细**（不是这次要修的）：被拒的原因只报「新建失败」，没有点明"名字不能以点开头"。这条只是不友好，不是错。

### A4 · 同名上传不再静默覆盖

**怎么看**
1. 进任意一个目录（比如 `公共`）。
2. 上传一个文件，例如 `a.txt`（内容随便写几个字）。
3. **不要改名，再上传一次同一个 `a.txt`。**

**期望看到**
- 屏幕角落弹**红色**提示，文案形如：**「上传失败 1 个文件」**。
- 屏幕底部的**上传抽屉**里，这一行显示红字：**「同名文件已存在：a.txt（为避免覆盖，请改名后重新上传）」**。
- **原文件的内容一字未变**（这是关键：不是"报错了也照样覆盖"）。

**没修好会看到什么**
- 第二次上传也提示成功；原文件被**静默覆盖**，而且不会留下任何"被覆盖过"的痕迹。

**实测留痕（我用真实数据做的只读式验证，没有产生任何写入）**
- 目标：已存在的 `公共` 项目里的 `公告.txt`，对它发一次同名上传。
- **[实测]** 返回：`HTTP 409`，响应体原文 ——

```json
{"ok":false,"error":"同名文件已存在：公告.txt（为避免覆盖，请改名后重新上传）"}
```

- **[实测]** 该文件上传前后 **SHA256 完全一致**（`EEB7884…A32452`），修改时间也没变 → 没被覆盖。
- **[实测]** 目录里**没有**留下 `.part` 之类的半截临时文件。
- 结论：拦截发生在"读上传内容"**之前**，所以既不覆盖、也不留垃圾。

### A5 · 兜底异常落日志（不用操作，知道位置就行）

**日志在哪**

```
G:\program\dsh-SQL\privhub\data\logs\privhub-YYYY-MM-DD.log
```

- 一天一个文件，自动保留最近 **14 天**，过期的自动删除。
- 今天（2026-09-20）这一份是：`privhub\data\logs\privhub-2026-09-20.log`。
- 用记事本直接打开即可；记的是**系统错误与启动信息**，不是谁点了什么（"谁点了什么"在 `data/audit.jsonl`，那是另一套，不要动）。

**修好前后的差别**

- 修好前：接口报 500 时，**日志里一个字都没有**，只能对着网页干瞪眼。
- 修好后：日志里会多出一行形如
  `[时间] [ERROR] [webServer] 路由处理异常 POST /privhub/api/xxx: …`，后面跟着完整堆栈。

**另外还有两条进程级兜底**（同样只看日志即可，服务不会因此退出）

- `[guard] 未处理的 Promise 拒绝（unhandledRejection），服务继续运行: …`
- `[guard] 未捕获异常（uncaughtException），服务继续运行: …`

看到这两行不用慌：它们的意思是"出过一次意外，已记录，服务还在跑"。反之，**如果日志戛然而止、之后什么都没有，那才是需要查的**。

## 四、启动 / 停止（只写方法，本次未执行停止）

### 现在这个实例

- 启动方式（等价于在 `G:\program\dsh-SQL\privhub` 下双击 `start.bat`）：

```
cmd /c start.bat 3180        # 工作目录 G:\program\dsh-SQL\privhub
```

- 它内部做的事（读 `privhub/start.bat` 得到）：设定 `PRIVHUB_ROOT=%~dp0`（即 privhub 目录）、`PRIVHUB_PORT=3180`，然后执行
  `node --import tsx/esm src/main.ts --port 3180`。
  `PRIVHUB_ROOT` 很关键：它决定 `data/`、`data-files/`、`plugins/` 从哪里找；缺省会退回"当前目录"。

### 要停服务时（**以下命令我没有执行**，供主子按需使用）

```
:: 方式一：已知 PID（本次是 37164，重启后会变）
taskkill /PID 37164 /T /F

:: 方式二：先按端口查出 PID，再停
netstat -ano | findstr :3180

:: 方式三：任务管理器 → 详细信息 → 结束 node.exe
::         （⚠ 这台机器上还有别的 node 程序在跑，别误杀）
```

- `PID 37164` 是 **node 服务本体**；它的父进程是 `cmd` **PID 35128**（那个跑 `start.bat` 的窗口）。
- `/T` 会连子进程一起结束；`/F` 是强制。正常收尾建议先只结束 node，再关那个 cmd 窗口。
- ⚠ **如果主子当初是双击 `start.bat` 启动的**：那个黑窗口末尾有个 `pause`，**关掉窗口 = 停掉服务**，这一点与"分离进程"无关，仅适用于手动双击的情况。

## 五、出问题怎么回滚（只写方法，**我没有执行任何回滚**）

### 5.1 只想让服务停下 → 见第四节

### 5.2 代码要退回 A 批之前

A 批这次改动**尚未提交**（`git log` 最新一条仍是 `5f1beb1 v3.1.0 管理控制台外壳…`）。撤掉的办法：

```
:: 把【工作区全部未提交改动】收进 stash（可随时找回）
git stash push -m "A批修复-临时收起"

:: 看收起来了哪些
git stash list

:: 想找回
git stash pop
```

⚠ **注意范围**：`git stash` 收走的是**所有**未提交改动，不只是 A 批那几条。本次受影响的文件一共这些（`git diff --stat` 实测）：

```
CHANGELOG.md
privhub/package.json                                  （版本号 3.1.0 → 3.1.1）
privhub/plugins/privhub-core/src/index.ts             （A3 点名规则）
privhub/plugins/privhub-files/src/index.ts            （A4 同名上传拦截）
privhub/plugins/privhub-svc-rag/src/index.ts          （A1 检索 + A2 队列）
privhub/src/main.ts                                   （启动日志 + 进程兜底）
privhub/src/web-server.ts                             （A5 异常落日志）
privhub/tests/run-all.mjs                             （A2 断言接入）
（另有未跟踪的新文件：privhub/tests/rag-resilience.mjs）
```

**只回滚某一个文件**的话，用：

```
git checkout -- privhub/plugins/privhub-svc-rag/src/index.ts
```

**⚠ 不建议用 `git reset --hard`**：它会把工作区改动直接抹掉、连 stash 都不给，而且会连带处理掉 `privhub/tests/rag-resilience.mjs` 这类未跟踪文件的相关痕迹。要退就退，别"硬退"。

### 5.3 数据要不要回滚？

**不用，也不要动。** A 批五条**没有一条涉及数据结构变更**，不存在需要回滚的数据迁移。

- `privhub/data/`（账号、会话、审计、语料、向量库）与 `privhub/data-files/`（真实文件）**保持原样即可**。
- 启动服务会正常写日志（`data/logs/`）和运行态文件，这是**正常使用**，不是污染。
- **绝对不要**为了"回到干净状态"去删 `data/`、`data-files/`，或删账号、清库——那是真实数据，删了不可恢复。
