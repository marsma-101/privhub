## 0. 一句话结论

**`privhub-files-edit-md` 的编辑器由「预览开/关」两态改为三态：`纯编辑`（默认）/ `纯预览` / `分屏`；内嵌与浮层两个形态用同一个状态字段、同一套按钮排。**

- 默认态**一律纯编辑**（md 与 `.txt` 同口径），**不做持久化** —— 每次打开文件都回到纯编辑。
- 纯预览**不是**退出编辑态：正文、`dirty`、编辑会话号（`_session`）一个字都不动，点回编辑接着改；退出编辑态仍只有「✕ 只读」那一条路。
- 三个坑各自有断言守着：Ctrl+S 走**组件级文档监听**（三态通用）、浮层 EasyMDE 挂载点用 `v-show` 保命、模板串里**零反引号**（L 段仍绿）。
- `frontend/index.html` 一字未动；不动 manifest / 插槽 / 打包链 / 别的插件；`data/`、`data-files/` 只读；未做 git 操作；版本号 **3.1.1 → 3.1.2**（主子拍板，`privhub/package.json` 已同步）。

> ⚠ **观感一律未实测**（本文件 §5）。仓库里没有浏览器测试，前端走 CDN，本机也没有可用的 Vue 运行时挂载环境。
> 本批能证明的是**状态机 + 真模板渲染出的节点 + 源码事实**，**不能**说"看着正常"；前端交互测试归另一条线。

## 1. 动机

三件事凑在一起，把「编辑器现在是什么形态」这件事弄成了**说不清**的状态：

| 病根 | 为什么危险 |
|---|---|
| `data()` 里 `previewOpen: true`，`openEditor()` 里 `= this.isMd` | md **一打开就是双栏**：想看整篇渲染结果，得先手动关掉预览；「纯编辑」这个形态在界面上根本不存在 |
| 只有「👁 预览开/预览关」一个按钮 | 两态开关表达不了三态（纯编辑 / 纯预览 / 分屏），用户要的「只看预览」得靠"关掉编辑栏"绕，语义是反的 |
| 内嵌与浮层**各有一套栏位写法** | 浮层那套没有三态概念、也没有 `ref`；两边行为不一致，改一处漏一处 |

而三态化本身会**踩响三个已有的地雷**（都不是新写的代码引入的，是三态把它暴露出来）：

1. **Ctrl+S 挂在哪** —— 迁前挂在源码 textarea 上（`@keydown="onSrcKeydown"`）。纯预览态编辑栏不再渲染 ⇒ 挂在它上面的监听**收不到事件** ⇒ 快捷键静默失效（不报错、不提示）。
2. **浮层 EasyMDE 的挂载点** —— `initMde()` 用 `document.getElementById('privhub-md-editor')` 取节点。三态若把浮层编辑栏写成 `v-if`，切到纯预览时节点被卸载，EasyMDE 就攥着一个**已销毁的节点**（不报错，但编辑器哑掉、下一次保存取到的是旧正文）。
3. **这个文件是 `template:` 反引号模板串** —— 注释或 CSS 里出现一个反引号就当场结束模板串 ⇒ 整个模块解析失败 ⇒ 该插件前端整块打不开（本项目踩过，当时 462 条断言还全绿）。

### 2.1 Ctrl+S 为什么选「组件级文档监听」（取舍写清）

三态把「编辑栏在不在」变成了变量，而**键事件的落点取决于焦点**。两条路：

| 方案 | 够不够 | 缺点 |
|---|---|---|
| ① 挂在「两栏共同的外层容器」上 | 只在**焦点落在那棵子树里**时有效 | 纯预览态就算点一下预览区把焦点带进去，焦点一旦跑到工具栏按钮 / 地址栏 / 其它面板上，事件根本不经过那棵树 ⇒ 仍是"有时候不好使"。而且"哪棵子树是共同的"这件事会随栏位写法变化再改一次 |
| ② **组件级文档监听**（本批采用） | **只要编辑器开着**，无论焦点在哪、当前哪一态，都落在同一个处理函数上 | 监听必须按生命周期挂/摘干净；必须带 `this.open` 闸（否则会吞掉编辑器之外整个界面的 Ctrl+S） |

⇒ **选 ②**：把「能不能保存」与「哪一栏可见 / 焦点在哪」彻底解耦 —— 这是"三态下都成立"的**充分**做法，而 ① 只是"通常成立"。

三条纪律写进了代码注释与断言：

- **不许两处都挂**（容器 + 文档）：同一个 Ctrl+S 会冒泡到两处 ⇒ 保存发两次（两个 PUT）。断言 `【源码·单点】` 钉住"代码里（**剥注释**）再没有任何 `@keydown` 绑定"。
- **闸门**：`this.open === false` 时一个键都不吞（断言 `【Ctrl+S·闸门】`）。
- **摘干净**：`beforeUnmount` 里 `unbindDocKeys()`，否则"一个已死的组件还攥着整个界面的 Ctrl+S"（断言 `【Ctrl+S·卸载】`）。
- **形态判断在先**：环境（或单测的 DOM 桩）没有 `addEventListener` 时**什么都不做、不抛错** —— "退化成不监听"可接受，"挂载时抛错"会让整块界面打不开。副作用：K 段那套老沙箱的 DOM 桩里**没有** `addEventListener` ⇒ edit-md 在那儿自然不挂监听，这一点在 N 段单独如实说明（N 段把桩补上才测得到）。

### 2.2 浮层 EasyMDE 那条坑

`initMde()` 的挂载点 id 从**组件自己的源码**里取（`getElementById('privhub-md-editor')`），并与**真模板渲染出的 vnode** 里那个 `textarea` 的 id 对比 —— 两边改名不同步当场变红（断言「浮层模板渲染出的 textarea id 与 initMde() 取的是同一个」）。

浮层编辑栏用 `v-show` 之后：三态下节点**始终留在 DOM 里**，只变 `display`。N 段的假 DOM 里，「节点在不在」**由真模板渲染出的 vnode 树说了算**（不是测试自己拍脑袋），于是"`v-if` ⇒ `getElementById` 返回 null ⇒ EasyMDE 拿到 null"这条链在沙箱里也真跑得出来（NC2 实测：`模板里这个 id 的节点在树里=false、getElementById 拿到的=null`）。
