## 一、一页结论

**七份报告的指向高度集中，可以压成一句话：**

> **这个项目的块切得没错，病在「缝」上——而所有缝都有一个共同症状：连错了不吭声。**

六路独立指向同一件事：**出错没有出口**。

| 角度 | 它看到的"不吭声" |
|---|---|
| 01 架构 | 装配漏了不打日志（`main.ts:53,58` 取 `process.cwd()`，扫描根不对时 L3 **一个都不装且零日志**） |
| 02 契约 | manifest 缺 `id`/`slots` → 整条 `continue` 丢掉，插件前端**根本不被 import**，无日志无提示 |
| 03 功能 | 入口名实不符、死代码 10 个、不可达分支 6 处——**都不报错** |
| 04 交互 | 8 处接口失败被伪装成"没有数据"；收藏**报假成功** |
| 05 质量 | 测试里 **7 个 ✅ 根本不是断言**、6 处"跳过也算通过" |
| 06 数据 | 点开头文件名**上传成功、永久不可见** |
| 07 交付 | 全站唯一兜底 catch **静默吞异常**（`web-server.ts:300-302`，`e` 未使用、无日志） |

**⇒ 如果只让主子记一件事：这个项目不缺功能，缺的是"出错时会喊"的机制。**

### 🎯 第 8 条的精确根因（三路交叉后由 03 一路定案，婢子已核代码）

**不是"顺序碰巧"，是两处真实缺陷叠加：**

1. `privhub-admin/client/manifest.json` 与 `privhub-admin-console/client/manifest.json` **都声明 `view:"admin"`**；
2. `shell/client/index.js:80-83` 的 `bottomItems` 用 `.find()` **取第一条** → 命中 `privhub-admin`（枚举序 0 < 4）；
3. **口子在过滤不对称**：`:75-78` 的 `topItems` **有** `bi.slot !== 'admin-nav'` 过滤，**`:80-83` 的 `bottomItems` 没有** → 一条 `slot:"admin-nav"` 的条目才会溜进图标栏；
4. `index.html:1049` 在 `activeView==='admin'` 时渲染的是 `slotComps['admin-console']` → **点开的是控制台**。

**后果**：控制台自己的 🛠️ 声明**永不出现在图标栏上**；它唯一实际作用是给 `routes.js viewSet()` 当"视图已装载"的凭据。
**⚠️ 修的时候注意（此处已更正一次，请以此为准）**：改 `bottomItems` 取项**即可**。

关于"要不要顺手删掉 `privhub-admin` 那条 `admin-nav` 声明"，**本条原写的理由（"那是控制台判定『用户管理』页可用性的凭据，删了会变『待接入』"）经复核不成立**——由 `08-连线契约.md` 提出异议，婢子已回源码核对：
- `admin-console/client/routes.js:71-76` 的 `viewSet()` 是遍历**全部** `barItems` 取 `bi.view || bi.slot`；而 `privhub-admin-console` **自己的** barItem（`manifest.json`）同样带 `view:"admin"` ⇒ **即使删掉 `privhub-admin` 的声明，`viewSet` 里依然有 `admin`，不会变"待接入"**。
- 但**仍建议保留**，理由要改：`routes.js:35` 的 `entryOf` 用于**反查插件标题/图标**（`:40` 的"用户管理"条目 `entryOf:'admin'`）。删掉后该条目会反查成 `管理控制台` 的 🛠️ 标题与图标，**是标签/图标错源，不是可用性失效**。

> **教训留痕**：本条是婢子从第三方结论转述时**未回源码**造成的，属"核摘要未核文件"的同一类错——已是本项目第四次。

## 八、诚实的边界（七路的共同盲区）

1. **没有一条测试开过浏览器**，没有截图、没有真人操作 ⇒ 所有"用户会撞上"都是**推演**。
2. 多份报告明确写下：**排序按"代码证据强度"，不是按"用户痛感"**。要把排序换成痛感，缺两样东西：
   - **主子自己操作 5 分钟的一段录像**；
   - **一次服务端错误日志抽样**（这一项直接决定 04 的第 2 条 P0 是 P0 还是 P3）。
3. 若干关键前提需运行时确认：Cordis 4.0.1 在 `inject` 依赖**永不满足**时是"静默挂起"还是"报错"（01 的 P0-1 关键前提，**未验证**）。
