## 1. 动机

内容区所有权迁移（第二步 a–d）已经把「谁的地盘」定清楚了：宿主拿 `.v3-viewer-host` / `.v3-editor-host` 两个锚点、
插件递名片（注册表）、渲染根由宿主交引用。但迁移留下的**收尾空档**正好是三类「**连错了不吭声**」：

| 空档 | 为什么危险 |
|---|---|
| 内嵌编辑器用 `$el.querySelector` 找自己的节点 | 查不到就 `null`，于是 focus 与滚动同步**静默失效** —— 不报错、不提示，用户只觉得「有时候不好使」 |
| `menuCloseAll` 那条兜底链 | 它**不发** `md:interrupt`；`checkOrder()` 为不误伤它而**故意不查**「有没有发过保存」⇒ **这条路没有任何断言守着** |
| 「该发保存意图而没发」 | 与「有意例外」混在一起，谁都不敢报，于是两类都查不出来 |
| 总线事件事实散在三处 | 想查「`md:interrupt` 到底谁发谁收」得翻三个文件；新加一条线没人登记也没人拦 |

## 5. ③ 409 冲突 + 取消的语义：两个口味（**只出方案，未改一行代码**）

### 5.1 现状（**改前**，行号为改动前）

`plugins/privhub-files-edit-md/client/index.js:508-514`：

```js
const r = await api('/privhub/api/doc', { method:'PUT', body: JSON.stringify({ ..., baseMtime: s.baseMtime }) })
if (r.conflict && !force) {
  if (confirm('该文档已被他人修改（' + this.fmtTime(r.mtime) + '）。\n覆盖保存将丢失他人的修改，是否继续？')) return this.save(true, s)
  if (mine()) this.status = '已取消（保留他人修改，请重新打开查看）'
  else this.reportSilentFailure(s, '该文档已被他人修改，为避免覆盖他人修改，本次未写入')
  return false
}
```

两条路走的是**同一段代码**，但可见行为完全不同：

| 路径 | 谁触发 | 取消后发生什么 |
|---|---|---|
| **显式保存** | 用户点「💾 保存」/ `Ctrl+S` | `dirty` 与 `this.doc` 都**没动**，正文留在编辑器里（**不丢字**），状态行给一句中文说明 |
| **静默保存** | 切标签 / 切目录 / 关标签（`tabs.js` 先发 `md:interrupt`） | 弹**阻塞式 `confirm`**；取消后只 toast 一句（`reportSilentFailure`），**编辑器随退场消失** ⇒ 用户手里那一版正文没了（磁盘上保住的是**别人**的版本） |

### 5.2 口味 A：静默路径**不弹**阻塞框（推荐）

**改哪几行**（`edit-md/client/index.js`，`save()` 内 `r.conflict` 那一支）：

- 加一个「这一发是不是静默路径」的判据：`save(force, snap)` 里已经有 `snap`，而 `snap.reason` 已经带着来源（`'interrupt'` / `'host-gone'` / `'superseded'` / `'unmount'` / `'manual'`）——
  **不需要新加参数**：`const silent = !!(snap && snap.reason && snap.reason !== 'manual')`。
- `if (r.conflict && !force && !silent) { …confirm… }`；静默路径**直接走**下面的「不写入 + 说出来」分支。约 **2 行**改动。

**可见行为怎么变**：
- 静默路径**不再有任何阻塞交互**（这条本身与既有约定一致：`edit-md` 的注释里写着「唯一带 `confirm` 的退场入口是 ✕ 只读」—— 现在静默路径也会弹，等于**破坏了这条自陈的约定**）；
- 失败提示仍是那句 toast：`⚠ 未保存：xxx.md —— 该文档已被他人修改，为避免覆盖他人修改，本次未写入（请重新打开该文件后再保存）`。

**风险与可逆性**：改动面只有一支分支 + 一个局部布尔；可逆性高（把 `&& !silent` 去掉即回到现状）。
**真正的风险**是**行为变化本身**：用户不再被"当场拦住"，冲突发生时**不会再有机会选择覆盖**（要覆盖得重新打开、再手动保存 —— 那时 `baseMtime` 是新的，会走成一次普通保存）。

**回归影响面**：`tests/personal-ui.mjs` 段 K 里 `confirm: () => { events.push('confirm'); return false }` 这根桩**会记录 confirm 被调用**——
本批的断言没有一条依赖「静默路径会弹框」，所以**不会变红**；但要**新增**一条断言钉住「静默路径 0 次 confirm」（否则这条口径没人守）。

### 5.3 口味 B：静默路径**仍然提示**，但把正文留住 / 给「复制正文」

**改哪几行**：
- 在 `leaveInline(reason)`（`:438-451`）里，保存**失败或取消**时**不要**立刻 `this.open = false` —— 但这一条与「丢内容不可接受」的准绳直接冲突：
  编辑器留着、内容区已经换成别的文件了（`leaveInline` 的注释写着「这一帧里内容区已经换成别的文件 —— 等于把 A 的编辑器贴到 B 的画面上」）。
  ⇒ 要留住正文，**不能**靠留编辑器，只能**把正文搬到别处**：
- 更小的做法（**推荐**）：加一个「**未写回的正文暂存**」`this._pendingDoc = { project, path, doc, reason, at }`（3–5 行），
  并在宿主的 toast 上加一个动作入口（或让编辑器下一次打开同一文件时**先问一句**「上次有一版没写进去，要用它覆盖当前内容吗？」）。
  这条路**不改退场时序**（该拆的还是拆），只是把「丢字」变成「可找回」。
- 「复制正文」按钮是同一件事的**手动版**：toast 里塞不进按钮，得在宿主侧加一个极小的浮条 —— 那是**新增界面入口**，按纪律应留给专项。

**可见行为怎么变**：冲突时用户仍被提醒（toast 或下一次打开时的提问），且**那一版正文可找回**。
**风险与可逆性**：`_pendingDoc` 是纯内存、随组件生命周期消失（登出/刷新即失）；要做持久化就得写 `sessionStorage`（**那是新的存储口径，不在本批地界**）。
**回归影响面**：`leaveInline` 的时序断言（段 K2-2 / K2-8 的「捕获早于退场」）**不会变**——因为不动顺序；但「暂存 → 下次提问」这条新路需要**新断言**，否则又是"连错了不吭声"。

### 5.4 两个口味怎么选（**决策留主子**）

| 判据 | 口味 A（不弹框） | 口味 B（留住正文/可找回） |
|---|---|---|
| 改动量 | **~2 行 + 1 条新断言** | ~5 行 + 1 个提示入口（或「下次打开时提问」）+ 2–3 条新断言 |
| 是否破坏既有约定 | 恢复约定（静默路径无阻塞交互） | 不破坏 |
| 用户会不会丢字 | **会**（但会被明确告知"没写进去"） | **不会**（可找回） |
| 是否新增界面入口 | 否 | 手动版「复制正文」需要（按纪律应留专项） |
| 最大风险 | 用户再没有"当场选择覆盖"的机会 | `_pendingDoc` 的持久化口径（不持久化则刷新即失） |

> 我的倾向（**只是倾向，请主子拍板**）：**先做口味 A**（它把"静默路径弹阻塞框"这个被自陈约定排除的行为收回去，改动最小、可逆），
> 把口味 B 的 `_pendingDoc` 作为**独立小批**做——因为「下次打开时提问」这条交互本身需要产品确认，且要配新断言。
> **本批一行代码没动**（③ 属产品决定，越权改了就返工）。
