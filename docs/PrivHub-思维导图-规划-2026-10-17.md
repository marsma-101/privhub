## 0. 先说参照物（避免照着不存在的东西做）

主人记得的是「Notion 或 OneNote 里有思维导图」。实际查证（据现有知识，本机无外网）：

- **Notion 没有原生思维导图**。用户在 Notion 里做导图靠两条路：① 内嵌第三方（Miro / Whimsical 的 embed）；② 写 **Mermaid 代码块**，用其中的 `mindmap` 图型渲染。Notion 只负责渲染 Mermaid。
- **OneNote 也没有原生思维导图**。它是自由画布 + 手写墨迹，配合第三方加载项才有导图；不是我们要对齐的东西。
- 真正把「Markdown 大纲 ⇄ 思维导图」做成一等公民的是 **markmap**（VSCode / Obsidian 的 Markmap 插件、Docusaurus 都用它）与 **Obsidian Canvas**（自由画布，JSON 存储）。
- Mermaid 的 `mindmap` 语法是**纯缩进**的：

  ```text
  mindmap
    root((中心))
      分支 A
        子节点
      分支 B
  ```

**结论**：不照抄某个 App 的具体交互，而是采纳这两条已被验证的通用做法——
**① 源数据是纯文本大纲（markmap 派）；② 渲染是导图视图（Mermaid 派）**。
对 PrivHub 而言，① 尤其关键：纯文本 = 智能体天然能读写。

## 1. 核心设计：一张导图 = 一个纯文本文件

这是整个方案的地基，先定死，其余都随之而来。

- **每张思维导图就是一个文件**，扩展名 **`.mindmap`**，内容是 **Markdown 风格缩进大纲**：

  ```text
  # 我现在有哪些项目

  - 私域枢纽
    - 文件中枢
      - 目录树 / 预览 / 上传
    - 协作
      - 任务看板
      - 项目看板
    - 知识
      - 知识图谱
  - 马泉斌
    - 个人空间
  ```

- 解析规则（纯函数，无 DOM）：按行缩进定层级（2 空格或 1 个 Tab 算一级），行首 `- `、`* ` 可有可无；首个 `# ` 行是标题；空行忽略。
- **为什么必须是纯文本而不是 JSON 画布（Obsidian Canvas 那种）**：
  1. **智能体可写**——大模型写缩进列表是本能，不需要理解节点坐标系；现有智能体文件写通道即插即用。
  2. **白拿全部既有能力**——版本历史、评论、标签、全库搜索、引用检查、双链、导出、水印、ACL：它就是一个普通文件，一行代码都不用写。
  3. **插件关掉也不丢**——没有本插件时它仍是一份可读的文本文件，不会变成打不开的黑盒。
- 备选（**不推荐**，列出来是为了评审时有对比）：用 `.md` + front-matter `type: mindmap`；或把导图塞进 Mermaid `mindmap` 代码块（要引 Mermaid，见 §3）。

## 2. 两层结构与权限

| | 全局层（项目总览） | 项目层 |
|---|---|---|
| **入口** | **最左竖栏的独立一级按钮**（与「工作台 / 智能体接入」同列，插在两者中间），**仅管理员可见** | 图标栏「知识」组「思维导图」；文件树点开 `.mindmap` 即渲染；「新建文件」→「创建思维导图」 |
| **内容** | 「我现在有哪些项目」的总览图 | 该项目下的若干张导图 |
| **权限** | **仅管理员**（普通用户看不到全部项目，因而不给全局图） | 跟随项目 `canAccess`：能看该项目的用户即可看 / 编辑 |
| **存储** | 系统级：`data/mindmaps/global.json`（经 `ctx.storage` 加密） | 项目内普通文件，**不经过任何新存储** |
| **多张** | 管理员可建多张全局图（如「项目地图」「团队分工图」） | 项目内可建任意多张，每张一个文件 |

> **图标定稿**：用 **🌳**（不用 🧠 —— 🧠 已被选完项目后的「知识」大类占用，`SECTION_DEFS` 里 `knowledge` 组的图标就是它，撞了）。

## 3. 渲染方案：自己画的 SVG，不引外部库

- 仓库**无构建步骤**、**无 CDN**、CSP 保留 `unsafe-eval` 只为 Vue 运行期模板编译——所以**不要**引 markmap / d3（几十万行、还得预打包成单文件塞进仓库）。
- 项目已有先例：`privhub-files-kg` 的知识图谱就是**手写 SVG**（自研力导向 + 防重叠）。思维导图更简单，照此办理。
- 计划：约 200~300 行写一个 **tidy-tree（整齐树）横版布局** + 折叠 + 缩放平移 + 适应窗口；
  - 布局：递归按「子树高度求和」给每个节点分配 y，深度给 x（Reingold–Tilford 对它属于杀鸡用牛刀）。
  - 交互：滚轮缩放、拖拽平移、双击折叠、`Tab` 加子节点、`Enter` 加兄弟节点、`Del` 删除、`F2` 改名（对齐 XMind / markmap 的肌肉记忆）。
  - 配色走主题 token（`--text / --line / --muted / 各分类色`），明暗两套自适。

## 4. 界面与版式：直接沿用刚定稿的看板版式

不用新花样，套用主人 2026-10 定稿的那一版（任务看板那套）：

```
view-page
 └─ wrap        flex:1 1 auto; min-height:0; display:flex; flex-direction:column; 全宽留白 sp-4/sp-5
     ├─ bar     固定工具条：视图切换(画布/大纲/并排) · 折叠层级 · 适应窗口 · 导出 · 保存状态

     │    ├─ 画布：<svg> 导图
     │    └─ 大纲：可编辑的缩进文本（与画布双向同步）
     └─ foot    固定页脚：一行说明（如「圆点为节点，双击折叠；Tab 加子节点」）
```

- 双视图：**并排**（默认，左画布右大纲，改哪边另一边实时跟着变）/ **仅画布** / **仅大纲**。
- 展示权重遵循既定规则：画布是主区（要人看、要人操作）；大纲、导出、说明性文字降到工具条 / 页脚。
- 目录视图（多张导图列表）也用同一套 wrap + body + ph-scroll。

## 5. 插件落地（具体文件与接线点）

新增 `plugins/privhub-mindmap/`：

**实际落地（P1 · 2026-10-17）** —— ⚠️ 与初稿不同：**P1 时做成纯客户端插件**（`client/` + `manifest.json`，**没有 `src/`、没有 `package.json`**，对齐 `privhub-shell-home` 的先例）。
原因：P1 的项目内导图**不需要任何服务端路由** —— 预览链路本就把非敏感文件按文本读，`/api/text/save` 本就能写任意路径，
智能体的 `/read` + `/write` 本就与扩展名无关。**服务端一行未改**，因此没有理由去挂一个空的 `src/index.ts`。

**P3 落地时补上了 `src/`**（`src/core.ts` + `src/index.ts`）：全局图不是文件 —— 没有归属项目、不进任何文件树，
不能借道「预览 + 文本保存」那两条链，于是它自己有了存储（`data/mindmaps/global.json`，走 `ctx.storage` 密文落盘）
与自己的路由。**项目内导图那条路径仍然一行服务端代码都不需要**，这一点没有变。

| 文件 | 职责（P3 现状） |
|---|---|
| `client/manifest.json` | `{ id, title:'思维导图', icon:'🌳', slots:['office-editor','mindmap','mindmap-global'], barItems:[知识组一条(view=mindmap) + global 组一条(view=mindmap-global)] }` |
| `client/outline.js` | 纯逻辑：大纲 ⇄ 树 的解析 / 序列化 / 树操作（**可被 Node 直接 import 做单测**，不碰 DOM —— 对齐 `explorer-v3/collide.js` 的做法） |

1. **文件查看器**：`window.PrivHub.viewers.register({ id, exts:['mindmap'], priority, mount, update, cleanup })`
   —— 注册表早已就绪（`plugins/privhub-files-explorer-v3/client/viewers.js`）。无声明时宿主走老的 md/text/image/pdf 分支，一字未改。

## 6. 智能体怎么用

- **项目内导图**：走既有智能体文件写通道（`/privhub/api/agent/v1/write`），智能体直接产出一份缩进大纲即可；格式写进《AgentAPI 接入指南》，并给一段示例。
  **（P1 已实测跑通，2026-10-17）**：测试里真签一把 Agent 密钥，智能体把 `.mindmap` 写进沙箱 →
  `/agent/v1/read` 按文本读回**逐字节一致** → 用**人这一侧的解析器**解出同一棵树。这条断言就是「同一份文件人与智能体共用」的地基证明。
- **全局总览图**：P4 再定，倾向给管家车道加 `/privhub/api/agent/v1/butler/mindmap`（仅本机回环、管理员等价），或先只给管理员手工维护。
- 服务端不做「导图语义校验」，只当普通文件读写——真正的格式容错在客户端解析器里（坏行降级为该行文本，不整张报废）。

### P3 验收实况（2026-10-17）

- **入口**：`manifest.json` 加了一条 `barItems`（`group:global` · `view:mindmap-global` · `capFeature:mindmap.global` · 🌳 图标 + 悬停说明与 `doc:02-知识组织.md`）。
  竖栏落点由 `privhub-shell/client/index.js` 的 `GLOBAL_ORDER = ['home','mindmap-global','agent']` 决定 ——
  🌳 插在「📊 工作台」与「🔌 智能体接入」之间（主人 2026-10-17 指定）。骨架两处小改：
  `openBarItem` 白名单加 `view === 'mindmap-global'`、渲染链加 `slotComps['mindmap-global']`。
- **权限为什么用开关而不是 `adminOnly`**：功能表登记 `mindmap.global`，`userDefault:'none'`，而**管理员在开关表里恒为 `write`**
  （`svc-cap/core.levelFor`）—— 默认效果就是「仅管理员可见 / 可改」，正是主人「单独的一个级别」的口径；
  路由侧同样问 `ctx.cap.can(u,'mindmap.global',need)`，所以**入口与接口同一个闸门**，
  将来要给某个人代管，把开关调成 read/write 即可，不会出现「入口放开了、接口还 403」。
- **服务端**：新增 `src/core.ts`（存储）与 `src/index.ts`（路由）。落盘 `data/mindmaps/global.json`，**走 `ctx.storage` 密文**（PHENC1）。
  路由四条：`GET 全表 + canEdit/limits`、`GET ?id= 单张`、`GET /schema`（条目契约，登录即可读）、`POST { id?,title?,text? }`（不填 id 建、填 id 局部改）、`DELETE ?id=`。
  **局部更新语义**：只提交 `title` 的请求不会把正文清空（反之亦然）。
- **不做第二份画布**：给 P1 的 `editor.js` 加了三个可选 prop（`loader` / `saver` / `note`），全局图注入自己的读写函数即可
  —— 画布、大纲双向同步、折叠、导出 SVG **一行都没重写**。`editor.js` 在 prop 缺席时行为与 P1/P2 完全一致（默认 null）。
- **「自动带出全部项目为根节点」**：建图时用 `/api/projects`（管理员拿到的是全部项目）把项目名写成一级分支；
  之后新开项目用列表行的「⤓ 补齐项目」—— **只增不改**：把还没出现的项目名追加成根节点，已手写的内容原样不动。
- **不在 ACL 的 `GUARD_PATHS` 里**（有意）：那条链管的是「项目内文件」的目录级 ACL，而全局图没有项目 / 没有路径，
  放进去会因取不到 `project/path` 而误判。它的闸门就是上面那道功能开关。
- **测试**：`tests/mindmap.mjs` 由 155 → **233 断言全绿**（新增 ⑥ 全局图组：接线 + 最小桥驱动 `global.js` **真身**
  跑 列出 / 过滤 / 403 态 / 打开 / 注入式 loader·saver / 新建（带出全部项目）/ 补齐（只增不改，含「全都在图里就什么都别写」）/ 改名 / 删除；
  再由**真 `editor.js`** 拿注入的 loader/saver 跑一遍读写，证明复用而非重写。真接口那一半扩进 ④ 端到端：
  管理员增删改查 + 落盘位置与密文头 + 普通用户三个动词全 403 + 匿名 401 + `cap/me` 管理员 `write` / 普通用户 `none`）。
- **顺手修掉一个真 bug**：`global.js` 的「补齐项目」把 `insertChild` 的返回值当树用，
  而它其实是 `{ root, path }`（还要把新节点路径带回去选中）—— 结果序列化出一堆垃圾。
  测试里那条「补齐后是 私域枢纽,马泉斌」的断言当场变红，改为 `.root` 后转绿。
- **回归**：`frontend-templates` 31/0；`integrity` 220/1（仍是那条与本功能无关的既有红）；`run-all --spawn` 除既有的
