# PrivHub 宿主机智能体管家（MCP）设计方案 —— 2026-10-13

> 对应待办 #21「宿主机智能体全权车道」。本文件是**设计方案**，待批准后施工。
> 批准前的状态：**未动一行实现代码**。

---

## 0. 给非技术读者的一页话

**要做的事**：让装在宿主机上的 AI 软件（Claude Code、Trae、VSCode、opencode、Cherry Studio……不管是哪个），
能像管理员一样替你**管理 PrivHub**——整理文件、加用户、建项目、改开关、配模型、看日志、跑备份。

**怎么做到"通用"**：MCP 是一种国际标准。我们做一个**小小的转接器**（一段程序），
它一边对 AI 软件说"我能干这些活"，一边转过头去指挥 PrivHub。
支持 MCP 的软件用这个转接器；不支持 MCP 的软件，走老办法（我们给它一份"能力清单"，它照着接）。

**已经和你定好的六条**（本设计的全部前提）：

| # | 你定的 | 落到设计里 |
|---|---|---|
| 1 | 管家**两样都要**：既整理内容，也管系统 | 工具集分四类，四类全做 |
| 2 | 危险动作**直接做、不确认** | 管理员等价；但每个"没得回头"的动作在审计里留一份"动手前的样子" |
| 3 | 向量库**全做 + 开关** | 默认"没模型也能用、界面不吓人"；有条件再一键开语义检索 |
| 4 | 接法**要通用** | 两条腿：MCP（标准）+ `/schema`（万能兜底） |
| 5 | **四类活全要** | 内容整理 / 内部管理 / 模型检索 / 服务运维 |
| 6 | 钥匙**只限本机** | 绑定 IP 白名单，只认宿主机自己 |

**一句实话**：这不是小工程。它比我们前几批任何一单都大，因为它要**新开一条通道**，
把今天"只有网页能做"的一批管理动作，变成"智能体也能做"。所以设计分了**四批**，
一批一批交付、一批一批验收，不会一次性砸给你。

## 1. 现状盘点（决定了成本，必须先说清楚）

### 1.1 今天的"智能体通道"长什么样

- 唯一入口：`/privhub/api/agent/v1/*`（`plugins/privhub-files-agent/src/index.ts`），
  认证头 `X-Agent-Key: pha_…`（`index.ts:220`），**明文只存哈希**（`index.ts:1032`）。
- 密钥三档范围 `project | directory | all`（`index.ts:287-296`）、**IP 白名单**（`index.ts:237-240`）、
  **每月自动过期**（`index.ts:227-232`）。
- **刻意的边界**（`index.ts:443-449`）：`projectReadOnly: true` —— 项目只读，写只进"个人空间沙箱"，
  且明文写着 **"channel: 仅 X-Agent-Key 通道；禁止使用网页会话"**。
- **够不到任何管理功能**：今天 22 条 agent 路由里，**没有一条**能加用户、建项目、改开关、配模型、看审计。

### 1.2 今天的管理功能长什么样

全部是 **"网页会话 + 功能开关（`ctx.cap`）"** 双门，逐条如下（`file:line` 为登记处）：

| 项目 | `POST /project-create`、`/project-delete` | 同上 `:30,42` | `admin.project.create` / `admin.project.delete` write |

### 1.3 三个已核实的事实（直接影响方案）

1. **日志已经落文件**：`<PRIVHUB_ROOT>/data/logs/privhub-YYYY-MM-DD.log`，按天分文件、留 14 天
   （`src/main.ts:115-142`）。所以"看日志"不用新造轮子，读文件即可。
2. **备份已经能用**：`privhub-git-backup` 每分钟自动 `git commit` 一份镜像到 `data/git-backup/mirror/`
   （`privhub-git-backup/src/index.ts:31-34,178-181`）。但**依赖宿主机装了 `git`**，没有则自动备份停摆并如实上报。
3. **"重启服务"没有接口，也不该硬做**：全仓**没有任何**能 `restart/stop` 的路由；
   `start.bat` 是"前台跑、退出后 `pause`"，**没有看门狗**（`privhub/start.bat`）。

## 2. 总体形态：一个转接器 + 一条车道 + 两条腿

```
 ┌──────────────────────────┐
 │  宿主机上的 AI 软件        │   Claude Code / Trae / VSCode / opencode / Cherry Studio …
 │  （任意支持 MCP 的客户端）  │
 └───────────┬──────────────┘
             │ MCP（标准话术，本地小程序）
 ┌───────────▼──────────────┐
 │  privhub-mcp（转接器）     │   零第三方依赖，node 直接跑；读一份本机配置（地址+管家钥匙）
 └───────────┬──────────────┘
             │ HTTP + X-Agent-Key
 ┌───────────▼──────────────┐
 │  PrivHub 服务（:3181）     │
 │  └ 管家车道 /agent/v1/butler/* （新）  ← 管理员等价、限本机、分项开关、审计快照
 └──────────────────────────┘

 第二条腿：不支持 MCP 的软件 → 读 GET /agent/v1/schema 的 tools 清单，自己接（把管家工具也加进这份清单）
```

**为什么转接器要"零依赖"**：项目定下"零外部依赖、低配宿主机、不开外网"。用官方 MCP SDK 会引入
一堆要维护的东西；而 MCP 的本地（stdio）部分是**很小、很稳定的协议**（`initialize` / `tools/list` /
`tools/call` / `ping` 四条消息），自己实现两百来行、可测可控，符合项目脾气。

## 3. 权限与安全模型（把你定的六条落成机制）

### 3.1 一把专用钥匙

| 字段 | 值 | 理由 |
|---|---|---|
| 类型 | `admin` | 管理员等价（你的决定） |
| 范围 `scope` | `all` | 全部项目（内容整理要动项目文件） |
| **IP 白名单** | `127.0.0.1/32`（+ `::1`） | **你的决定"只限本机"**；用现成功能，零新开发 |
| 名字 | 如 `宿主机管家` | 审计里一眼可辨 |

另有一个**专门的"管家身份"**（服务账号）：所有由它执行的动作，审计里记成 `ai:宿主机管家`，
和"管理员本人操作"分得开——这样你能随时回答"这是人干的还是 AI 干的"。

### 3.2 两个开关（都挂进已有的"功能权限开关"表，不另起炉灶）

- **总开关** `agent.butler`：关掉 ⇒ 整条管家车道 403，钥匙再多权限也够不着。这就是你要的"简单切换的开关"。
- **分项开关**：`agent.butler.files` / `.users` / `.projects` / `.switches` / `.keys` / `.audit` /
  `.model` / `.service`——可以只关"删用户"这一项，别的照常。
- 用户侧一律 `none`（普通用户看不到、用不了）；管理员恒 `write`——**与你定的全局规则一致**。

### 3.3 危险动作的"落地保险"（不增加任何确认环节）

你选了"直接做、不确认"，所以不设二次确认。但每个**不可逆**动作在审计里**留一份"动手前的样子"**：

| 动作 | 快照内容 |
|---|---|
| 删项目 | 该项目文件清单（名 + 大小 + 摘要） |
| 删用户 | 该用户的账号记录（项目授权、角色、个人空间名） |
| 重置密码 / 吊销密钥 | 账号名 / 密钥 id 与配置 |
| 彻底删除 / 清空回收站 | 被删条目清单 |

出事后，人照着快照能人工还原（文件真身另有回收站与 git 备份兜底）。

## 5. 关键取舍：管家怎么"认得"管理员的身份？

这是本方案唯一的大分叉，两条路：

| | **路 A：给智能体开新通道（推荐）** | 路 B：管家以"管理员本人"登录 |
|---|---|---|
| 做法 | 密钥认证 → 服务端把它的身份**当成**那个管理员，但**单独走一层管家路由** | 转接器存一个管理员令牌，直接调今天所有路由 |
| 新代码 | **多**（要新写一批 `butler/*` 路由） | **几乎为零** |
| 能否单独吊销管家 | **能**（这是密钥，一键吊销） | 不能——它就是你本人 |
| 审计能否一眼看出是 AI | **能**（记成 `ai:宿主机管家`） | 不能（记成管理员本人） |
| 月度过期 / IP 绑定 | **有**（现成） | 要另造 |
| 是否违背既有设计 | 不违背（延续"仅 X-Agent-Key 通道"） | **违背**（今天明文禁止智能体用网页会话） |

**推荐路 A**：多写一些代码，换来"管家是一把**可以随时收回、可以一眼区分**的钥匙"。
对一个"可能交给别人维护"的系统，这点余量值那个工。路 B 留着作为"如果时间紧"的退路。

## 6. 服务运维：为什么"重启"不做成接口

服务**自己把自己关了，没人叫它回来**——`start.bat` 是前台运行、退出后 `pause`，**没有看门狗**。

所以分两层：

- **能做成接口的**（本批做）：`health`（状态）、`logs_tail`（日志）、`backup_run`（备份）——都是"读文件 / 触发已有动作"，不涉及进程生死。
- **只能靠系统命令的**（做成"说明"）：重启 / 停服。方案：给宿主机智能体一份
  **《运维命令速查》**（`taskkill` 结束旧进程 → 重跑 `start.bat 3181` → 用 `health` 确认回来了），
  写成它照着做就行的几步。**可选增强**：加一个"看门狗"脚本（节点被关掉自动拉起），
  有了它，重启就能安全地做成接口。**这一项等你点头再做**，因为它改的是"服务怎么被托起"这件事。

## 7. 通用安装体验（"不懂的人也能接上"）

不试图自动改每个软件的配置（那既做不到、也危险）。改为**给一段放之四海皆准的东西**：

1. **一份 JSON 配置块**：任何用配置文件接 MCP 的软件（Claude Desktop、VSCode、Cherry Studio…）
   把同一段粘进它自己的配置里即可。
2. **一行命令**：支持命令行的软件（Claude Code）一条命令接上。
3. **一句话兜底**：不支持 MCP 的软件，给它 `/schema` 网址，让它自己读工具清单。
4. **PrivHub 里一个"一键生成"按钮**：在「🔌 智能体接入」页新增「宿主机管家」卡片，
   点一下**自动签发那把本机钥匙**、并**生成上面三种接法**（直接复制即用），
   还带一个"自检"（点一下，看看接没接上、能不能读到服务状态）。

> 这一步是整个"通用 + 省心"的成败所在：目标是把"接上管家"从"改 JSON 文件"降成"复制一段、粘贴"。

## 8. 测试与验收（沿用仓库既有规矩）

- **MCP 协议契约**（进程内）：喂 `initialize` / `tools/list` / `tools/call` 给转接器，断言应答形状；
  `tools/list` 的名字必须与 `/schema` 的能力**一一对齐**（防止两条腿漂移）。
- **HTTP 端到端**（隔离实例 3190，**绝不打 3180/3181**）：管家钥匙能读能写能管；
  **IP 白名单**：非本机来源 403；**总开关关掉** ⇒ 全 403；**分项开关**逐个生效；
  **不可逆动作**确实留下审计快照。
- **静态契约**（`integrity.mjs`，只增不改）：管家功能已登记进 `cap` 表、`/schema` 含管家工具、
  MCP 工具名与 schema 一致、管家钥匙模板**强制本机白名单**。
- **验收条**（对齐你最初的诉求）：*"在宿主机上，用一句自然语言让智能体整理一个项目的文件 / 加一个用户 / 看一眼服务状态，都能成。"*

## 9. 分批交付（四批，逐批交付验收）

| 批次 | 内容 | 你能验收的事 |
|---|---|---|
| **① 地基** | 管家钥匙（本机绑定）+ 管家车道骨架 + 总/分项开关 + **MCP 转接器** + 自检 | 在宿主机上接上管家，能查服务状态 |
| **② 内容 + 内部管理** | 项目文件读写移动删、标签、用户/项目/开关/密钥/审计 | 让 AI 整理一个项目、加一个用户 |
| **③ 模型 / 检索** | 模型配置、语义检索开关、降级可视化、重建索引 | 让 AI 告诉你检索为何降级、并配通（若条件允许） |
| **④ 运维 + 安装体验** | 日志、备份、(可选)看门狗 + 重启、一键生成接线卡、文档 | 让 AI 看日志、跑备份、重启服务 |

## 10. 诚实边界与风险

- **工程量大**：这是"新开一条能力通道"，不是加个开关。四批合计远超前面任何一单。
- **"不确认"是双刃**：你选了管理员等价且不确认；保险只有"审计快照 + 可吊销的钥匙 + 总开关"。
  一次误读可能真删掉东西——快照是"事后能捞"，不是"事前拦住"。
- **另辟的管家身份**意味着多一个账号要维护（它不开个人空间，只作操作者）。
- **重启方案受限于"没有看门狗"**：不加看门狗时，重启只能是"命令说明 + 让 AI 执行"，做不到一键可靠重启。
- **git 备份依赖宿主机装了 `git`**：没装则自动备份停摆（现成行为，本方案不改）。
- **不做物理数据迁移、不碰真实数据**：全部验证在隔离实例（3190）完成。
- **本地小模型（语义检索）**：能否在低配宿主机上跑，需先实测；本方案不承诺它一定落得下。

**①地基的诚实边界**

- **尚无界面**：本轮只能靠 `butler-setup.mjs`（命令行）或直接调 HTTP 签发钥匙；
  应用内的「🔌 智能体接入 → 宿主机管家」卡片（一键签发 + 多客户端接线 + 自检按钮）属**第④批**。
- **管家目前还"只能看不能干"**：车道通了、自检能过，但真正的内容/管理/模型/运维能力在 ②③④ 批接上；
  本轮的 `capabilities` 是**如实预告**（哪些项已开），不代表该能力已实现。
- **回环归一**改了 `authAgent` 的白名单比对：白名单含 `127.0.0.0/8` 的钥匙，现在也接受 IPv6 回环
  `::1`。这是**语义更正**（两者都是本机回环），且只对回环生效，不会放宽任何非回环网段。
- **未在真实宿主机上端到端跑过**：全部验证在隔离实例（3190）+ 假后端（3197）完成；
  "在真实的 AI 客户端里接上"这一步需你在宿主机实机试一次。
