## 0. 调研结论（DSH 插件规范，来自官方文档与仓库）

参考来源：
- 官方架构：[architecture.zh.md](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.zh.md)
- 官方打包/开发：[publish.zh.md](https://github.com/deepseek-ai/DeepSeek-Harness/blob/master/docs/user/develop/basic/publish.zh.md)
- 插件模板：[dsh-plugin-template](https://github.com/kun2-5code/dsh-plugin-template)（六种插件形态、十四个浏览器 UI 界面）
- 插件生态：[awesome-deepseek-harness](https://github.com/awesome-deepseekharness/awesome-deepseek-harness)

关键事实（决定我们怎么落地）：

1. **「一切皆插件」是 DSH 的官方工程哲学**——与用户诉求完全一致。
2. 插件有**多种形态（shapes）**：后台服务、前端 UI 面板（panel）、客户端 slot、slash 命令、工具、技能等。
3. 前端 UI 插件挂在 **浏览器 UI 的特定挂载面（slots/surfaces）** 上——这正是我们「每个区域一个插件」能够成立的技术基础。
4. 插件通过 `dsh.profile.bundles` 配置被 DSH 加载，可热插拔、可装卸。

> 对用户的可理解翻译：DSH 官方本来就把「界面的一块区域」叫做一个挂载点（slot），我们的「顶栏/左树/中间面板/右侧条」天然就是四个挂载点，每个挂载点塞一个插件，正好符合用户「一个区域一个插件」的设想。

## 2. 插件清单（最终版）

### 阶段一（骨架 + 登录 + 预置账号）✅ 当前目标

| 插件名 | 职责 | 形态 | 对应 UI |
|--------|------|------|---------|
| `ds-app-shell` | 主界面外壳：四区布局承载器 + 整体样式 | ui (shell) | 整个框架 |
| `ds-ui-topbar` | 顶栏：系统名 + 面包屑 + 权限标识 + 用户 + 退出 | ui | topbar |
| `ds-auth-login` | 登录页 + 会话判定（管理员/普通）+ 注册申请入口 | ui + server | 登录页 |
| `ds-user-store` | 账号与权限元数据存取（预置 管理员1 / 普通1） | server/(数据) | — |
| `ds-file-tree` | 左侧目录树：左键展开、右键菜单（阶段一仅骨架+示例节点） | ui + server | tree-sidebar |
| `ds-file-panel` | 中间文件面板：文件卡片展示（阶段一仅占位/示例数据） | ui + server | file-panel |
| `ds-inspector` | 右侧功能条（阶段一空壳占位） | ui | inspector |

### 阶段二（文件核心操作）

| 插件名 | 职责 | 形态 |
|--------|------|------|
| `ds-file-upload` | 上传（含拖拽上传，复用 DSH 拖拽能力）、下载 | ui + server |
| `ds-file-ops` | 右键菜单：新建文件夹 / 复制 / 移动 / 重命名 / 删除（进回收站） | ui + server |
| `ds-recycle-bin` | 回收站：恢复 / 彻底删除 | ui + server |
| `ds-permission-scope` | 项目/目录级权限隔离（A项目/B项目可见性） | server + ui |

### 阶段三（后话 / 可选）

| 插件名 | 职责 |
|--------|------|
| `ds-file-preview` | 在线预览（图片/PDF/Office/文本） |
| `ds-permission-matrix` | 细粒度权限（单文件 看/传/下/改/删） |
| `ds-search` | 全文检索 |
| `ds-audit-log` | 审计日志（谁在何时做了什么） |
| `ds-version` | 版本历史 |
| `ds-admin-approve` | 管理员审批注册申请 + 配权限（后台） |

## 3. 权限模型（方案C 落地方案）

- **磁盘**：共享根目录下按项目分文件夹。
  ```
  shared/            ← 宿主机共享根
    ├── A项目/
    ├── B项目/
    └── 公共/
  ```
- **权限表**：`data/permissions.json`，记录「角色 × 范围(项目/目录) × 操作」。
  - 阶段一：只实现「角色」判定（管理员/普通），范围/操作后续加。
- **账号数据**：`data/users.json`，预置：
  ```json
  [
    { "username": "admin",  "role": "admin",  "password": "<hash>" },
    { "username": "user1",  "role": "user",   "password": "<hash>" }
  ]
  ```

## 5. 开发顺序（用户已确认的节奏）

1. **阶段一目标**：DSH 骨架 + 登录 + 预置两账号 → 局域网能登录进主界面 = 成功。
2. 之后**每加一个功能 = 写一个新插件**，逐步垒高。

### 阶段一内部步骤建议
1. `ds-app-shell`（外壳 + 四区布局）
2. `ds-user-store`（账号数据 + 预置账号）
3. `ds-auth-login`（登录页 + 会话 + 角色判定）
4. `ds-ui-topbar`（顶栏，含当前用户/权限标识/退出）
5. `ds-file-tree` + `ds-file-panel` + `ds-inspector`（先出骨架/占位）
6. 装配进 `dsh.profile.bundles`，本地跑通
7. 打包 → 向日葵/网盘传宿主机 → 局域网登录测试
