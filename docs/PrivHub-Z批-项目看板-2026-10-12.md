# PrivHub Z 批 · 项目看板（AI 可控纵向分区页）— 2026-10-12

## 一句话

给每个项目加一块「项目看板」：纵向分区页（section 自上而下、可全宽/半宽两栏），
内含 状态/统计卡 · 计划/里程碑 · 富文本(Markdown) 三种组件；
**看板的控制权交给 AI 智能体** —— 智能体重写布局文档即可调整分区大小/顺序/内容，
人只读（本插件不提供拖拽编辑器）。

## 需求与选型（用户拍板）

原始诉求：给每个项目加看板，写明项目状态、文件数量，做多区域划分，走独立界面风格；
**把看板控制权完全交给 aiagent**，由它按需调整分区大小/位置并写入状态与计划。

用户通过选项确认：

- **版式 = ② 纵向分区页**：分区从上到下堆叠；每个分区 `width=full` 全宽 / `half` 半宽
  （相邻两个 half 自动并排），`collapsed` 可折叠。
- **组件 = 富文本/Markdown 区 · 状态/统计卡 · 计划/里程碑**
  （未选「文件分布图」，故本期不做该组件；`facts.byExt` 已在服务端算好，后续加组件随时可用）。

## 数据契约

一个项目一份文档，落 `data/dashboards/<project>.json`（经 `ctx.storage` 透明加密）。

```
DashboardDoc { project, title, subtitle, sections[], revision, updatedAt, updatedBy, source }
Section      { id, title, width: full|half, collapsed, widgets[] }
Widget       { type: markdown|stats|plan, title, text, items[] }
  stats.items = [{ label, ref?, value?, hint? }]   ref 引用实时 facts
  plan.items  = [{ text, state: done|doing|todo|blocked, note? }]
```

`facts`（服务端实时算，非写死）：`files/dirs/bytes/bytesText/byExt/members/lastUpdated/
recent7d/truncated/scannedAt`。stats 组件按 `ref` 引用 `files/dirs/bytesText/members/
recent7d/lastUpdated`。

`STAT_REFS` 与 `LIMITS`（sections≤30、widgets≤12、statsItems≤12、planItems≤60、
text≤4000、title≤80、label≤40、note≤200）见 `core.ts`。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/privhub/api/dashboard?project=` | 读看板 + 实时 facts + `canEdit` |
| PUT | `/privhub/api/dashboard` | `{project,dashboard}` 覆盖写（需可编辑） |
| POST | `/privhub/api/dashboard/reset` | `{project}` 还原默认看板 |
| GET | `/privhub/api/dashboard/schema` | 组件契约（供智能体发现） |
| GET | `/privhub/api/agent/v1/dashboard?project=` | **智能体**读看板（X-Agent-Key） |
| POST | `/privhub/api/agent/v1/dashboard` | **智能体**重写布局文档（X-Agent-Key） |

鉴权串联同 task-board：`requireUser(401) → isValidProjectName(400) → canAccess(403)
→ 写操作再叠文件级 ACL(edit, 路径=项目根)`。

## 智能体写车道 = 「项目只读」的唯一例外

`privhub-files-agent` 的既有契约是**项目对智能体始终只读**（写一律 `AGENT-4032`）。
本批在 `schema` 的 `boundary` 里显式登记了这一例外：

```
projectWriteExceptions: ['/privhub/api/agent/v1/dashboard —— 仅项目【看板文档】（展示布局），不碰任何项目文件']
```

- 例外只覆盖「看板展示文档」，**不碰任何项目文件**；其余写端点仍一律 403 硬隔离。
- 智能体写看板额外校验：`scopeAllows(key,project)` 命中 → 绑定用户 `canAccess` →
  ACL `edit`（路径=项目根）。任一不满足分别回 `AGENT-4031 / AGENT-4034 / AGENT-4031`。
- 写入 `source='agent'`、`updatedBy='ai:<密钥名>'`，revision 递增，落审计
  `agent-dashboard-write`（detail 带 `via=<用户名>`）。

复用既有 `X-Agent-Key` 机制（**不新建密钥库**），与 `privhub-files-office-ai` 同属
「API Key 车道改项目内容」的既有先例。

## 安全

- **清洗**：任何来源（人 / 智能体）的 JSON 都过 `sanitizeDashboard` —— 丢弃未知组件类型、
  未知 stat ref、非法 plan state（归一 `todo`）、非法 width（归一 `full`）；长度/数量夹紧；
  补 id。形状不对（无 `sections` 数组）→ 400，不静默产出空板盖掉真数据。
- **Markdown 渲染**：`v-html` 的内容一律「先整体转义（`& < > " '`）、再套白名单标签」
  （h3-h5/p/ul/li/blockquote/code/strong/em/a），**禁 HTML 直出**。链接只放行
  `http(s)://` 与站内绝对路径，其余降级为纯文字。
- **存储**：写入包进 `svc.withFileLock`（不做无锁读改写，revision 才数得准）；
  文件经 `ctx.storage` 加密（PHENC1），磁盘不可读明文。
