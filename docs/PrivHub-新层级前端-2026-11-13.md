# PrivHub 新层级前端（L1 总览 / L2 项目层 · 个人层 / L3 管理层）· 2026-11-13

> 主人这一轮的要求：**真的换成新的界面逻辑**，再把现有功能安排进新页面里。
> 上一轮只做「增量下沉」（旧界面 + 低频收进更多），方向被改定为**搬家式重构**。
> 两条硬要求不变：**现有功能一条不删**；不常用的可以放到更深的地方。

---

## 一、新的层级结构

```
L0 入口层   登录 / 会话（骨架，未改）
L1 总览层   工作台 = 整个盘子怎么样（KPI → 管线 → 项目卡片 → 我的入口）
L2 项目层   选中项目后固定 4 个主 tab：看板 · 任务 · 日程 · 文件
            其余项目内功能（知识 5 项 / AI）→「更多」抽屉，一层可达
L2 个人层   我的：任务 / 日程 / 文件 / 偏好
L3 管理层   管理控制台（自带四区路由，非 admin 不可见）
```

每屏顶部有一条 **34px 层级条**，把「你在哪一层」写出来，并给出回上一层的出口：

| 场景 | 层级条 |
|---|---|
| 项目层 | `📊 总览 › 📂 项目名 › 文件 · 搜索` |
| 个人层 | `📊 总览 › 🏠 我的` |
| 管理层 | `📊 总览 › 🛠️ 管理控制台`（暖色带区分——它改的是全系统） |

右侧常驻「我的 / 管理 / 项目列表」三个跨层跳转，管理入口**只在真的装得上时渲染**。

### 旧竖栏保留为可切换形态

层级导航是默认形态；个人层「我的偏好 › 导航形态」可一键切回**紧凑图标竖栏**。
两套读同一份 `barItems` 与同一份归组数据，所以切换不丢功能——用惯竖栏的人不必被迫改习惯。
状态与持久化都在骨架（`nav.compactRail` / `setCompactRail`），不在组件里另存一份。

## 三、单一真源：`ia.js`

新增 `plugins/privhub-shell/client/ia.js` 作为信息架构的**唯一真源**：
四个类别、全局组顺序、系统组顺序、常用位数量、项目层四 tab、更多分组。

竖栏（`index.js`）与新导航（`project-nav.js` / `layer-bar.js`）都从它 import。
**为什么必须同源**：两份名单必然漂移，而漂移的表现是「同一个功能在竖栏里属知识、
在 tab 里属更多」，用户就找不到它了。回归钉住两个消费者都真的 import 了它
（防止「单一真源」变成没人用的死文件）。

## 四、几个关键的设计判定

**主 tab 是位置，不是开关。** 点当前 tab 停在它的落地页，不像旧图标那样 toggle 回文件视图——
主导航点一下把人弹走是最恼人的交互。

**同族视图不掉高亮。** 搜索 / 收藏 / 回收站都属「文件」这一族，在它们里面时「文件」tab 仍亮着。
否则用户会以为自己离开了文件区。层级条则显示 `文件 · 搜索`，路径清楚。

**缺席不装死入口。** 功能被开关关掉或插件未装载时，对应 tab 不渲染；
但若只是落地页缺席而同族还有别的视图（如 files 关了、search 还在），
tab 退到该族第一个可用视图，不整块消失。

**当前视图藏在「更多」里时自动展开**，并在把手上点一个提示点。
否则从别处进了某功能，导航里看不到自己在哪，「我在哪儿」这条线索就断了。

**个人层是派生只读。** 任务与日程的唯一来源仍是各项目的任务看板，
这里只把「指派给我的」横切出来，不另存副本、不做编辑——避免两处编辑打架。
点一行任务进**它所属项目**的任务看板（服务端算出目标，不用「列表第一个」兜底）。

## 五、上一轮审计修掉的问题（本轮一并带上）

主人要求「检查是否通过规则和逻辑解决问题，而不是兜底和写死代码的假测通」。
审计确实查出 6 处真问题，其中一处是**我自己的假测通**：

1. **色盲可分辨性是假测通**：四个管线桶只有 todo/review 有图案，doing/done 纯靠颜色，
   而旧断言只查「文件里出现过 gradient」→ 缺陷代码照样绿。
   已改为逐桶取 `background-image`、要求非空且两两不同、图例与条内一致。
   并用**变异检验**证明：抽掉 doing 的图案后新断言报错、旧断言仍通过。
2. **完成列靠标题猜**：`/完成/` 会把「未完成」「待完成」「not done」判成已完成，
   且与权威 `doneColumnId` 打架 → 同一面板出现两个对不上的「已完成」数字。
   改为**完成与否只认 doneColumnId**。
3. **可见项目 KPI 用截断后的条数**：500 个项目显示成 60 个 → 新增 `totals.visible`（未截断总数），
   其余 KPI 在截断时逐项标注「按前 N 个项目」。
4. **判空用筛选后列表**：搜不到时谎称「你没有可访问的项目，请联系管理员开权限」→ 改用 `totals.visible`。
5. **卡点项目数用筛选后列表**：出现「卡点 50 处 / 0 个项目需要处理」→ 改用服务端 `totals.blockedProjects`。
6. **「我的任务」用 `|| list[0]` 兜底**：数字与跳转目标对不上 → 服务端算出真正有未完成卡片的项目。

另修：`search` 回执此前是半成品字段（服务端回了、界面没用）→ 已接上并说明「命中 N 个、取回 M 个」；
截断告知从冒用 `kind='overdue'` 改为独立 `kind='partial'`（数据完整性告知，不计数、用 ℹ 不用 ⚠）；
原因只列前 3 条时补「还有 N 条」；个人目录读失败 `entries=null` 显示「—」而不是 0。

**`node tests/run-all.mjs --spawn` → exit 0，HTTP 370 / 370，全部静态套件 0 失败。**

| 个人界面 373 / 管理台 83 / 运行时契约 170 … | 全部 0 失败 |

新套件覆盖的是**运行期归属判定**，不是语法：无家可归的功能必须为 0、
同族视图高亮不掉、缺席不装死入口、非管理员看不到管理入口、
点任务进对的项目、偏好开关真的写进骨架、新槽真的挂进渲染链。

### 两处断言跟着搬家走（不是放宽）

归组数据抽到 `ia.js` 后，`integrity` 与 `mindmap` 里读 `index.js` 找数组的断言会**静默退化成空断言**。
已改为读 `ia.js`，并各加一条「消费者真的 import 了它」的断言——
否则「单一真源」可能是个没人用的死文件，而测试照样绿。
