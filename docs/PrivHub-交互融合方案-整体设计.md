# PrivHub 整体交互方案（融合版）— 启动器 · 首页 · 三栏工作区 · 就地操作

> 日期：2026-09-03 · 状态：**方案待确认**（V4 交互重构候选）
> 定位：融合多轮候选方案的各自优势，形成一套**分层、可分期落地、服务端零依赖**的整体交互方案
> 排除项：AI 对话助理（本轮不考虑，`office-ai` 网关保留现状不动）
> 基础文档：`PrivHub-架构与功能说明.md`（V3 基线，本文为其交互演进）

## 一、方案来源与融合原则

| 候选方案 | 可取之处 | 在融合方案中的落点 |
|---|---|---|
| A 桌面工作台 | 三栏布局、Ctrl+K 命令面板、快捷键、长按菜单 | **L3 启动器 + L2 三栏化 + 全局快捷键** |
| B 任务向导 | 首页、引导任务线、空态按钮化、图标分组 | **L1 首页引导 + 全局空态规范** |
| C 知识工作台 | 全局搜索常驻、视图收编、图谱嵌入右栏、左栏快捷区 | **顶栏搜索条 + 内容分页 + L2 右栏** |
| D 启动器优先 | 一个框直达文件/动作/标签，三源联想 | **L3 启动器（核心创新点）** |
| F 收件箱工作流 | 待办流组织、处理动作、收件箱清零 | **L1 首页收件箱（"进来干什么"）** |
| G 就地手术 | 行内重命名、浮动工具条、拖拽移动、lightbox、进度内联 | **L4 就地操作层（全局行为规范）** |

**融合原则（避免堆叠冲突）**：
1. **四层分工**：启动器管"找"、首页管"开始"、工作区管"干"、就地操作管"快"——同一时刻用户只面对一层
2. **视图不冗余**：一个功能只出现在一个地方（搜索收编进启动器，收藏/最近收编进左栏快捷区，标签/模板/图谱/Wiki 收编进内容分页）
3. **上下文不丢**：进入任何功能视图都不丢项目与选中文件（内容分页 + 右栏常驻）
4. **可分期**：四层可独立上线、独立回归、独立回退
5. **服务端零依赖**：全部为前端骨架/插件改动；仅收件箱聚合需要 1 个轻量查询 API（复用审计/meta 数据）

## 二、整体形态（登录后布局）

```
┌──────────────────────────────────────────────────────────────────────┐
│ ● PrivHub │ 🏠 A项目 B项目 +  │ 🔍 搜索文件 / 命令… ⌘K  │ 👑管理员 退出  │
├─┬──────────┬───────────────────────────────────────┬──────────────────┤
│📥│ 收件箱 3  │ [📄文件][📚知识库][🏷标签]  ▍          │ 📄 选中文件        │
│⭐│ 收藏      │ ┌───────────────────────────────┐   │ 名称/类型/大小/时间 │
│🕐│ 最近      │ │ 文件网格/列表（就地操作层）      │   │ 权限: 读写         │
│──│          │ │ · 双击文件名=行内重命名          │   │ 标签: [合同][V3]   │
│📁│ A项目     │ │ · 多选→底部浮动工具条           │   │ 🕸 相关节点        │
│  │ ·合同    │ │ · 拖到左栏树=移动               │   │  ●README◄─●需求   │
│  │ ·规范    │ │ · 双击文件=lightbox 预览        │   │  ●规范            │
│  │ B项目     │ └───────────────────────────────┘   │ 操作: 下载/编辑/…  │
│──│          │ 状态栏: 共12项 · 已选2项             │                    │
│⚙│ 管理组    │                                       │                    │
└─┴──────────┴───────────────────────────────────────┴──────────────────┘
```

- **顶栏**：logo + 项目横排（保留）+ **搜索条（聚焦即启动器）** + 用户区
- **左栏**：上=快捷区（收件箱/收藏/最近）· 分隔线 · 中=目录树（保留拖拽调宽/折叠）· 下=管理组
- **中区**：内容分页（文件/知识库/标签）+ 视图内容 + 状态栏
- **右栏**：文件信息 + 权限 + 标签 + 图谱相关节点（可折叠，复用现有 `rightOpen`）

## 三、四层交互设计

### L1 首页（Home）— 解决"进来干什么"

`activeView: 'home'`，替代现有纯文案欢迎页（`shell` 插件 WelcomeView 升级）：

```
┌────────────────────────────────────────────────┐
│  欢迎回来，张工 👋                    [引导 2/5] │
│  [⬆ 上传] [➕ 新建文档(模板)] [🔍 搜索]         │
│                                                │
│  📥 收件箱 3                                   │
│   📄 周报-王五.docx   王五 · 今天 09:12         │
│      [预览] [归档到 汇报/] [打标签] [删除]      │
│   📄 需求评审.md       草稿 · 昨天 18:30        │
│      [继续编辑] [归档] [删除]                  │
│                                                │
│  🕐 最近打开（横排）                            │
└────────────────────────────────────────────────┘
```

- **收件箱流**：最近上传 + 未完成 todo 的 MD 草稿（解析 `- [ ]`，零新增存储）+ 待归档；每项一排处理动作，处理后自动进下一项（收件箱清零）
- **引导任务线**（首次登录）：4 步「①选项目 ②上传 ③搜索定位 ④编辑/归档」，进度存 localStorage，可跳过，首页常显进度条
- 未登录用户无项目时 → 空态引导"联系管理员开通权限"（现有逻辑）
- 服务端：新增 `GET /api/inbox`（聚合最近上传/草稿/待归档，复用审计与 meta 数据）

### L2 三栏工作区（Files）— 解决"日常干活"

- **中区** = 文件面板 + 内容分页 `[文件][知识库][标签]`：
  - `文件`：现有网格/列表（V3 explorer 不变）
  - `知识库`：当前目录 README.md/index.md 的 Wiki 渲染（复用 `files-wiki` 组件，从全屏视图改为分页内容）
  - `标签`：按标签筛选文件（复用 `files-tags` 组件）
  - 分页切换**不丢**项目/路径/选中态（复用 `nav` 现有状态，只加一个子状态 `contentTab`）
- **右栏**：从"纯预览"改为**信息 + 权限 + 标签 + 图谱相关节点**面板：
  - 信息：名称/类型/大小/修改时间（现有 preview 数据）
  - 权限：显示当前用户有效权限（新增 `/api/acl/effective`，服务端计算，已规划项）
  - 标签：当前文件标签 + 快捷打标（复用 `files-tags` API）
  - 图谱：双链+标签关联节点，点击跳转定位（复用 `files-kg` 数据）
  - 打开文件时中间主区显示详情/编辑器（MD 编辑器已具备；图片/文本预览迁入中区，lightbox 见 L4）
- **左栏快捷区**：收件箱（带角标）/ 收藏 / 最近 三行，替代独立视图入口（favorites 视图保留 API 兼容）

### L3 启动器（Launcher）— 解决"找不到入口"

- 形态：顶栏搜索条，**点击或 Ctrl+K 聚焦展开**为全宽覆盖层（对齐 Spotlight）
- **三源联想**（一次输入同时匹配，按类分组展示）：
  1. **文件**：文件名 + 全文（复用 BM25/CJK bigram 搜索 API）
  2. **动作**：新建（带模板）/ 打开项目 / 切换视图 / 上传 / 设置（动作注册表 = 扩展现有 `barItems` 契约，新增 `actions` 段）
  3. **标签**：匹配标签名 → 跳"标签"分页并筛选
- 回车执行：文件 → 打开；动作 → 执行；结果带 [打开/下载/移动] 快捷操作
- 键盘导航：↑↓ 选择、Enter 执行、Esc 关闭（骨架级组件，`nav` 状态机零侵入）
- 视图直达示例：输「权限」→ 跳管理视图；输「会议纪要」→ 带模板新建

### L4 就地操作层（In-place）— 解决"点太多下"

全局行为规范，逐项落地（均为纯前端）：

| 交互 | 说明 |
|---|---|
| 行内重命名 | 双击文件名 = 就地编辑（F2 同效），回车确认 |
| 多选浮动工具条 | 选中 ≥2 项后底部浮现：下载/移动/删除/打标签 |
| 拖拽移动 | 文件/多选拖到左栏树目标文件夹 = 移动（复用拖拽上传基建） |
| lightbox 预览 | 双击图片/文本/PDF = 居中大图 + 右上动作条（下载/编辑/收藏） |
| 进度内联 | 上传/下载进度显示在文件行内，替代独立抽屉（抽屉保留兜底） |
| 搜索联想 | 启动器输入时联想历史 + 已打开标签 |
| 长按菜单扩展 | 文件/文件夹 10 项菜单 + 空白处菜单（落地 P2-4） |
| 快捷键 | F2 重命名 / Delete 删除 / Ctrl+A 全选 / F5 刷新 / Enter 打开 / Backspace 上级 / Ctrl+K 启动器（落地 P2-5） |

## 四、视图体系重构（activeView 全集）

| 视图 | 状态 | 说明 |
|---|---|---|
| `home` | 新增 | 首页 + 收件箱 + 引导进度 |
| `files` | 保留 | 三栏工作区，新增子状态 `contentTab`（文件/知识库/标签） |
| `trash` | 保留 | 回收站独立视图（角标不变） |
| `favorites` | 保留 | 收藏视图（API 兼容；左栏快捷区直达） |
| `search` | 收编 | 不再独立视图 → 启动器三源结果承担 |
| `settings/admin/acl/audit` | 保留 | 管理类全屏视图（本就该独占） |
| `tags` | 收编 | 内容分页「标签」 |
| `template` | 收编 | 启动器动作「新建文档」+ 首页快捷动作 |
| `kg` | 收编 | 右栏图谱相关节点 + 知识库分页入口 |
| `wiki` | 收编 | 内容分页「知识库」 |

> 收编原则：**浏览类功能进内容分页，管理类功能保持全屏，检索类功能进启动器**。
> 兼容：`setActiveView`/`openBarItem` 契约不变，被收编视图的入口从图标栏移除，视图状态保留（回退零成本）。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 三栏挤压小屏 | 右栏可折叠（复用 `rightOpen`）；左栏拖拽调宽已有 |
| 视图收编回归面大 | 收编 = 换入口不删组件，`activeView` 兼容保留，回退零成本 |
| 启动器与现有搜索重复 | 搜索视图入口移除，结果由启动器承担，单一入口 |
| 收件箱聚合依赖新 API | 轻量查询，复用审计/meta；无 API 时首页降级为"最近打开" |
| 引导打扰老用户 | 一次性 + 可跳过 + 进度条可关闭 |
