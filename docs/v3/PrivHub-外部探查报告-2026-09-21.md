## 二、功能与控制方式（已摸清）
- **功能**：账号登录/注册；多项目管理（`project-create`/`project-delete`）；文件浏览/预览（`preview`/`preview-raw`）/新建目录/改名/删除；回收站（`trash-list`/`restore`/`purge`/`clean`）；设置；**插件 / 智能体接入开发者平台**。
- **控制方式**：
  - 人工：Web UI（登录 → 项目 → 文件 → 操作）
  - 程序/AI：REST API 统一前缀 `/privhub/api/*`，鉴权头 `Authorization: Bearer <token>`；token 由 `/privhub/api/login`（账号+密码）下发，存浏览器 localStorage。
  - 插件架构：`/privhub/api/shell/manifest` 列出插件 → `import()` 动态加载，按 slot 镶嵌 UI；插件子资源靠**会话 Cookie** 鉴权。
- **公开端点**：`/privhub/api/shell/manifest` 无需登录，返回 `partial:true` 的基础插件清单（认证、骨架）。

## 三、无法连通 / 链接困难（重点）
1. **旧地址已成死链且仍被在用工具体引用**（已修，见第四节）。
2. **AI link key 无法建立会话（核心链接困难）**：
   - 当月 key（`pha_xxxx`，36 位）可经 `get_key.py` 取到，但：
     - 作 `Bearer` 打 `/me`、`/projects` → `未登录`
     - 作 `apikey` 字段 / 用户名+密码 打 `/login` → `用户名或密码错误`
     - `/privhub/api/ai/*`、`/key`、`/token`、`/agent`、`/link` 等疑似端点 → 404
     - 作 query 参数 → 401
   - 结论：当前公开/未登录面**无法用该 key 换取有效 token**；智能体接入的确切鉴权端点与头字段服务端**未在公开面暴露**（仅登录后加载的 agent 插件含开发者平台说明）。即"AI 链接"目前对外部智能体是断的。
3. **插件 Cookie 依赖脆弱（架构性，历史 S16 白屏根因）**：`import()` 加载的插件子资源无法带 `Authorization` 头，只能靠服务端下发的会话 Cookie 证明身份；SPA 启动先打 `/me` 补 Cookie。一旦 Cookie 缺失（被清/隐私模式/跨上下文），插件整体 401 → "界面加载不出来"，错误只进 console。
4. **（待复核）静态资源 GET 在本环境返回空体**：根 HTML GET 正常（63829 字节），但 `/vue.global.prod.js`、`/privhub-plugins/*/index.js` 等 `.js`/`.svg` 的 GET 返回 HTTP 200 却 0 字节（HEAD 却报 content-length 3188）。可能是本沙箱 curl 的怪异或服务端特定响应，需在真实浏览器复核。

## 五、改进建议
1. **全量替换旧地址引用**：除已修两处，建议再扫一遍所有仓库/文档/书签/代理脚本里的 `192.168.10.55`，统一改 `192.168.20.11`；可做成全局替换任务。
2. **打通 AI 链接鉴权（最紧迫）**：让服务端提供明确机制——推荐专用 `/privhub/api/ai/login`（用 key 换 token）或把 key 映射到固定只读用户；并在「开发者平台」面板直接给出 curl 示例与头字段，消除"靠口口相传"。
3. **消除插件 Cookie 单点脆弱**：让 `/privhub-plugins/*` 子资源也能认 `Authorization: Bearer`（或改用 import map 注入 token、或同源已登录态+服务端对插件路由统一鉴权），避免 Cookie 缺失即全站白屏；并对 401/网络错误给出可见提示而非静默卡死。
4. **前端连通性自愈**：检测到 401 或"网络错误：无法连接服务器"时，明确提示"服务器地址可能已变更/网络不通"，并在登录框上方常驻当前基地址，避免误连旧 IP 无人察觉。
5. **静态资源 GET 异常排查**：在真实浏览器/不同客户端复核 `.js` 资源是否真返回空体；若是服务端问题，检查是否对带特定 Accept/无浏览器头的请求返回空（可能影响部分自动化客户端）。
6. **文档固化**：把"现用地址 + AI 链接用法 + 常见 401/连不上排查"写进 PrivHub 开发者平台面板与项目 README，减少重复踩坑。
