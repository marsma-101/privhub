# PrivHub 小白使用问题清单

> 视角：**不懂代码的普通使用者**。只问两件事——「这功能我怎么用」「我知道有这功能，但它藏在哪儿」。
> 全部结论来自本仓库代码与文档实勘（标 [一手]），个别标 [存疑]。
> 复核日期：2026-09-18 · 对应版本 v3.1.0

---

## 一、会真正卡住的（功能有，界面上没路）

### 1. 改不了自己的密码 [一手 · 代码核实]

- **现象**：README 写「首次启动自动生成默认账号 admin / admin123（**登录后请立即修改密码**）」。可是全系统只有一个密码相关接口 `POST /privhub/api/admin/user-reset-password`——**只能管理员重置别人的**。设置页、个人菜单里都没有「修改密码」。
- **证据**：`plugins/privhub-admin/src/index.ts:119`（唯一的 password 路由）；`plugins/privhub-shell-settings/client/index.js` 全文无改密入口；`plugins/privhub-auth/client/index.js` 只有 login / register。
- **影响**：普通用户改密码必须找管理员；管理员自己改不了（得自己给自己重置，界面还未必允许）。README 那句「立即修改」是空头指令。

### 2. 「个人空间」在整个界面上没有名字 [一手 · 代码核实]

- **现象**：注册时系统按真实姓名建了一个**仅本人可见**的文件夹（智能体的可写沙箱）。但在界面上，它就**只是一个和你同名的项目**，出现在项目下拉和左侧项目列表的第一位。没有「我的空间」「仅我可见」之类任何标记。
- **证据**：`plugins/privhub-core/src/index.ts:611` `visibleProjects()` 返回 `[own, ...base]`；代码注释（`privhub-core/src/index.ts:89`）写着「**前端据此在项目列表里标记「我的空间」**」——但全仓库客户端与 `frontend/index.html` 里搜不到「我的空间」四个字。唯一线索是设置页那句「你的文件夹名和它保持一致：张伟（仅你本人可见）」（`plugins/privhub-shell-settings/client/index.js:106`）。
- **影响**：小白看到自己名字的项目会当成一个普通项目；不会知道智能体往这儿写、不会被查重/搜索碰到、系统永不删除。**这是本清单里最该补的一处**——功能设计得很细，界面上一个字没交代。

### 3. 全文搜索在个人空间里永远搜不到东西，且不解释 [一手 · 代码核实]

- **现象**：搜索页有「📄 文件名 / 🔎 全文」两个模式。在个人空间里用「全文」，结果恒为「没有匹配「xx」的内容」——因为个人空间压根不进索引，界面不说原因。
- **证据**：`plugins/privhub-files-fulltext/src/index.ts:48,87` 明确跳过个人空间；`plugins/privhub-files-search/client/index.js:126` 空结果固定渲染「没有匹配…的内容」。
- **对比**：同一件事在查重上处理得对——`plugins/privhub-svc-rag/src/index.ts:1237` 返回「查重仅针对项目，不作用于个人空间」，界面会照实提示。搜索漏了这层。

### 4. 导出功能只有一种人找得到 [一手 · 代码核实]

- **现象**：MD → HTML / PDF / Word 的导出（文档里的 F21）**只存在于 Markdown 编辑器内部**。在文件列表的 ⋯ 菜单和右侧详情面板里都没有「导出」这一项（详情面板有「🌐 生成页面」，那是 md→HTML 展示页，不是导出 PDF/Word）。
- **证据**：`plugins/privhub-files-edit-md/client/index.js:365` 调 `/privhub/api/export`；`plugins/privhub-files-explorer-v3/client/detail.js:189-198` 的 9 个按钮与 `panel.js:500-512` 的 ⋯ 菜单均无导出。
- **影响**：小白想「把这个 md 转成 Word 发给同事」，会在文件上右键找半天，找不到。

### 5. 界面上看不到版本号 [一手 · 代码核实]

- **现象**：`GET /privhub/api/health` 会上报版本，但前端**没有任何一处调用它**。设置页、管理控制台、关于页都没有版本信息。
- **影响**：报障、对文档、判断「我这台是不是旧版」，用户都无从下手。

## 二、找不到 / 认不出（入口偏，或名字对不上）

### 6. 「🔁 查重」藏在「🤖 AI 工具」里 [一手]

- **现象**：查重是全员功能（项目级去重），但它的家在 AI 工具视图里，页签写着「🔁 项目查重」。图标栏上只看到 🤖 一个入口，名字跟查重没关系。
- **现状**：文件页顶栏有一个「🔁 查重」直达按钮（`plugins/privhub-files-explorer-v3/client/panel.js:434`），算是补救，但只有**打开项目后**才看得到；在还没进项目时无处可找。
- **顺带**：AI 工具里还有「语料治理」和「我的 AI 密钥」，三件不相干的事挤在一个名字很泛的图标下。

### 7. 「自动备份」只在管理控制台侧栏，且没有面向用户的说明 [一手]

- **现象**：git-backup 把 `data-files/` 镜像成本地 git 裸仓。界面入口只有管理控制台「系统运维 > 自动备份」，展示可用性 + 手动触发一次提交。
- **缺口**：`/privhub/api/gitbackup/history` 与 `/gitbackup/restore` 两条路由**任何前端都没调用**（实测扫描）；也就是说「怎么恢复」在界面上是空白。备份做没做、备到哪、怎么回滚，用户都看不到。

### 8. 「邀请成员」的入口极深 [一手]

- **现象**：只有在**已进入项目**、展开树根节点、点根节点的 `⋯` 菜单，才会看到「📨 邀请成员」——而且**仅管理员可见**（`plugins/privhub-files-explorer-v3/client/panel.js:509` 附近，`isRootMenu && isAdmin`）。
- **影响**：普通成员想拉同事进项目，界面上找不到（只能走流程找管理员）。管理控制台侧栏里也没有「邀请」这一项。

### 9. 图标栏是 10 个纯 emoji，靠鼠标悬停才知道是什么 [一手]

- **现象**：业务图标栏按顺序是 📁 文件、🔍 搜索、🕸️ 知识图谱、🏷️ 标签、📝 新建文档、📚 知识库、⭐ 收藏、🗑️ 回收站、🔌 智能体接入、🤖 AI 工具；底部是 👥 + ⚙。中文名只写在 `title` 属性里，**只有鼠标悬停才弹出**（`frontend/index.html` 的 `.abar-item:hover::after { content: attr(title) }`）。
- **影响**：触屏 / 平板完全无提示；新用户得把 12 个图标挨个悬停一遍才知道哪个是哪个。「📁 文件」和「📝 新建文档」这两个尤其容易被当成同一类。

### 10. 「打开侧栏 / 收起侧栏」措辞含糊 [一手]

- **现象**：顶栏右侧那颗按钮切换的是**右侧文件详情面板**（`plugins/privhub-shell/client/index.js:55` 附近的 TopbarUser）。
- **影响**：同时还有左侧目录树的折叠按钮（`⏴`，提示「收起侧边栏」），两个「侧栏」指的是两个东西，小白容易搞混。

## 三、小磕绊与不一致

### 11. 底部的管理图标：图标和提示都是「用户管理」，点开却是「管理控制台」 [一手 · 实测]

- **现象**：图标栏底部固定组的代码是「按 view 名取**第一个**匹配项」（`plugins/privhub-shell/client/index.js:80-83`，`order = ['admin','settings']` + `find`）。而 `view: "admin"` 被两个插件同时声明：
  - `privhub-admin` → 图标 👥，名称「用户管理」
  - `privhub-admin-console` → 图标 🛠️，名称「管理控制台」
- **实测顺序**：本机 `readdir` 返回 privhub-admin 在前，因此底部实际显示 **👥「用户管理」**，点击进入的却是整个管理控制台。
- **旁证**：manifest 聚合处会打印告警「barItems 冲突：view "admin" 由 privhub-admin 与 privhub-admin-console 同时声明」（`plugins/privhub-shell/server/index.ts:57-62`）。
- **文档对不上**：「图标栏底部管理组现为「🛠️ 管理控制台 + ⚙ 设置」」（`docs/PrivHub-架构与功能说明.md` 3.3 节）与实测不符。

### 12. 「新建」的操作流程不统一 [一手]

| 菜单项 | 实际行为 |
|---|---|
| 📄 新建文档 | 走三步向导，可**选格式 / 填名字 / 选目录**，md 还能套模板 |
| 📊 新建数据表 | 点一下**立刻**生成 `未命名数据表-x9k2.xlsx`，不问名字不问目录 |
| 🌐 新建页面 | 点一下**立刻**生成 `未命名页面-x9k2.html` |
| 📈 数据看板页面 | 点一下立刻生成（`dataview:new`） |

- **证据**：`plugins/privhub-files-explorer-v3/client/ops.js:319-345`；`plugins/privhub-files-dataview/client/index.js:6-20`。
- **影响**：小白会先得到一个名字奇怪的文件，再自己去重命名。「🌐 新建页面」生成的是 `.html`，多数人不知道那是什么。

### 13. 「📚 向量数据库（开发中）」灰按钮摆在正式按钮区 [一手]

- **位置**：右侧详情面板按钮组（`plugins/privhub-files-explorer-v3/client/detail.js:198`）。未完成的功能与可用功能并列显示。

### 14. 详情面板的按钮灰了，但不说清楚为什么 [一手]

- **现象**：详情面板 9 个按钮中，「编辑 / 批注评论 / 生成页面 / 发布链接 / 版本历史」都按文件类型置灰，提示语只写「**仅支持 md 文档**」「仅支持文本类文件」——没写「**你当前选中的是 xlsx**」。
- **影响**：选中一个 Excel 后按钮灰了，用户第一反应是「坏了 / 我没权限」，而不是「类型不对」。

## 四、引导与文档脱节

### 15. 「引导体系」实际只有一个界面有 [一手]

- 架构文档 3.4 节宣称「各区块标题旁 ⓘ 帮助卡 + 页签顶部 💡 快速上手 + 教程卡」。
- **实测**：在全部客户端里搜「快速上手 / 帮助 / 教程」，**只有 `privhub-svc-rag`（AI 工具）一个插件命中**。其余 12 个视图（设置、标签、模板、知识库、图谱、搜索、收藏、回收站、管理控制台等）都没有任何就地说明。

### 16. 默认账号密码只写在 README 里，登录页一个字没有 [一手]

- `plugins/privhub-auth/client/index.js:39-66` 登录卡只有用户名 / 密码 / 注册链接。
- **影响**：拿到程序包但没读 README 的人，第一关就进不去。反过来，把默认密码写到登录页又有安全权衡——这是个需要拍板的取舍，不是纯缺陷。

### 17. 文档与代码的其他不一致（照文档找会扑空）

| 文档说法 | 实际情况 |
|---|---|
| 图标栏底部是 🛠️ 管理控制台 | 实测是 👥 用户管理（见第 11 条） |
| 多标签页由 `F01 shell-tabs` 提供，走 `tabs` slot | **无任何插件声明 `tabs` slot**；标签页已并入 `privhub-files-explorer-v3/client/tabs.js`，骨架里那段 `slotComps.tabs` 是死代码 |
| 「所有落盘数据均已加密」 | 文档自己已纠正：settings / comments / publish / invites 四个 JSON 是明文 |
| 部署包与源码同步 | `docs/` 与 `deploy/privhub-deploy/` 各落后一版（少 `privhub-admin-console`、`privhub-shell-agent-console`） |

## 五、给主子的拍板清单

按婢子的看法，下面这几条值不值得动、先动哪个，请主子定：

1. **个人空间在界面上要不要正名**（第 2 条）——这是设计里最细致、界面上最沉默的一块。加个「我的空间」标签是小改动，但要先定**文案口径**（叫「我的空间」还是「我的文件夹」）。
2. **修改自己密码**（第 1 条）——要补的话是**新接口 + 新界面**，属于功能缺失而非样式问题；也可以选择「就用管理员重置」并在 README 里改口径。
3. **底部管理图标的身份**（第 11 条）——一条 `find` 顺序问题，改动极小，但**文档说法要一起改**，否则下次复核还会对不上。
4. **全文搜索在个人空间的空结果是否要给提示**（第 3 条）——文案级改动，成本最低、体感最直接。
5. **导出入口是否上浮到文件菜单**（第 4 条）——影响「转 Word 给同事」这类最高频的实际动作。

> 本清单只摆问题与证据，不动手改；要落到代码或并进 `docs/PrivHub-改进建议.md`，等主子发话。
