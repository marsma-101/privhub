## 一、已确认决策（2026-09-05 讨论收敛）

| # | 决策 | 结论 |
|---|---|---|
| 1 | **数据不出网红线** | 语料与模型调用全部限定服务器/局域网内；如有外送需求由运维在模型服务端自行承担，系统不做云端方向（隐私合规优先） |
| 2 | **模型接入 = 运维配置式** | 系统不做模型选型；新增 `privhub-svc-model`（L2）：运维填 OpenAI 兼容 `baseURL + apiKey(可选) + 模型名` 即用；LLM 与 embedding 可分别指向不同端点/模型；启动自检 + 界面可见状态 |
| 3 | **数据质量优先** | P1 先做「语料治理」（解析/清洗/去重/策展/人工裁决），再做检索与问答——Pre-Retrieval 决定上限（Gao 2023 Survey；Barnett 2024 七失败点） |
| 4 | **原文不可动** | 原文（S7 加密）是唯一事实源；清洗/整合/标记全部作用于**派生语料层**，可重建、可审计、可回滚 |
| 5 | **人工裁决闭环** | 冲突/重复/时效问题 → 待裁决清单 → 人工动作（保留 canonical / 合并 / 剔除 / 过期）→ 台账；不做全自动破坏性决策（human-in-the-loop 共识） |
| 6 | **内容不预整合，元数据要规范** | RAG 检索自带聚合，内容保持原样 + 结构感知分块；元数据（frontmatter：类型/日期/作者/项目/标签/版本）需规范化（编目卡原则） |
| 7 | **Key 管理 UI 并入 RAG 界面** | Agent API 密钥的生成/续期/吊销/用量 + 专属空间回收站，随 RAG 界面第一期一并交付 |
| 8 | 向量库 | P2 定：推荐 sqlite-vec（单文件、零外部进程、低配友好），chunk/元数据设计先行保证可换引擎 |

## 三、模型接入层 `privhub-svc-model`（L2，M0 前置）

### 3.1 配置（插件 Config，运维填）

```ts
{
  enabled: false,                    // 未配置时不启用（RAG 界面显示「未接入模型」）
  llm: { baseURL: '', apiKey: '', model: '', timeoutMs: 60000 },       // chat/completions
  embedding: { baseURL: '', apiKey: '', model: '', timeoutMs: 30000 }, // embeddings（可指向不同服务）
  maxRetries: 2,
}
```

### 3.2 行为

- **协议**：OpenAI 兼容（POST `{base}/v1/chat/completions`、`{base}/v1/embeddings`；Ollama / vLLM / LM Studio / DSH 网关均兼容）。
- **能力探测**：`GET {base}/v1/models`（可选）→ 缓存模型清单；运维配置的模型名不在清单时界面警示（不阻断调用）。
- **启动自检**：进程启动 + RAG 界面打开时做连通性检查（`/v1/models` 或最小 embedding 调用），状态：`ok / unreachable / no-key / timeout`，界面可见。
- **调用封装**：批量 embedding（自动分批 ≤32 条/批）；chat 支持流式与非流式；超时/重试（指数退避）；统一错误映射（超时→MODEL_TIMEOUT、401→MODEL_AUTH、404→MODEL_NOT_FOUND）。
- **红线**：不内置任何厂商 SDK/方向；不做云端回退；模型服务地址必须内网可达（配置检查给出局域网提示）。
- **测试**：内置 mock provider（配置 `{ baseURL: 'mock' }`）——离线单测不依赖模型。

## 四、P1 语料治理（数据质量基建，本阶段核心）

### 4.1 摄取与解析

| 事件 | 动作 |
|---|---|
| 启动全量扫描 / `file:changed`(created/saved/restored) | 解析 → 清洗 → 更新语料 |
| `file:changed`(deleted/purged/renamed/moved/clean) | 移除/移动语料与索引 |
| `file:saved`（编辑保存） | 增量重解析该文档 |

- **解析矩阵**：md/txt（编码检测，复用预览逻辑）· docx/xlsx/pptx（复用 svc-office）· pdf（pdf-parse + 扫描件标记）· html（去标签）；其他类型（图片/压缩包）不进语料。
- **清洗规则**（输出到派生层）：页眉页脚/签名块去除（可配置正则）· 空行/连续空白归一 · 编码统一 UTF-8 · 超长单行截断规则。
- **敏感过滤**：复用 Agent 的敏感扩展名黑名单 + 「不含内容」文件（小于阈值）跳过；可选 OCR 结果不进语料。

### 4.2 去重与冲突检测

- **精确重复**：内容哈希（去除空白后）→ 跨文件去重报告。
- **近似重复**：MinHash/SimHash 签名聚类（阈值可调）→ 供人工裁决（自动仅报告，不删除）。
- **冲突组**：同名异文（同一路径内容 hash 变化 & 多版本并存）、版本系列（名称含 v1/v2/日期）。
- 输出：`待裁决清单`（语料视图内分组呈现）。

### 4.3 策展台账与人工动作

- `data/rag-curation.json`：`{ docId: { canonical: true/false, mergedFrom: [], excluded: true, expiredAt?, note, by, at } }`。
- 人工动作（语料工作台）：保留首选 / 合并（主+从，生成合并视图，保留来源映射）/ 剔除（可恢复）/ 标记过期（检索排除，文档仍可读）。
- **原则**：台账只驱动派生语料；原文一个字节不改；台账变更后语料重建（增量）。

### 4.4 元数据规范化（编目卡）

- 摄取时补齐 frontmatter 字段（缺省推导）：`type / updated / author(上传者) / project / tags(复用 svc-meta) / lang`；中文/大小写/日期格式归一。
- 元数据参与检索过滤（按类型/项目/标签筛选）。

### 4.5 分块与语料存储（P1 落文本层）

- 结构感知分块：标题/段落/代码块边界优先，块大小目标 400–600 token、重叠 50 token；中文按 CJK 边界切（不切词）。
- 语料落盘：`data/rag-corpus/`（S7 加密 jsonl：`{ docId, chunkId, text, meta, srcHash }` + `manifest.json` 元数据索引），为 P2 向量化预留字段（vector 列由 P2 的 embedding 填）。
- **可重建**：任意时刻可从「原文 + 台账」全量重建语料；`srcHash` 校验原文未变（变了 → 标脏 → 重解析）。

## 六、P2 检索与问答（后续）

- 向量化：语料经 `svc-model.embedding` 批量入库（sqlite-vec）；失败重试/续传。
- 混合检索：BM25（现有）+ 向量 TopK 融合（RRF）；**ACL view 实时过滤**（复用 authProjectRead 模式）+ 时效过滤 + canonical 优先；可选 rerank（模型侧能力，视运维模型而定）。
- 问答：`/api/rag/ask`（LLM 经 svc-model）→ 带引用的回答（引用 = chunk 的来源文档/路径/版本）；流式输出。
- 权限：检索注入用户可见项目 ∩ ACL；问答记录入审计（user 维度）。

## 七、P3 评估闭环（后续）

- RAGAS 式指标（faithfulness / context precision / answer relevance）可就近采样运行（需 LLM，代价可控）；
- 用户反馈：答案 点赞/纠错 → 纠错写回策展台账（标记问题文档/请求重写）；
- 指标面板：检索命中率、无答案率、语料健康度。

## 九、开放问题（少量，实施中确认）

1. 语料准入默认值：默认全部文档 `rag: true`（可在语料目录关闭）——倾向此方案，实施时可调。
2. 扫描件（PDF 图片型）：P1 仅标记不进语料，OCR 作为可选增强（资源敏感）。
3. 模型配置的 apiKey：存 data（S7 加密）——复用 storage 即可；不入审计/日志。
