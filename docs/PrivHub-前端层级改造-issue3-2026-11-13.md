## 一、为什么不照抄

issue #3 描述的是一份**理想重构蓝图**（L0–L3 四层、项目层 4 固定 tab、个人层 4 tab、管理层 5 模块）。
本项目的现实是：**41 个客户端插件、30 个 barItems、19 个管理路由**，且大量行为被回归套件钉死。
照抄会直接违反第 ① 条要求，实测有两处硬冲突：

| issue #3 的要求 | 与本项目的冲突 | 本轮决定 |
|---|---|---|
| 管理控制台对非 admin **渲染为禁用态**（保留可见性） | `tests/admin-console.mjs` 钉住「普通用户看不到管理入口」——这是**安全契约**，不是排版偏好 | **保留现状**（不渲染）。可见性收敛到最小是既有产品决定 |
| 个人层设「我的规则」tab、界面出现「个人空间」概念 | `tests/personal-ui.mjs` D2 段钉住「用户可见文案不得出现『个人空间』」（主人明确说过那种形式难看） | **保留现状**。个人入口叫「我的文件」，用真实姓名当目录名 |
| 项目层固定 4 tab、管理层固定 5 模块 | 现有 19 个管理路由 / 6 个知识类功能无处安放，砍掉即删功能 | **不重组 tab**，改用「频率分层 + 低频下沉」达到同样的减负效果 |

**采纳的是它的原则，不是它的骨架**：以项目为中心、频率决定位置、深度封顶、状态可回退、
三态覆盖、控件反映当前态、逻辑与样式解耦。

## 二、改了什么

### 1. 首屏变成 L1「项目总览」驾驶舱（新增）

工作台（`privhub-shell-home`）首屏改为回答三个问题，自上而下即优先级：

1. **整个盘子怎么样** → KPI 行：可见项目 / 卡点合计 / 平均进度 / 我的待办
2. **活儿堆在哪一段** → 管线聚合：待办·进行中·待审核·已完成 四态堆叠条 + 图例 + 合计（**只放聚合，不放明细**）
3. **该点进哪个项目** → 项目卡片：健康度 / 进度条 / 当前节点 / 卡点原因 / 成员 / 最近截止，整卡可点进项目
4. 最后一张「我的」入口卡：我的文件（本人目录顶层条目数）/ 我的任务 / 全部项目

新增文件：
- `plugins/privhub-shell-home/client/overview.js` — 组件与数据流
- `plugins/privhub-shell-home/client/overview-styles.js` — 样式（令牌化）
- `plugins/privhub-project-dashboard/src/overview.ts` — **跨项目聚合纯函数**
- `GET /privhub/api/dashboard/overview` — 服务端总览端点（挂在既有 project-dashboard 插件下）

### 2. 低频功能下沉一层（图标栏）

每段只有前 **2** 个条目直显，其余收进段内「更多」抽屉（再点一次展开）：

| 段 | 常用（直显） | 低频（「更多」里） |
|---|---|---|
| 文件 | 文件 / 搜索 | 收藏 / 回收站 |
| 知识 | 知识库 / 知识图谱 | 标签 / 新建文档 / 引用检查 |
| 协作 | 任务看板 / 项目看板 | 任务日历 |
| AI | AI 工具 | （无） |

**关键实现取舍**：`sections[].items` 保持**全量且顺序不变**，`primary` / `more` 只是渲染层切分。
这样「一条不删」有代码级证据，且既有 `iconbar.mjs` 的顺序断言全部照旧通过。
切分按**位置**而非写死名单——段内顺序本身就是频率排序，只维护一处，不会两份名单互相漂移。

当前视图若藏在低频区，`syncOpen()` 会**自动展开**并点一个提示点：
否则用户从别处进了某功能，栏里却看不到自己在哪，「我在哪儿」这条线索就断了。

### 3. 原工作台内容整体下沉，一条没删

快捷入口 / AI 连接状态 / 最近打开 / 我的收藏 → 收进「🧰 个人工作面」折叠区。
默认收起把首屏让给总览；**展开状态记在 localStorage**，常翻最近/收藏的人开一次就一直开着。

### 4. 顶栏主题即时切换（个人偏好）

🌙/☀️ 一键切换，立即生效、无保存按钮；权威写入仍走骨架 `applyTheme()`（不另存一份 localStorage）。
按钮显示**下一步动作**，`aria-label` 说明**当前状态**。

### 5. 顺手修掉一个静默失真

`home` 模板引用了 `modelOk` 但组件从未定义它 → AI 徽标恒显示「待处理」。
已补真源（LLM 与 embedding 两条通道都 ok 才算可用），并加断言钉住。

## 三、三条不可越界的数据纪律

1. **进度只有一个真相源**：总览不另存进度副本，直接投影任务看板的 `TaskSummary`。
   同一份数据算两次必然漂移，这是本项目踩过的坑。
2. **不编造数字**：没建过任务 → `percent=null` → 界面「—」，**不是 0%**；
   文件数未统计 → `null`，不是 0 个文件；平均进度只在「有任务的项目」上取均值，空板不拉低分母。
3. **隐私边界**：范围 = `indexableProjects`（**排除个人空间**）再逐个 `canAccess`。
   聚合层是纯函数，**不得自行枚举项目**（源码级断言禁止出现 `allProjects`/`listFiles`/`node:fs`）。
   个人入口只取 `personalDirOf(当前用户)`，管理员也拿不到别人的。

**性能取舍**：总览**不做 `computeFacts` 递归扫描**——72GB 的库扫一遍就是几十秒，
乘以几十个项目足以把首屏拖死。成员数改从用户表现算（O(用户数)），文件数留 `null`。

**卡点口径写在界面上**（可复核，不是一个孤零零的数字）：
> 卡点 = 逾期未完成的任务 + 超出 WIP 上限的在制品 + 计划里标记为受阻的条目

### 过程中真实修掉的问题（不含糊掩盖）

**产品缺口（实测发现，不是测试问题）**

1. **项目多于 60 个时搜索失效**：原先筛选只在前端做，而首屏只加载前 60 个项目 →
   第 61 个项目**永远搜不到**，用户会以为它不存在。已改为服务端 `?q=` 在**截断之前**
   按全量可见名单查找，并补读首屏之外的命中；KPI 与「我的待办」**不随筛选缩水**（始终全盘口径）。
   前端配套：防抖 300ms、丢弃过期回包、清除筛选要重新取数、卸载时清防抖计时器。
2. **桶归类只认中文「审核」**：自建列名叫 `REVIEW` 会被误归成在途 → 标题也认英文。
3. **`modelOk` 从未定义**：AI 徽标恒显示「待处理」→ 补真源（两条通道都 ok 才算可用）。

**测试自身的假保险（会让「绿」失去意义）**

4. `integrity.mjs` 的「工作台只复用既有接口」只扫 `index.js`，
   而总览端点在拆出的 `overview.js` 里 → **这条契约扫不到新代码**。已改为扫整个 `client/` 目录。
5. `/api/admin/users` 出于隐私只回 `hasPersonalSpace`、不回目录名，
   拿它取 `personalDir` 永远得空数组 → 改用 `allProjects` 做对照集，断言才真能失败。
6. 「L1 只读」原先靠注释里写了「只读」判断 → 改成真数端点与 `api()` 调用点个数。
7. 我自己写错的两条断言：`dueAt` 应取最早的**未完成**截止（逾期项也算）；
   `isActive` 对回收站读的是 `nav.trashView` 镜像标志，mock 只设 `activeView` 属于与组件脱节。

### 一次必须记下的误判（过程诚实）

中途我曾根据**被截断的工具输出**宣称「HTTP 368/368 全绿」，**这是错的**。
把完整输出落盘后实测是 **360 通过 / 9 失败**：

- **1 条**是我新加的总览断言 —— 真因就是上面的产品缺口 ①（测试根里数百个历史项目把它挤出前 60）。
- **8 条**是 `refcheck` 套件扫到**上一轮残留**（报错里期望本轮后缀 `ek7moi`、实际扫出上轮 `eftkgd`）。
  按「先怀疑环境、做对照实验」的原则，**不删任何既有测试数据**，换全新测试根复跑 → 8 条全绿，
  证实与本批改动无关。
- 第二次对照我自己又设错了环境变量：`media-preview` 与 `mindmap` 各自默认占 **3191**，
  我把主实例也指到 3191，造成 13 条**端口串扰假失败**。只换测试根、端口保持默认 3190 后 → **exit 0**。

结论：**回归结论必须以完整日志 + 进程 exit code 为准**，不能看尾部截断输出。

## 五、已上线生产（含一次参数踩坑）

**发现**：生产 3181 的 `active.releaseDir` 指向的**就是开发目录本身**（不是 `releases/3.5.0`）。
所以改 `frontend/index.html` 与 `plugins/*/client/*.js` 会**立刻在生产生效**（nginx 直读该目录），
但服务端新路由要等进程重启才加载 —— 一度出现「新界面已上线、它依赖的新 API 还是 404」的半截状态：
打开生产工作台，首屏总览显示「读取失败 + 重试」。

**处置**：就此询问主人，主人选择「蓝绿切换让新代码完整生效」。

**踩坑（我自己写错命令）**：第一次执行
`switch --release <开发目录> --version 3.5.0` 返回 `ok:true`，但跑的是**旧发布包**。
真因在 `runtime/control.mjs` 的 `performSwitch`：

```js
const info = version ? findReleaseByVersion(version) : resolveReleaseArg(releaseArg)
```

`--version` 优先级高于 `--release`，于是它去 `releases/` 按版本号找到了旧包。
**正确命令：只传 `--release`**（版本号由 `validateRelease` 自己从 `package.json` 读）：

```powershell
node runtime\control.mjs switch --release 'G:\program\dsh-SQL\privhub'
```

**切换后实测（不是「应该可以」）**：

| 核验项 | 结果 |
|---|---|
| `/privhub/api/health` | `ok=true` v3.5.0 **slot=green** pid 37956 |
| `GET /dashboard/overview` | **401**（已注册；此前 404）—— 对照 `dashboard/schema` 同为 401 |
| `GET /dashboard/overview?q=公共` | **401**（服务端按名查找也已加载） |
| `index.html` 含新低频折叠样式 | **是**（前端确为新版） |
| `active.json` releaseDir | 回到开发目录（与改动前的部署形态一致） |
| 槽位 | 3302 服务中、3301 已干净停止、control 3300 存活、nginx 3181 正常 |
| `scripts/verify-store.mjs --json` | **exit 0**，12 个账号、库内样本可读 |
| nginx 今日日志 | 只有 `[notice] signal process started`，**无 emerg/alert/crit** |

全程不停服（预热另一槽 → 冻结排空 → reload → activate → nginx reload → 停旧槽）。

> 教训：**「命令返回 ok」不等于「跑的是我要的代码」**。切换后必须实测三件事：
> health 的 slot、新路由 401 而非 404、`index.html` 是否含新代码特征串。
