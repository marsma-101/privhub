# PrivHub 交互改进说明：项目选择入口 + 文件视图三栏化（参照 llm_wiki）

> 日期：2026-08-30 · 状态：**方案待确认（本轮先改交互，不动视觉样式）**
> 参照源：`references/llm_wiki`（welcome-screen.tsx / app-layout.tsx / preview-panel.tsx / activity-panel.tsx）

---

## 一、用户反馈的核心问题

> 「在文件夹这个功能里边儿你不选项目的时候你点他是点不开的……对于第一次使用的人会觉得很别扭。
>  希望把选项目的这个工作放到文件夹的这里边儿：没有选项目的时候点开文件夹，里面是提示选项目；
>  进去了之后后续所有操作都是针对于这个项目的操作。」

**现状**：点「📁 文件」图标时——
- 已选项目 → 回到该项目文件视图（正常）
- 未选项目 → `backToWelcome()` → 欢迎页只有一句「请在顶栏点击项目开始浏览文件」，**没有项目列表、没有入口按钮**；选项目只能靠顶栏那个不显眼的下拉「选择项目：▾」

**问题本质**：项目选择入口（顶栏下拉）与文件视图（📁 图标）脱节。首次使用者在「文件」视图里找不到「选项目」的动作。

## 二、llm_wiki 的参照做法

llm_wiki 未进项目时显示 **WelcomeScreen**（welcome-screen.tsx）：
- 大标题 + 副标题（品牌区）
- **「新建项目」「打开项目」两个主按钮**
- **最近项目列表**（点击即进入，hover 显示删除）
- 进入项目后：左侧文件树 / 中间文件预览编辑 / 右侧研究面板

即：**「选项目」是文件视图的空态内容，而不是顶栏附属物**。

## 三、现状架构梳理（改动前）

### 3.1 导航状态机（frontend/index.html nav）
```
project: null | string      ← 当前项目（null = 未选）
path / entries / selected   ← 项目内浏览状态
activeView: 'files'|...     ← 视图化状态（⑤ 已完成）
projectsList: string[]      ← 当前用户可见项目（loadProjects 填充）
```

### 3.2 项目选择现状（两个入口，均不在文件视图内）
| 入口 | 位置 | 行为 | 问题 |
|---|---|---|---|
| 项目下拉 | 顶栏「选择项目：▾」 | selectOption → openProject | 不显眼，首次用户不知道 |
| 欢迎 ptab | 顶栏「🏠 欢迎」 | backToWelcome → 纯文案 | 无列表无按钮 |

### 3.3 文件图标点击逻辑（openBarItem）
```js
else if (view === 'files') {
  if (nav.project) nav.openProject(nav.project)   // 已选 → 回项目
  else nav.backToWelcome()                          // 未选 → 欢迎页（无交互）
}
```

### 3.4 权限模型（服务端已完备，本轮不改）
| 项 | 实现 | 位置 |
|---|---|---|
| 可见项目 | `visibleProjects(user)`：admin 全部；普通用户 user.projects | privhub-core/src/index.ts:270 |
| 项目访问 | `canAccess(user, project)`：admin 全放行；普通用户白名单 | privhub-core/src/index.ts:279 |
| 全链路校验 | files/list/preview/upload/doc/kg/tags/fulltext/export/edit-md 每个接口先 canAccess 再干活，无权限 403 | 各插件 src |
| 项目列表 API | `/privhub/api/projects` 返回**当前用户可见**项目（已过滤） | privhub-files/src/index.ts:29 |

> **结论**：权限后端无需任何改动。「用户能看到哪些项目」已经由 `visibleProjects` 在服务端过滤——前端只要展示 `projectsList`，普通用户天然看不到无权限项目。

## 四、目标架构（本轮实现）

### 4.1 文件视图空态 = 项目选择屏（核心改动）
`activeView === 'files' && project === null` 时，main 区显示 **项目选择屏**（替代现在的纯文案欢迎页）：

```
┌──────────────────────────────────────────────┐
│   📁 选择项目                                  │
│   选择一个项目开始浏览文件                      │
│                                              │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐      │
│  │ A项目     │ │ B项目     │ │ 公共      │      │  ← 项目卡片（可见项目）
│  │ 📂 打开  │ │ 📂 打开  │ │ 📂 打开  │      │
│  └──────────┘ └──────────┘ └──────────┘      │
│  [＋ 新建项目]（admin）                        │
│                                              │
│  （普通用户无可见项目时：提示联系管理员开通权限） │
└──────────────────────────────────────────────┘
```

**交互**：
- 点项目卡片 → `nav.openProject(name)` → 进入该项目（后续所有操作均针对该项目，现状已如此）
- 「＋ 新建项目」→ `nav.newProject()`（admin 才显示）
- 空态（普通用户无任何项目）→ 显示「暂无可用项目，请联系管理员开通权限」
- 数据源：`nav.projectsList`（登录/增删时已刷新）

**落点**（插件架构内）：
- 改造 `privhub-shell` 插件 client 的 `WelcomeView` 组件（shell 插件本来就提供 welcome slot）——从纯文案升级为项目选择屏
- 骨架 `nav` 无需大改；`openBarItem` 的 files 分支可保持（未选项目时 activeView='files' + project=null 自然显示项目选择屏）
- 顶栏项目下拉**保留**（快捷切换项目，与项目选择屏并存）

### 4.2 三栏布局（后续阶段，本轮仅规划）
参照 llm_wiki app-layout（左文件树 / 中预览 / 右研究面板），PrivHub 对应：

| 栏 | llm_wiki | PrivHub 现状 | 目标 |
|---|---|---|---|
| 左 | 文件树/知识树 | 目录树 ✅ | 保留 |
| 中 | 文件预览/编辑 | 文件面板（列表）+ 右栏预览 | **打开文件在中间主区展示详情**（MD 编辑器已有；图片/文本预览迁到中间） |
| 右 | 研究面板 | 预览右栏（340px） | **改为「文件信息 + 权限说明」面板**：文件名/大小/类型/修改时间 + 当前用户对该文件的权限（读/写，来自 ACL 规则）+ 标签/最近访问 |

**权限说明面板**（新能力，后续做）：
- 显示当前用户对选中文件的权限：`canAccess` 结果 + ACL 规则命中情况
- admin 显示「管理员：完全访问」；普通用户显示「可读写/只读」+ 命中规则描述
- 数据来源：可新增 `/privhub/api/acl/effective?project=&path=` 返回当前用户对该路径的有效权限（服务端计算，不泄露他人规则）
