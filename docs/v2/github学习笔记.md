## 第1课：Git 和 GitHub 到底是什么？

```markdown
# 📖 第1课：Git 和 GitHub 到底是什么？

## 一、为什么需要 Git 和 GitHub？

### 先看一个场景

假设你在写一个重要的文档、论文或者代码：

```
毕业论文_v1.docx
毕业论文_v2.docx
毕业论文_v2_修改版.docx
毕业论文_v3_导师修改.docx
毕业论文_v3_导师修改_我改的.docx
毕业论文_最终版.docx
毕业论文_最终版_真的最终版.docx
毕业论文_最终版_打死不改版.docx
```

是不是很崩溃？你根本不知道哪个是哪个，也不知道改了什么。

**Git 就是来解决这个问题的。**

---

## 二、Git 是什么？

### 用最简单的话说：

> **Git 是一个"版本记录工具"**，它能帮你记录文件的每一次修改，让你随时可以回到过去的任何一个版本。

### 一个比喻：游戏存档

Git 就像 RPG 游戏的存档系统：

- 打到 BOSS 前存个档 → 如果打输了，可以读档重来
- 走错路线了 → 可以回到之前的存档点
- 想试试新打法 → 可以开一个"副本存档"，不影响主线

**Git 的关键概念：**

| 游戏术语 | Git 术语 | 含义 |
|---------|---------|------|
| 存档 | 提交（Commit） | 把当前状态记录下来 |
| 存档点 | 版本 | 记录了谁、什么时候、改了什么 |
| 读档 | 回退（Reset/Checkout） | 回到之前的某个版本 |
| 副本存档 | 分支（Branch） | 在不影响主线的情况下尝试新东西 |

---

## 三、GitHub 是什么？

### 如果 Git 是存档系统，那 GitHub 就是：

> **一个存放"存档"的云端仓库，让多人可以共享和协作。**

### 为什么需要 GitHub？

- **备份**：代码放在网上，不怕电脑坏了
- **分享**：让别人看到你的代码
- **协作**：多人同时在一个项目上工作
- **展示**：你的 GitHub 主页就是你的技术简历

### Git 和 GitHub 的关系：

```
Git（工具）    →    在你自己电脑上操作
GitHub（平台）  →    在云端，存储和分享你的代码
```

**重要：Git 和 GitHub 是两回事！**

- Git 是免费的、开源的**软件**，安装在你电脑上
- GitHub 是微软旗下的**网站**，提供代码托管服务
- 类似的还有 GitLab、Gitee（码云）

---

## 四、怎么理解"版本控制"？

### 例子：写一个网页

**没有 Git 的时候：**
```
第一天：index.html（写了标题）
第二天：index_新.html（加了导航栏）
第三天：index_新_改.html（改了颜色）
```
→ 乱成一团，不知道哪个是最新的

**有 Git 的时候：**
```
第一天：提交 → "添加了网页标题"
第二天：提交 → "添加了导航栏"
第三天：提交 → "修改了配色方案"
```
→ 每次改动都有清晰的记录，随时可以回看

## 五、核心概念速览

| 概念 | 一句话解释 |
|------|-----------|
| 仓库（Repository） | 一个项目的"文件夹"，Git 会追踪里面的所有变化 |
| 提交（Commit） | 一次"拍照"，记录当前所有文件的状态 |
| 分支（Branch） | 一条独立的"工作线"，可以同时进行不同的开发 |
| 合并（Merge） | 把两条工作线的成果合在一起 |
| 克隆（Clone） | 把云端仓库下载到本地 |
| 推送（Push） | 把本地的改动上传到云端 |
| 拉取（Pull） | 把云端的改动下载到本地 |

# 📖 第2课：安装 Git 并注册 GitHub

## 一、注册 GitHub 账号

### 第一步：打开网站

在浏览器中打开：https://github.com

**取名建议：**
- ✅ 用英文或拼音，如：zhangsan、li-ming、xiaowang
- ✅ 可以加数字，如：coder123、dev_2024
- ✅ 简短好记，专业一点
- ❌ 不要用乱七八糟的字符
- ❌ 不要太长

> 以后找工作的时候，面试官可能会看你的 GitHub。用户名就是你给人的第一印象。

### 第三步：验证

## 二、安装 Git

### Windows 用户

**第1步：下载安装包**

打开：https://git-scm.com/downloads/win

点击下载，一般会自动选择64位版本。

## 三、配置 Git（必须做！）

安装完 Git 后，需要告诉 Git "你是谁"。因为每次提交都会记录作者信息。

打开终端（Windows 是 cmd 或 PowerShell，Mac/Linux 是 Terminal），输入：

```bash
# 设置你的名字（用英文，可以和 GitHub 用户名不同）
git config --global user.name "你的名字"

# 设置邮箱（要和 GitHub 注册邮箱一致！）
git config --global user.email "你的邮箱@example.com"
```

**示例：**
```bash
git config --global user.name "Zhang San"
git config --global user.email "zhangsan@gmail.com"
```

**检查是否配置成功：**
```bash
git config --global user.name
git config --global user.email
```

# 📖 第3课：你的第一个 GitHub 仓库

## 一、仓库（Repository）是什么？

### 一句话理解：

> 仓库就是一个项目的"家"，所有代码文件都放在里面。

### 类比：

```
你的电脑文件夹：
  📁 我的项目/
    ├── index.html
    ├── style.css
    └── 图片/

GitHub 仓库：
  📦 我的项目（仓库名）
    ├── index.html
    ├── style.css
    └── 图片/
```

区别在于：GitHub 仓库不仅存文件，还记录了文件的**所有修改历史**。

## 二、在 GitHub 上创建仓库

### 操作步骤

**第1步：登录 GitHub**

打开 https://github.com ，登录你的账号。

**第2步：点击新建**

你会看到页面左上角或中间有一个绿色按钮：**New** 或 **Create repository**

或者直接访问：https://github.com/new

**第3步：填写仓库信息**

```
┌──────────────────────────────────────┐
│ Repository name:  my-first-repo      │  ← 仓库名
│                                      │
│ Description: 我的第一个仓库（可选）    │  ← 描述
│                                      │
│ ● Public     ○ Private              │  ← 公开/私有
│                                      │
│ ☑ Add a README file                 │  ← 勾选这个！
│                                      │
│ 然后点击绿色按钮：Create repository   │
└──────────────────────────────────────┘
```

### 各选项说明

| 选项 | 说明 | 新手建议 |
|------|------|---------|
| Repository name | 仓库名称，只能包含英文、数字、-、_ | 用短横线分隔，如 my-first-repo |
| Description | 简单描述这个项目是干什么的 | 可选，但建议写 |
| Public / Private | 公开：所有人都能看到<br>私有：只有你能看到 | 学习阶段选 Public 就行 |
| Add a README file | 自动创建 README.md | **一定要勾选！** |
| Add .gitignore | 忽略某些文件不提交 | 先不选 |
| Choose a license | 选择开源协议 | 先不选 |

## 四、在线编辑文件

### 编辑 README.md

你刚才勾选了"Add a README file"，仓库里会有一个 `README.md` 文件。

## 五、什么是提交（Commit）？

### 简单理解

> 提交 = 给当前文件状态拍一张"照片" + 写一句说明

### 提交包含的信息

```
每次提交都会记录：
  ✅ 谁提交的（你的名字和邮箱）
  ✅ 什么时候提交的
  ✅ 改了什么文件
  ✅ 提交说明（Commit Message）
```

### 提交说明怎么写？

```
好的提交说明：
  ✅ "添加了登录功能"
  ✅ "修复了首页显示错误"
  ✅ "更新 README，添加自我介绍"

不好的提交说明：
  ❌ "修改"
  ❌ "123"
  ❌ "."
  ❌ "改了一些东西"
```

**原则：让别人（包括未来的自己）一看就知道这次改了什么。**
