## 一、插件复用三原则

对所有「想接入的功能」，按以下顺序裁决：

| 层级 | 原则 | 做法 |
|------|------|------|
| 第一层 | **能直接用的直接用** | 不改名字、不改代码。仅「跟随项目内容生成的代码」允许动（如项目名、配置）。原生代码能不动就不动。 |
| 第二层 | **部分可用需适配** | 复制一份 → 改名为项目名 → 改成能用的。原生代码能不动就不动。 |
| 第三层 | **都不行才自研** | 前两层都走不通，才自己写新插件。 |

> 裁决流程：先看能否「直接用」→ 不行看能否「复制改适配」→ 再不行才「自研」。

---

## 二、产品迭代 / 回滚机制

改插件 A 的内容时，遵循「先备份、后改、可回滚」：

1. **复制**：先复制插件 A → 插件 A-1（备份原版）。
2. **改 A**：在 A 上按需求修改。
3. **验证**：
   - ✅ 无问题 → 删掉 A-1，保留 A。
   - ❌ 有问题 → 卸载 A，装上 A-1 回滚。

> 目的：生产环境下做迭代更新时，只需在宿主机上「卸载旧插件、装上新插件」即可完成热替换，不影响后续使用，回滚零风险。

## 三、本次应用的裁决实例

- **案例：右侧可伸缩多面板侧栏**
  - 参照插件：`dsh-better-sidebar`（社区，React 全家桶 + 终端/Git/编辑器）。
  - 第一层「直接用」：❌ 带终端/Git 等文件盘无关能力 + 安全面，且深度依赖 DSH React/slot 体系，无法长到我们的 Vue 前端。
  - 第二层「复制改适配」：⚠️ 需带整套 React 依赖，改适配≈用 Vue 重写容器，名不副实。
  - **裁决**：落入第二层与第三层交界 —— **借鉴其「右侧可伸缩 + registerTab 多面板」设计思想，自研 Vue 版轻量容器**。保留其最有价值的能力：以后加面板 = registerTab 塞一个面板，不必重做侧栏。
