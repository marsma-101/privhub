## 0. 调研结论（实地核对的底座插件真机制）

依据本机实际代码（非臆想）：

1. **分层配置模型**：Profile / Bundle / Patch 四层合成插件树。插件靠 `package.json` 的 `dsh.bundle.patch` 字段声明挂载，`cordis.patch.yml` 里 `insert` 一行（`id` + `name`）即完成装配。
2. **前端宿主机制**：`web-app` bundle 通过 `frontend-static` 插件 + `webServer.registerFallback` 托管 dist（SPA），dist 位置由 `resolveDistIndex()` 决定（我们已改为可用 `PRIVHUB_FRONTEND_DIR` 环境变量覆盖）。
3. **HTTP 接口注册**：`ctx.webServer.register({ kind: 'exact'|'prefix', path, handler })`，handler 为 `(req: IncomingMessage, res: ServerResponse) => void|Promise<void>`，通过 `ctx.effect()` 注册（可逆）。
4. **服务键**：`ctx.webServer`、`ctx.fs`、`ctx.effect`、`ctx.provide` 等。
5. **模块解析**：profile 目录的插件包名通过 `healProfilesModuleFallback` 把安装依赖闭包 symlink 到 `$DSH_HOME/profiles/node_modules`，从而可解析 in-box 插件。
6. **rc.7 安全限制**：底座版本锁定 `0.1.0-rc.7`，**禁止命令行传 `--host 0.0.0.0`**（直接报错退出）；局域网绑定改由 profile 的 `cordis.patch.yml` 里 `host: 0.0.0.0` 实现。

## 1. 总体技术路径（已定）

**复用引擎基础设施，产出纯粹的文件盘程序（薄复用）。**

- 复用：底座 `dsh-base`（基础服务）+ `dsh-web-app`（webserver 等）+ `webServer.register` HTTP 能力。
- 替换：禁掉 AI 对话 UI，塞入我们自己的 Vue 文件盘 + 登录/文件接口。
- 前端：Vue 单页应用（登录页 + 顶栏/左树/中面板/右侧条 四区布局）。
- 后端：5 个 cordis 插件（core + auth/files/trash/admin 四业务域），通过 webServer 注册 HTTP 接口。
