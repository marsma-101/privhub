# 插件化重构设计 — PrivHub 施工蓝图

> **文档状态：现行设计基准（2026-08-28 确认）**
> 本文是「前端插件化 + 两层布局」重构的施工蓝图，取代《架构与插件设计.md》中被简化的「单 Vue 页宿主替换」形态。
> 配套基准：`文件管理系统-需求记录.md`（功能需求）、`插件工程规范.md`（插件写法）。
> 决策记录：用户确认——登录认证与权限管理分为两个插件；项目栏仅管理员可添加项目；一次性全拆（中间态保持可用）。

---

## 1. 背景与动机

### 1.1 现状问题

| 问题 | 现状 |
|------|------|
| 前端不是插件 | 全部 UI 是一个 50KB 单文件 `frontend/index.html`（内联 Vue 模板 + 全部逻辑），前端零插件化 |
| 前后端物理分离 | 前端在 `frontend/`，后端在 `plugins/`，同一功能的两侧隔得很远 |
| 承载靠 hack | 前端通过「接管底座 dist」（替换 `dsh-web-frontend/dist`）提供，rc.7 底座不识别 `PRIVHUB_FRONTEND_DIR` |
| 布局不合预期 | 现在是「项目树 + 文件面板」单层；用户要的是「项目栏 → 项目工作区」两层，且每栏内容可插拔 |

### 1.2 目标

1. **页面骨架插件化**：底座（cordis 生态）上加一个「页面骨架插件」（`privhub-shell`），提供三/四栏布局骨架，各栏内容由插件镶嵌。
2. **插件前后端一体**：每个业务插件目录内部分 `client/`（UI 组件）与 `server/`（API 逻辑）两侧，一个插件 = 一个功能域。
3. **两层布局**：
   - 第一层：**项目栏**（最左侧，可伸缩）——列出当前用户有权限的项目，顶部圆形 ➕ 添加项目（仅管理员）；类似 IDE 活动栏。
   - 第二层：**项目工作区**（点击项目进入）——顶栏 + 项目内目录树 + 文件面板 + 右侧预览/设置条。
4. **认证与权限分离**：`privhub-auth`（登录/注册/会话，管「你是谁」）+ `privhub-admin`（用户/角色/项目权限，管「你能干什么」）。

## 2. 目标架构总览

```
DSH 底座（cordis + webServer）
│
├── privhub-shell     页面骨架插件（前后端一体）
│     ├── client/     骨架：项目栏 + 工作区四区 slot + 主题切换
│     └── server/     骨架页托管 + 项目列表/创建 API + 插件 manifest 聚合
│
├── privhub-auth      认证系统（前后端一体）
│     ├── client/     登录/注册组件 → 挂 auth slot
│     └── server/     登录/注册/会话 API（现有代码平移）
│
├── privhub-admin     权限管理系统（前后端一体）
│     ├── client/     用户管理页/项目管理页 → 挂 topbar 入口
│     └── server/     用户 CRUD/角色/项目权限/重置密码（现有代码平移）
│
├── privhub-files     文件管理（前后端一体）
│     ├── client/     目录树组件 + 文件面板组件 + 预览条组件
│     └── server/     目录/文件/上传下载/预览 API（现有代码平移）
│
├── privhub-trash     回收站（前后端一体）
│     ├── client/     回收站组件（列表/恢复/彻底删除）
│     └── server/     回收站 API（现有代码平移）
│
└── privhub-core      共享服务（纯后端，无 client）
      └── server/     账号/会话/回收站持久化 + 文件根 + 权限判定（现有，保持不动）
```

## 3. 插件契约规范

### 3.1 目录结构（每个业务插件）

```
privhub-app/plugins/privhub-<域>/
├── package.json          # cordis 插件声明（现有，新增 client 入口字段）
├── cordis.patch.yml      # 插件配置（现有）
├── server/
│   └── index.ts          # 后端：路由注册（从现有 src/index.ts 平移）
└── client/
    ├── manifest.json     # 注册清单：{ id, title, slot, entry }
    └── index.js          # 前端入口：export default { component }（全局 Vue 组件）
```

### 3.2 Slot 定义（骨架提供的挂载点）

| slot | 位置 | 承载 |
|------|------|------|
| `auth` | 全屏（未登录时） | privhub-auth 登录/注册 |
| `project-bar` | 最左侧可伸缩栏 | privhub-shell 项目列表 + ➕（仅 admin） |
| `topbar` | 工作区顶栏 | shell 面包屑/主题 + admin 管理入口 |
| `tree` | 工作区左侧 | privhub-files 目录树 / privhub-trash 回收站入口 |
| `panel` | 工作区中间 | privhub-files 文件面板 |
| `preview` | 工作区右侧可伸缩条 | privhub-files 预览 + shell 设置 |

### 3.3 Client 加载机制（轻量，自研约定）

- 沿用全局 Vue（`vue.global.prod.js`）+ 浏览器原生 `import()` 动态加载。
- 每个插件 `client/index.js` 是独立 ESM 文件，导出 `{ slot, component }`；骨架启动时调用 `server` 的 manifest 聚合接口，按 slot 逐个 `import()` 并注册。
- 插件可独立装卸：manifest 缺一则对应 slot 不渲染。
- 组件内统一通过 `fetch('/privhub/api/<域>/…')` 调用本插件 server 侧接口（路由前缀沿用现有）。

### 3.4 权限规则（维持现状）

- 管理员：项目栏显示全部项目，可 ➕ 新建/删除项目，有「用户管理」入口。
- 普通用户：项目栏只显示有权限的项目，无 ➕ 按钮，无管理入口；无权限项目访问返回 403。

## 5. 施工步骤（一次性全拆，中间态可用）

1. **契约定稿**：slot/manifest/client 加载机制按本文档第 3 节实施。
2. **privhub-shell 骨架**：项目栏（可伸缩、➕ 仅 admin）+ 工作区四区 + auth slot；manifest 聚合接口；骨架页经 dist 接管方式提供（沿用 start.bat 已固化的逻辑）。
3. **迁移 privhub-auth**：登录/注册组件挂 auth slot。
4. **迁移 privhub-admin**：用户管理/项目管理挂 topbar 入口。
5. **迁移 privhub-files**：树 / 面板 / 预览挂工作区三区。
6. **迁移 privhub-trash**：回收站挂树栏底部入口。
7. **收尾**：删除旧 `frontend/index.html`；冒烟回归（现有 5 套 smoke 脚本 + 项目栏新用例）；更新《需求记录》《部署说明》。

> 施工期间旧单页保留在 `frontend/index.html`（或改名 `legacy/`），骨架以占位符先跑通镶嵌机制，每迁完一个插件即可用，随时可回退。

## 6. 验收标准

- [ ] 未登录 → auth slot 渲染登录/注册，登录后进入骨架
- [ ] 项目栏：admin 见全部项目 + ➕ 可建项目；user1 只见「公共/A项目」、无 ➕
- [ ] 点击项目进入工作区：树 / 文件面板 / 预览条 / 顶栏均正常
- [ ] 任意插件 manifest 移除 → 对应栏位不渲染、其余功能不受影响（可插拔验证）
- [ ] 现有 smoke-test / smoke-tree / smoke-sort / smoke-permission / smoke-dblclick 全部通过
