## 1. 密文判定口径

`plugins/privhub-svc-storage/src/index.ts:39` 定义：

```js
const MAGIC = Buffer.from([0x50,0x48,0x45,0x4e,0x43,0x31,0x00,0x01]) // "PHENC1\0\x01"
```

即文件前 8 字节 = ASCII `PHENC1` + `\0` + `\x01`。
本扫描对每个文件 `OpenRead` → 读 8 字节 → 逐字节比对；不足 8 字节判为明文。

## 8. 与改造方案的直接关联（供方案评估引用）

1. **799/800 密文** → nginx 直读明文池必须配一次全量解密迁移，或改成「写时明文、读时按需从旧格式升格」。
2. **`.trash` 占 76.75%** → 索引/迁移范围必须显式区分活文件与回收站。
3. **1 个存量明文文件** → 直读路径会「部分成功」，需要一个统一判定，不能假设全库同质。
4. **中文/长目录名普遍存在**（`AI小说研究`、`谢雨-容器`、`能启动清单与统一入口-v0.3.md`）
   → 扁平 `file_id` 化之后，这些名字只留在索引里、不进 URL，正好是方案的目标形态。
5. **空项目目录 5 个**（其中 `memory-tap-mcp` 等是真实项目目录）→ 索引表不能只按「磁盘上有目录」
   来建，否则空项目会消失。
