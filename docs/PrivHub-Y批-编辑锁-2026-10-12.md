## 一句话

在线编辑是「读 → 改 → 写」的长事务，两个用户同时进来会互相覆盖。既有的
`baseMtime` 409 是**乐观**检测（保存那一刻才发现冲突）；本批加了**悲观**锁 ——
第二个用户一申请就被拦下并收到「文件正被 X 修改，请稍后重试」
（就是你提的那个 C++ 双线程 mutex 类比）。

## 设计（已按你的两个选择落地）

- 顺序：**锁独立成批，先做**（X1 引用稳定批押后）。
- 范围：**内容 + 名字级操作全锁** —— 不只编辑器里的正文，重命名 / 移动 / 删除
  这类「名字级」操作也一并纳入。

### 锁的两种形态

| 形态 | 谁持有 | 时长 | 用途 |
|---|---|---|---|
| `content` 长锁 | 编辑器（前端申请） | 默认 10 分钟，保存/心跳续期 | 打开文件即申请；别人改不动、删不掉、改不了名 |
| `name` 短锁 | 服务端（重命名/移动/删除内部） | 仅覆盖一次 fs 操作（毫秒级） | 名字级操作期间不可被并发抢；也反向拦住在编辑该文件的人 |

### 冲突判定：路径前缀（分隔符感知）

`a/b.md` 与 `a/b.md.txt` **不**冲突；锁住目录 `a` 与锁住 `a/b.md` **冲突**；
锁住文件 `x/sub/a.md` 时，改名它的父目录 `x/sub` 会被拦（前缀命中）。
项目根（`''`）视为锁全项目。

### 与既有机制的关系

- `baseMtime` 409 **保留**，作为最后防线（脚本 / Agent / 模板等不走锁的写入仍靠它兜）。
- 写前校验只在「他人持锁」时拒绝；**自己持锁**不拦自己的保存。
- 锁是**尽力而为**的前端协调：申请失败/网络异常不阻断打开文件。

### 权限

申请 / 续期 / 释放要求该文件「可编辑」（`ctx.acl.can(u,'edit',project,path)`，
未命中规则即放行 + `canAccess` 项目可访问）。释放默认仅持有人，`admin` 可 `force` 强解。

### 边界（写清楚，避免误解）

- **进程内内存表**：PrivHub 单进程部署下即全局唯一。将来若多实例共享同一
  `data-files/`，本锁失效，需换落盘 / Redis。
- 本批**没有**把锁做成「写盘必须先持锁」的硬门槛（除了 office2 原有语义）：
  模板 / Wiki / 脚本仍可直接写，只要没人持锁。这样不破坏既有自动化。

## 未动项 / 已知取舍

- office2 前端仍打旧路由 `/api/office2/lock`（后端已转发到 `ctx.lock`，行为不变）。
  后续可让前端直接改用 `/api/lock`，本批不做以免动到 office2 的稳定链路。
- `/api/lock*` **没有**登记进 `privhub-admin-acl` 的 `GUARD_PATHS`，权限在路由内显式校验：
  DELETE 走 query 传参、且释放要区分「持有人 / admin 强解」，这两点 guard 都不表达。
- `tests/personal-ui.mjs` 的 K 沙箱没有 `setInterval`：前端定时器一律先做存在性判断
  （退化成无心跳 / 无轮询，不抛错）。这是本批踩到并修掉的一处「沙箱里炸主路径」。
- 锁只覆盖「编辑器打开的文件」；批量上传 / 覆盖式上传未纳入（无「正在编辑」语义可依据）。

### 过程中的两次 in-batch 抖动（均判为既有测试的时序问题，非本批引起）

1. `acl-file-filter` 的「near 近似摄取」超时（2/3 命中，20413ms）。
   **独立单跑 183ms 9/0、复跑全量亦 9/0**，判定为摄取时序抖动
   （与 W-D 记过的 rag-resilience 同类）。
2. `dup-verdict §3.2-A2`「内容一致 → verdict=same」某轮返回 `differ`（9ms），
   其余轮次全绿。**独立单跑 3× 全绿；专门写了压测脚本复现（见下）未复现。**
   - 压测：造 80 个填充文件压住 RAG 摄入队列，再上传一对同内容 `.txt`，
     轮询 `/api/rag/dup` 25 次 → **25/25 判 same**；去掉填充、250ms 快轮询 40 次
     → **40/40 判 same**（内容指纹 `19c8912c5d`，走文本分支）。
   - 机理假设（未定论）：`fingerprintOf` 对「已摄入」文档用库内 `dupHash`、
     对「尚未摄入」文档用即时 `sha256(normalizeText(text))`；若一族里一部分已摄入、
     另一部分未摄入，理论上二者可能不同源。压测脚本里出现过一次首轮 `raw:` 指纹
     （`.txt` 走了二进制/原文分支）随即转文本分支，但**未造成 differ**，
     该现象本身也未能稳定复现。
   - **未改 `svc-rag` 任何代码**（该逻辑属 W-D 范围，且不在本批授权内）。
