### 2.3 外部集成方真实联调反馈（2026-09-21 线上站点探查）

> 来源：《[PrivHub-外部探查报告-2026-09-21.md](PrivHub-外部探查报告-2026-09-21.md)》——外部集成方对线上实例 `192.168.20.11:3180` 的只读 curl 探查。
> 报告原文（含其推断与误判）逐字归档，本项目侧的代码核对结论写在该报告顶部的归档批注里。

| # | 优先级 | 问题（已按代码核对重新定性） | 证据 |
|---|---|---|---|
| **JT-19** | P1 | **智能体接入方式在匿名面不可发现**：外部集成方拿到当月有效密钥（`pha_` 前缀）却联不通——尝试 Bearer、key 换 token、猜 `/ai/*` 路径全部失败，得出"AI 链接是断的"结论。**代码侧实测：通道完备**（`X-Agent-Key` 头 + `/privhub/api/agent/v1/*` 20 条路由 + 自描述 `/schema`），**缺的是发现路径**：头字段与端点前缀在未登录面零提示，说明只在登录后的「🔌 智能体接入」面板与仓库文档里（鸡生蛋困境） | `privhub-files-agent/src/index.ts:200-201`（仅认 x-agent-key，401 带 AGENT-4010 中文 hint）、`:398-415`（/schema 也要会话或密钥） |
| **JT-20** | P2（先复核） | **疑似非浏览器客户端 GET 静态资源返回 0 字节**：探查方实测根 HTML 正常（63829 字节），但 `/vue.global.prod.js`、`/privhub-plugins/*/index.js` 等 GET 返回 200 空体（HEAD 却有 content-length）。可能是对方沙箱 curl 怪异，也可能服务端对无浏览器头的请求响应异常——**需在真实浏览器与多种客户端复核**；若属实会影响自动化客户端 | 探查报告三-4；本轮未复现 |
| **JT-21** | P2 | **前端无连通性自愈提示**：401 或"无法连接服务器"时不提示"服务器地址可能已变更/网络不通"；登录页不显示当前基地址。背景：使用方经历过旧 IP（192.168.10.55）弃用、外部工作流仍引用死链的事故（旧地址排查属外部仓库事项，非本仓库代码） | 探查报告五-4；与 JT-09（界面显示版本号）可同批做登录页信息补强 |
| **GC-15** | P2 | 插件子资源仅 Cookie 鉴权、缺失即白屏（详见 C 组） | 探查报告三-3 |

**JT-19 建议改法**（不需做报告建议的"key 换 token"——那会破坏人/智能体双通道分离的既有安全设计）：
① 未登录面提供最小可发现信息——`/schema` 的 401 响应已带 hint，可再在登录页/公开 manifest 里放一句"智能体接入请使用 X-Agent-Key 头，详见登录后面板"；
② 「🔌 智能体接入」面板直接给出可复制的 curl 示例（头字段 + `/agent/v1/me` 自检命令）；
③ 仓库 README 补一句接入指引链接到《PrivHub-AgentAPI-接入指南.md》。
