# 改动方案 v5：读写分离 + 前后端分离

> 2026-11-12 · 分支 `feat/storage-tiering`（从 `main@2ae08c6` 开出） · **代码零改动**
> 本版按用户第十轮定的两个目标重构方案：**① 读写分离 ② 前后端分离，二者之间用 nginx 链接**。
> v4 的功能清单不作主干，只作实现细节参考（见附录 A）。

---

## 0. 先把两个目标翻译成架构

| 目标 | 翻译成什么 |
|---|---|
| **读写分离** | **读**（看文件、预览、播放、下载）与**写**（上传、改写、删除、改名、移动）走**两条独立路径、两套进程**。读路径不进 Node 业务链、不碰插件、不发事件；写路径保持现状（事件/审计/锁/版本一个不少）。 |
| **前后端分离** | **nginx 是唯一边界**。前端（浏览器 SPA）只与 nginx 对话；后端（Node）躲在 nginx 后面。前端不知道后端有几个进程、插件怎么分层、文件在哪个盘；后端不知道请求从哪个页面来。 |
| **二者用 nginx 链接** | nginx 同时承担两个角色：**静态/内容服务**（替后端发字节）+ **API 反向代理**（转给后端）。 |

**由此推出最重要的一条设计约束**：

> **前端拿到的 URL 里不能有"后端语义"** —— 不能有物理路径、不能有插件路由、不能有项目真实姓名拼成的路径。否则前端就被后端绑死了，谈不上分离。
> 所以：**URL 只放不透明文件 ID**。

---

## 1. 关键发现：扁平化 + 不透明 ID，让 nginx 直读从"很难"变成"很自然"

前几轮我一直在纠结 nginx 直读的安全问题（穿越、中文名编码、个人空间越权），并因此设计了 `X-Accel-Redirect` 那套绕法。**你把存储扁平化之后，这个问题自己消失了**：

| 用分层路径直读（v3/v4 方案 A） | 用扁平 ID 直读（本版） |
|---|---|
| URL 含 `项目名/子目录/文件名.md` → 中文、空格、`#`、`?`、`%`、反斜杠全要处理 | URL 只有 `/f/<32位十六进制>.md` → **无编码问题** |
| nginx `alias` 拼接用户可控路径 → `%2e%2e%5c`、junction 逃逸要逐个挡 | 路径是**服务端生成的不透明 ID**，用户拼不出穿越 |
| 需要 `X-Accel-Redirect`（Node 解密/判权后交内部 location）才安全 | **`alias` + `auth_request` 直接可用**，少一层 |
| 文件改名后 URL 失效 | **改名不改 ID，URL 永久有效** |

**结论：方案从 v4 的「A（X-Accel-Redirect）」简化为「B（alias + auth_request）」，而且 B 在这里是安全的。**

## 2. 目标架构

```
                       ┌──────────────── 浏览器（前端 SPA）────────────────┐
                       │ 页面/JS/CSS ← nginx 静态                            │
                       │ 列表渲染   ← 主索引（JSON，不带物理路径）            │
                       │ 看/听/看大图 ← GET /f/<id>                          │
                       │ 上传/改写/删除/改名 ← POST /privhub/api/*           │
                       └───────────────────┬───────────────────────────────┘
                                           │  唯一边界 = nginx（对外 3181）
        ┌──────────────────────────────────┴──────────────────────────────────┐
        │                              nginx                                   │
        │                                                                      │
        │  【读路径】location /f/<id>                                          │
        │      auth_request → /__privhub_file_auth  (判权，一次轻量子请求)      │
        │      alias {{DATA_FILES_POOL}}/<id><ext>                             │
        │      sendfile ────────────────────────► 磁盘（扁平池，明文）          │
        │                                                                      │
        │  【写路径】location /privhub/api/  →  proxy_pass → Node               │
        │  【前端】location /index.html、/privhub-plugins/  →  静态直出          │
        └──────────────────────────────────┬───────────────────────────────────┘
                                           │
                                   ┌───────┴────────┐
                                   │  Node 后端      │
                                   │  主索引（加密JSON）│
                                   │  写链路全保留    │
                                   │  鉴权端点        │
                                   └───────┬────────┘
                                           │
                         ┌─────────────────┴──────────────────┐
                         │ 磁盘                                               │
                         │  .pool/<id><ext>   ← 扁平、明文、nginx 直发          │
                         │  data/（系统 JSON、审计块）← 仍加密                   │
                         └────────────────────────────────────────────────────┘
```

**读路径上 Node 只出现一次**：`auth_request` 那次判权（几十毫秒的内存查表）。字节一个都不经过 Node。

## 3. 读写分离：两条路径的职责边界

| | **读路径** | **写路径** |
|---|---|---|
| 入口 | `GET /f/<id>` | `POST /privhub/api/*` |
| 谁发字节 | **nginx `sendfile`** | Node |
| Node 做什么 | 只判权（一次内存查表：id → 索引行 → `canAccess` + `acl.can` + 个人空间） | 全部业务：解密/加密、事件、审计、锁、版本、查重、索引维护 |
| 是否发事件 | ❌ 不发（纯读） | ✅ `file:changed` / `file:saved` / `audit:logged` 全保留 |
| 是否可缓存 | ✅ nginx `ETag`/`Last-Modified` + 浏览器缓存 | ❌ |
| 是否受 409 版本门 | ❌ 不受（GET，且在 `/privhub/api/` 前缀外） | ✅ 受（旧页面写请求被拦） |
| 故障影响 | nginx 挂了才不可读 | Node 挂了不可写（读仍可用，这是分离的好处） |

**分离带来的实际收益**：
- 大文件/视频播放不吃 Node 内存与事件循环 → **列表和写操作不再被下载拖慢**；
- 读可被 nginx 缓存、可开 `sendfile`/`tcp_nopush`（模板已开，`nginx.conf.template:24-26`）；
- Node 重启/蓝绿切换时，**已缓存的静态内容仍可读**（切换窗口的体验改善）。

## 4. 前后端分离：nginx 作为契约边界

| 契约 | 内容 | 为什么这样定 |
|---|---|---|
| 前端只认三种 URL | ① 静态资源 `/index.html`、`/privhub-plugins/…` ② 内容 `/f/<id>` ③ API `/privhub/api/…` | 前端不需要知道后端插件分层 |
| `/f/<id>` 只含不透明 ID | 不含项目名、不含虚拟路径、不含扩展名之外的信息 | 不泄漏目录结构；改名/移动不换 URL |
| 列表接口返回"渲染所需最小集" | `{id, name, ext, size, mtime, isDir, virtualPath}`，**不含物理路径** | 前端纯展示；物理位置是后端内部事 |
| 物理路径永不出现在任何响应里 | 主索引里的 `physical_id` 不下发 | 与 D9 教训同源：路径信息是最该藏的东西 |

**这样"分离"才成立**：换后端实现（插件合并、换存储布局、换数据库）时，前端契约不变。

## 5. 存储：扁平池 + 主索引（服务端）

### 5.1 扁平池的物理布局

```
data-files/
  .pool/
    ab/abcd1234...ef.md        ← 按 ID 前两位分片（见下）
    7f/7f3a9c21...8b.pdf
```

**为什么按前两位分片**（重要实践细节）：Windows/NTFS 单目录文件数过多时目录遍历与创建会明显变慢。逻辑上仍是**扁平**（用户看不到任何子目录），物理上按 ID 前 2 位分 256 桶，10 万文件时每桶约 400 个，性能稳定。URL 仍是 `/f/<id>`，nginx `alias` 用两位前缀拼即可：
```nginx
location ~ ^/f/([0-9a-f]{2})([0-9a-f]+)(\.[a-z0-9]+)?$ {
    auth_request /__privhub_file_auth;
    alias {{DATA_FILES_POOL}}/$1/$1$2$3;   /* 注意：$1 前缀拼两次 */
}
```

### 5.2 主索引

- 存**加密 JSON**，走 `ctx.storage`（与 `meta.json`/`links.json`/`dup-index.json` 同规格）→ **不重犯 D9**（明文 SQLite 打开就能读出全部目录结构，`vec.ts:16-26`）。
- 字段：`id, project, virtual_path, name, ext, size, mtime, is_dir, physical_id, aliases[]`
- 派生数据：**可全量重建、宽容读取、有上限**（抄 `svc-links:19-20,25-26`）。
- 维护双保险：`file:changed`/`file:saved` 增量 + 启动/定期全量对账（`fulltext:83-87` 范式）。

### 5.3 虚拟目录 ≠ 物理目录

| 用户操作 | 主索引动作 | 物理动作 |
|---|---|---|
| 看到目录树 | 按 `parent_virtual_path` 查表 | 无 |
| 新建文件夹 | 插一条 `is_dir=true` 的行 | **无** |
| 移动文件 | 改 `virtual_path` | **无** |
| **改名** | 改 `name` + 写 `aliases` | **无**（ID 不变，URL 不变） |
| 上传 | 新增行 + 新 ID | 写入 `.pool/` |
| 删除 | 标记/移除行 | 移到回收站或删 |

**这就是"扁平化"与"不丢功能"两全的关键**：磁盘上没有层次，用户体验上有层次。

- 1.3 `mkdir` / `move` / `rename` 改为**只操作索引**（不碰磁盘）。保留 `withNameLock`（`files:800-801`）。

### 阶段 2 · 老库迁移（**按你的方案重构：扫描建索引 → 空闲慢搬，不回写源文件**）

> 你定的做法消掉了原「一次性原地迁移」的不可逆风险，这是本版最大的改进：
> **源库只读、不删不改**；新库先建索引，字节慢慢搬；中途断电/停机不丢数据。

**场景**：老库在 `E:\old-privhub`，新装 PrivHub 的 `dataFilesDir` 设为 `F:\new-privhub`。

- 2.1 **配置新库位置**（管理台设置 `dataFilesDir = F:\...`，需重启生效，明示）。
- 2.2 **添加老库迁移任务**：管理台填「老库位置 = `E:\old-privhub`」，可选只读挂载校验（确认可读、是 PrivHub 库结构）。
- 2.3 **第一遍：只读扫描 → 建索引（快，不搬字节）**
  - 遍历老库 `**`：对每个文件记录 `虚拟路径（原层级）、文件名、后缀、大小、mtime、sha256（可选，流式算）`；
  - **不解密就不碰内容**：若老库是 PHENC1 密文，此遍只记录「encrypted=true + 原物理路径」，内容解密留到搬运时做；
  - 写入主索引，`physical_id` 暂指向「老库路径」（`source=legacy`）；
  - 这一遍**只读**，可中断、可重跑（幂等：同虚拟路径覆盖同一行）。
- 2.4 **第二遍：空闲慢速搬运（可中断、可续传）**
  - 逐文件：读老库 → 若密文则解密 → 写新库 `.pool/<id><ext>`（明文）→ **回读校验** → 更新索引 `physical_id` 指向新位置、`source=new`；
  - **不删除老库源文件**（你明确要求）；全部完成并校验通过后，由管理员**手动**决定是否归档/删除老库；
  - 搬运中每次写完先写「完成标记」再更新索引，**断电后重跑只需删掉半截 `.pool` 临时文件重搬**（用 `tmp + rename` 原子写，`svc-storage:484-496` 范式）；
  - 节流：可配置并发/带宽/时段，包在 `ctx.privhub.onActivate()` 里（standby 槽不跑），单实例租约防双槽重复搬。
- 2.5 **查重合并（可选、在搬运时顺手做）**：同项目 `exact`（同 sha256）只留一份物理字节、多行指向同 `physical_id`（引用计数）；`near` 只记录不合并。
- 2.6 **只取消用户文件库加密**（按 `PRIVHUB_DATA_FILES` 前缀跳过，不改加解密实现）；系统 JSON 与 PHAUD1 审计块保持加密。
- 2.7 **`secret.key` 保留**：只要老库还有密文没搬完，就必须保留（`storeCheck`/`verify-store` 会抽样解密，`core:584-602`，提前删会让蓝绿切换前硬失败）。
- 2.8 管理端 UI：迁移任务卡片（老库路径、扫描进度、已建索引数、已搬字节/总数、失败清单、暂停/继续/取消），`<ph-help>` 一句悬停说明。
- 验收：
  - 扫描阶段：索引行数 = 老库文件数（跳过审计块/日志/git-backup，`svc-storage:684-707` 守卫）；
  - 搬运阶段：抽查 N 个文件，新库字节与老库解密后逐字节一致；**中途 kill 进程后重启能续传，不重复搬已完成项、不留坏文件**；
  - 老库源文件**数量与 mtime 不变**（证明只读）。

### 阶段 3 · nginx 读路径（2~3 天）

> **⚠ 实现完成后追加：本节初稿的方案已被真实 nginx 实测推翻，以下是最终形态。**
>
> **五处偏差（全部实测，nginx 1.28.3）**
> 1. **不用 `auth_request` 透传 `X-Accel-Redirect`** —— 子请求里的 accel 头不会被主响应消费（调试头证明它到了，主响应仍 404）。改为：**主请求 `proxy_pass` 到 Node，Node 判权后自己返回 `X-Accel-Redirect`**。
> 2. **`alias` 只能用字面前缀，不能用变量**：`alias $var` 不解码 `%XX`（`CreateFile ".../C%3A%2F..."` → 404），而 Node 响应头必须编码中文（非 ASCII 会让 `setHeader` 抛 `ERR_INVALID_CHAR` → 500）。`X-Accel-Redirect` 被当 URI 处理会正确 percent-decode，中文才通。
> 3. **URL 必须带扩展名**：走 accel 后 nginx **按 URL 扩展名重算 `Content-Type`，忽略上游**。裸 `/f/<id>` 退化成 `application/octet-stream`（图片不显示、视频不播放、SVG 严格 CSP 挂不上）。**且只在明文提速开启后出现**，默认降级路径测不出来 —— 前端已改为拼 `/f/<id>.<ext>`。
> 4. **安全头必须只写在 internal location**：accel 后只有白名单头保留（`Content-Type`/`Cache-Control`/`Set-Cookie`/`Content-Disposition`/`Accept-Ranges`），`X-Content-Type-Options`/`Referrer-Policy` 全丢。
> 5. **`if` 不能包 `alias`**：`if` 在 rewrite 阶段执行，那时子请求还没回来，`$upstream_http_*` 是空的。
>
> **三个集成期才发现的问题（已修）**
> - `/api/list` 与 `allProjects()` 原来靠扫磁盘判「项目是否存在」，扁平化后磁盘没有项目目录 → 所有项目 404、列表打不开。改为「**磁盘 ∪ 索引**」并集。
> - `withinNativeRoot` 判 legacy 越界时用当前 `dataFiles` 折基准，**跨盘迁移（E→F）全部误判 404**。改为优先用条目自己的 `legacyRoot`。
> - `listFiles` 索引分支投影时丢了 `id` 字段 → 前端拿不到 id 就走不了直读（静默全部回退）。

- 3.1 **读路径端点** `GET /privhub/api/file?id=<id>`（`/file-auth` 保留为别名）：`requireUser` → 索引查行 → `canAccess` → **显式 `acl.can(u,'view',…)`** → **显式个人空间归属判断** → **物理路径自证** → 分两路收尾：
  - **明文** → `X-Accel-Redirect: /__privhub_internal/<相对库根路径>`（逐段 encode）→ nginx sendfile
  - **密文 / legacy 未迁移** → Node `createReadStream` 解密流式发送（支持 Range 206）
  - **不问配置、只看这次请求的真实磁盘状态** → 开关开不开、老库迁没迁都不用部署协调
- 3.2 nginx 模板（读路径放 `/privhub/api/` 前缀外，自动避开 409 门）：
  ```nginx
  location ~ ^/f/(?<fid>[A-Za-z0-9_-]+)(\.[^/]*)?$ {
      proxy_pass http://privhub_active/privhub/api/file?id=$fid$is_args$args;
      proxy_set_header Cookie $http_cookie; proxy_set_header Authorization $http_authorization;
      proxy_set_header Range $http_range; proxy_set_header If-Range $http_if_range;
      proxy_buffering off; proxy_request_buffering off;
      proxy_hide_header cache-control;
  }
  location /__privhub_internal/ { internal; alias "{{DATA_FILES_DIR}}/";
      add_header Content-Security-Policy $privhub_svg_csp always; ... }   # map $uri 取 SVG 值
  ```
- 3.3 响应头：`nosniff`、`no-store`、`Referrer-Policy` **只写 internal location**；SVG 用 `map $uri` 动态 CSP（非 SVG 空值不产生头）；`types{}` 只补 mime.types 真缺的 6 项（qt/mkv/3g2/oga/opus/ogv），重复项会触发 duplicate extension 警告。
- 3.4 `{{DATA_FILES_DIR}}` 占位符走 `computeDataFiles()`（**不能用常量**——库根会被 adopt-legacy 改写）；`configPathValue()` **拒绝** `$`/`%`（nginx 无安全转义手段）。
- 3.5 **统一 URL 工厂**：`utils.js` 一处决策（`contentUrlFor`/`contentUrls`），骨架 `index.html` 与 `office2/view.js` 是逐字镜像；调用方全覆盖（content.js 6 处、panel.js、detail.js、tabs.js、treecache.js）。
- 3.6 回归：未登录 401 / 越权 403 / 个人空间非归属者 403（含管理员）/ 越界路径 404 / SVG CSP / Range 206 / 不存在的 id 404 / 中文+空格文件名 / `.tar.gz` 双扩展名 / internal 直连 404。

### 阶段 4 · 写路径与上传（2~3 天）
- 4.1 所有写路由**不变**（用户已拍板写走正常流程）：`upload / upload/* / text/save / doc / delete / rename / move` 继续走插件，事件全保。
- 4.2 **上传重名：先查库再问人**（按你定的）。`init` 阶段先查主索引同项目同名：
  - 命中 → 返回给前端，**让用户选「改名」还是「覆盖」**，并把风险写清楚（对话框文案见下）；

## 8. 一个可选的进阶（先不做，留位）

**`secure_link` 签名 URL**：由 Node 在列表接口里直接签发带过期时间的签名 URL，nginx 用 `secure_link` 校验，**读路径完全不需要回 Node**（连那次 `auth_request` 都省了）。

- 优点：读路径零后端参与，真正的"纯 nginx"。
- 代价：权限撤销后签名 URL 在 TTL 内仍有效（需短 TTL，如 5 分钟）；多一份密钥管理。
- 建议：**首期用 `auth_request`（始终准确）**，等确认读压力大再上签名。
