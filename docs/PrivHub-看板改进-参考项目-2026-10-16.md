### 一句话定位

**「看板 + 真的会干活」**：卡片点「执行」会拉起一个 DSH 会话真跑任务、跑完把状态写回卡片；
再叠上**定时 / 跑完接着跑 / 自动巡航**三种自动化，以及一套完整的**清单 + 复核 + 通知中心**。
数据存在宿主一侧，**电脑和手机看同一块板**（SSE 实时同步，断网也能用）。

> ⚠️ **关键判断**：它的「执行是真的」**依赖 DSH 引擎**（session controller / agent / llm）——
> 正是 PrivHub 已 vendored 但**尚未挂载**的那一层（`references/engine/`，即 V4 的范围）。
> 所以它对本项目的价值是**两条腿**：
> ① **纯 UX / 数据模型 / 自动化**那一半——**不依赖引擎**，现在就能借鉴；
> ② **真执行 + 多设备同步**那一半——**依赖引擎**，属 V4 线，先记不做。

### 架构（三段，值得抄的是**分层方式**）

```
src/core/*   纯逻辑（无框架、无 cordis）：board-doc / tasks / item / task-transitions /
             execution / automation / cruise / scheduler / schedule / presets / store …
src/host/*   服务端：board-route（宿主真相 + 租约 + 命令转发）/ board-service / agent/tools
             / session-state-route / permission-route / attachment-route / update-route
src/client/* 浏览器：React 面板 + 组件（board/ 40+ 文件、item/ 30+ 文件、design/ 设计系统）
```

三条**与我们架构直接相关**的设计：

1. **宿主 = 唯一真相，浏览器 = 乐观副本；一套合并语法让并发编辑确定收敛**
   （`core/board-doc.ts`）。每行按其 `updatedAt` LWW；删除带墓碑（tombstone 时间戳 = 见过的最新
   `updatedAt` + 1ms，故删除永远压过陈旧的副本）；**冲突按「作者身份」而非时钟裁决**——提交声明
   `changed`（本次自己动过的 id）宿主无条件接受，未声明的按 LWW。`revision` 是单调变更计数，
   只做「SSE 重同步信号」与「是否真变了」的判据，**不做写闸门**。
2. **「有意义的转移」只实现一次，界面与模型都必须走它**（`core/task-transitions.ts`）：
   把卡移到「已完成」不只是写 `status`，还要**解除定时、关掉所有会话规则**——若界面做了、模型只写
   `status`，同一意图会得出两个结果。纯函数：**无 `Date.now()`、拒绝是「值」不是抛错**
   （`{ ok:false, why }`，`why` 是模型能据此纠正的一句话）；**空操作返回同一个对象**（避免无谓的同步风暴）。
3. **开关 = 「一个事实」而不是「一个功能」**（`host/surfaces.ts`、`host-board.ts`）：
   一个包只能有一份浏览器产物，于是**每个界面开关对应一个「宿主侧小模块」，模块体里声明「我开着」**；
   关掉开关 = 装载器**根本不求值**那个模块（不是运行时判断），所以「忘了判断」不可能发生——
   这正对应我们 `svc-cap` 的开关体系，但**做到了「关闭即不存在」**这一更强的诚实性。

### 能力清单（按我们**是否已有**标注）

| 能力 | 要点 | PrivHub 现状 |
|---|---|---|
| **真执行 + 状态回写** | 点「执行」→ 拉起会话真跑 → 跑完自动落「待审核」；卡片显示跑过几次、上次成没成 | ❌ 无（需引擎/runner） |
| **复核页** | 一次执行的**完整记录**（transcript），可就地「通过 / 打回」 | ⚠️ 有审核流，无 transcript |
| **卡片评论区 = 该卡的会话** | 排队发 / 插话发；图片文件可直接拖入 | ⚠️ 有 `files-comments`，未与会话绑定 |
| **任务清单（清单 = 第二份文档）** | 与看板是**兄弟文档**不是视图；`taskId` 单向只读引用卡片；步骤一层（不可嵌套）；`ref` 短号 `#12` | ❌ 无 |
| **定时 / 跑完接着跑 / 自动巡航** | 5 字段 cron、`禁止重叠`（Forbid）、错过跳过不补跑、巡航窗口（跨午夜自动 +24h 归一）、按分钟心跳 | ❌ 无（**纯逻辑，最易移植**） |
| **通知中心 + 动态页** | 「等你处理的事」聚合；动态按日分组 | ❌ 无 |
| **三个独立日期** | 开始 / 计划 / 截止，各有语义（早于不动 / 想做完 / 不能顺延）；只有错过截止变红 | ⚠️ 只有 `dueDate` |
| **自然语言日期** | `@明天` / `10月15日` / `2026-10-15` / `+3` / `周三` 都认；**三种读不懂各说各话**（写法不认识 / 缺年份已过 / 日历上没这天） | ❌ 无 |
| **模板 + 运行配置预设** | 详情可存模板；运行配置（工作区/Agent/模型/思考程度/权限）存预设、设默认 | ❌ 无 |
| **多面筛选 + 计数** | 日历 / 日期桶 / 久未动 / 优先级 / 状态 / 日程 / 已删除，**每项带数字，0 也写** | ⚠️ 筛选弱 |
| **键盘操作** | `A` 建 / `J`·`K` 移 / `X` 多选 / `1`–`4` 优先级 / `E` 改名 / `⌘Z` 撤销 / `Esc` 逐层收 | ❌ 无 |
| **删除可撤销 + 30 天回收** | 撤销栈；左栏「已删除」可找回 / 彻底删 | ⚠️ 有回收站插件 |
| **多选批量操作** | 改状态 / 优先级 / 排今天 / 问 AI / 删除一次做完 | ❌ 无 |
| **多设备同步** | 宿主文档 + **引擎租约**（同一时刻只一台浏览器跑定时/调度）+ 命令转发；SSE；窄屏紧凑布局 | ❌ 无（需引擎/SSE） |
| **设计系统** | `tokens.module.css` / Chip / Dialog / Field；**窄屏列变横向滑动**；FLIP 动画；拖拽自动滚动 + 落点计算 | ⚠️ 有主题变量 |
| **更新检查 + 一键更新** | 读「正在运行那一份」的安装来源，据此决定怎么更新 | ❌ 无 |
| **AI 接口（3 工具 + 2 斜杠命令 + 1 段系统提示）** | `taskboard_capabilities / _query / _execute`；**目录即唯一权威**（含「谁能做」），短号出入不传 UUID，业务失败**回「该改什么」** | ⚠️ agent 车道有，工具面窄 |

### 借鉴 = 分三档（先做得到、后做够）

**第一档 · 纯 UX/纯逻辑，不碰引擎，本轮可做**
- 多面筛选 + 计数；键盘操作；多选批量；删除撤销
- **三个独立日期**（开始/计划/截止）+ **自然语言日期解析**（含三种错误话术）
- **cron 解析 + 按分钟调度的定时任务**；**「禁止重叠 / 错过跳过」口径**
- **巡航窗口状态机**（手动开关与定时窗口用**一条可解释的规则**组合）
- **清单**（独立文档，`taskId` 只读引用卡片，步骤一层，短号 `#12`）
- 模板 + 运行配置预设
- 通知中心 + 动态（按日分组）
- 「有意义的转移只实现一次」——把「移列」的副作用（解定时 / 关规则）收进**一个共享函数**
- 开关「关闭即不存在」（对 `svc-cap` 的强化）

**第二档 · 需要一个 runner，但可用 PrivHub 自己的模型车道**
- **卡片「执行」真跑 + 状态回写**：用现有 `svc-model` / agent 车道（`ai.write` 那套）当 runner，
  不必先挂 DSH 引擎
- **复核页（执行 transcript）**；**卡片评论区绑定对话**

**第三档 · 依赖 DSH 引擎 / SSE，属 V4 线，先记不做**
- 多设备副本同步 + 引擎租约 + 命令转发 + SSE 实时
- 与 DSH 原生 session/agent 的**结构性对接**（原生 plan/goal 状态、命令注册表、附件存储）

### 明确**不**照抄的
- **React 组件**：我们是 Vue 字符串模板（`template:` + 运行时编译），组件不可直接搬；只搬**交互与信息架构**。
- **引擎耦合**：`execution.ts` 整个建立在 `ctx.sessions` / workspaces 之上，脱离引擎无意义。
- **多设备 CRDT 复杂度**：第一档阶段我们单实例、单（或少数）浏览器，**不引入**整套副本合并语法；
  等真有「手机看同板」的需求再上（第三档）。
- **不搬代码结构**：我们坚持「无打包 + `tsx/esm` 直跑 + 插件目录即装卸」；它的 `lib/` 构建产物与
   `tsdown` 打包链与本项目哲学相反。

### 许可与署名（若移植纯逻辑）
MIT 允许借鉴与移植。若**直接移植**其纯逻辑模块（如 `core/schedule.ts` 的 cron 解析），
须在本项目内**保留 MIT 许可与出处署名**；**建议优先「读懂后自研实现」**，与仓库既有风格一致。

## 本批已落地：项目看板 · 智能体名册（2026-10-16）

> 主人需求：「在项目看板里加一个功能——让智能体注册到这个任务下，写明自己擅长和以前干过什么，
> 好让 PM 指派任务。」三个设计口径（经主人拍板）：**①全局一份名册、注册时声明服务范围；
> ②能力来源＝「自述 + 系统实证」；③指派以人为本（看板为主）、AI 可选辅助。**

新插件 **`privhub-roster`**（L3，纯逻辑在 `src/core.ts`，被三处共用）：

- **登录态路由**（`privhub-roster/src/index.ts`）：`GET /privhub/api/roster/schema`（条目契约）、
  `GET /privhub/api/roster[?project=]`（全局 / 按项目视图）、`POST /privhub/api/roster`（人工登记/编辑）、
  `DELETE /privhub/api/roster?id=`。读名册不设功能开关（登录即可看）；写由新开关
  **`roster.write`**（`privhub-svc-cap`，`userDefault: 'write'`，与协作类兄弟项同档）把闸。
- **智能体自注册**（`privhub-files-agent`）：`POST /privhub/api/agent/v1/roster`（`X-Agent-Key`，
  **按密钥幂等**——同一把钥匙重复注册＝更新同一条，不堆记录；同名撞车回 `AGENT-4042`）、
  `GET /privhub/api/agent/v1/roster`（读同侪，按密钥可见项目过滤服务范围）、
  `GET /privhub/api/agent/v1/board`（读「指派给我的卡」+ 整板自动读，供智能体自查待办）。
- **「系统实证」不落盘**：`evidence`＝服务端**从任务看板现算**的该项目战绩（已完成 / 未完 / 总数 / 最近完成），
  与项目看板 tasks 组件读**同一份**板文件（共用 `privhub-task-board/src/core.ts`），因此永不与看板漂移。
- **项目看板第 5 种组件 `agents`**：默认看板新增一区「智能体名册」（默认区数 3 → 4）；
  只读投影「服务本项目」的条目，人可 `roster.write` 时行内登记/编辑/删除。
- **任务看板指派**：负责人输入框挂 `<datalist>`，候选＝本项目的在册智能体（仍可手填用户名）。
- **事件**：新增领域事件 **`roster:changed`**，已同步登记进 `privhub-webhook` 事件目录（含 `LISTEN`）与
  `privhub-core/src/events.ts` 类型契约；`tests/integrity.mjs` 的「事件目录覆盖全部实际 emit」反漂移断言据此通过。
- **测试**：新增 `tests/roster.mjs`（29 断言：契约 / 读写权限 / 重名 / 服务范围越权 / 实证现算 /
  开关生效 / 智能体车道自注册与幂等 / 看板 agents 投影 / `roster:changed` 入目录），已挂进 `tests/run-all.mjs`。
- **口径变更（须主人知悉）**：默认项目看板由 **3 区改 4 区**（新增「智能体名册」），
  `tests/dashboard.mjs` 两条「默认三区」断言相应改为四区 —— 这是**功能需求导致的既有断言变更**，
  非放宽判据。仓库统计口径同步：插件目录 **62 → 63**、后端路由 **150 → 154**、注册路由插件 **38 → 39**。
