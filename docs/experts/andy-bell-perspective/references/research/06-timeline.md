### 2.2 CUBE CSS 的诞生（含方法论的「改名」过程）

这是整条时间线里最需要小心的一段，因为**方法论不是一次成型的**：

1. **约 2019 年之前**：他长期使用并教学 BEM。
2. **2019-09-14 前后 · State of the Browser 2019（伦敦）**：首讲《Keeping it simple with CSS that scales》。**2020-05 的幻灯片版本里已经出现 `Composition Utility Block Exception / CUBE CSS`**（[Notist 幻灯片全文](https://noti.st/hankchizljaw/6KMw7Z/keeping-it-simple-with-css-that-scales)）。但同一场演讲的**书面版（2019-09-18）用的名字是 C-BEUT**（Cascade / Block / Element / Utility / Token），[原文](https://archive.hankchizljaw.com/wrote/keeping-it-simple-with-css-that-scales/)。→ **即：方法论的骨架在 2019 年 9 月已公开，但当时叫 C-BEUT；CUBE 这个名字是后来（最迟 2020-05）才替换上来的。**
3. **2020-05-26**：《CUBE CSS》介绍文章发布，方法论正式定名成文（[piccalil.li/blog/cube-css](https://piccalil.li/blog/cube-css/)）。
4. **2020-06-30**：Smashing Podcast 第 19 期《What Is CUBE CSS?》对外传播（[链接](https://smashingmagazine.com/2020/06/smashing-podcast-episode-19)）。
5. **2020-07-29**：首次以 CUBE CSS 为**演讲标题**——Vienna Calling（线上）（[Piccalilli 归档](https://archive.piccalil.li/talk/cube-vienna)）；同月 Technica11y 也讲。
6. **2023-11**：宣布 cube.fyi 官网改版（[博文](https://bell.bz/2024-the-year-of-css-education/)）。

> 所以「CUBE CSS 首次公开提出的时间与场合」有两个候选答案，取决于问的是**骨架**还是**这个名字**：
> - 骨架首次公开：**2019 年 9 月 14 日前后，State of the Browser 2019（伦敦）**，当时名为 C-BEUT。
> - CUBE 这个名字首次公开：**最晚 2020 年 5 月**（CSS Café 幻灯片／2020-05-26 介绍文），首场以 CUBE 命名的演讲是 **2020-07-29 Vienna Calling**。
> - [推断] 更早的 2019 年下半年可能已在小范围使用 CUBE 一名，但**没有找到 2020-05 之前的公开 CUBE 出处**。

## 三、思想分期（存在明显分期）

### 第 1 期（约 2006–2018）：BEM 时代 + 框架实用主义

- 长期使用并教学 BEM，写文章讲「用 Sass 控制作用域与 BEM 命名」（见其 CSS-Tricks 作者页与 2018 年文章内链）。
- 对框架态度务实而非敌对：2018 年原文说 **"We love Vue here at No Divide"**，并称 React/Vue "excellent for big applications"（[原文](https://archive.hankchizljaw.com/wrote/the-power-of-progressive-enhancement/)）。
- 同期已确立「渐进增强」为核心信条——**这一条三期未变，是他最稳定的立场**。

### 第 2 期（约 2018–2023）：方法论建构 + 「少写 CSS」

- 从 BEM 转向自创方法论：BEM → **C-BEUT**（2019-09 书面版）→ **CUBE CSS**（2020-05 定名）。
- 2019-09 首次公开的立场转向已经很清楚：**反对把 CSS-in-JS / 重框架当默认解**，反对像素级还原设计稿，反对以「scale」为借口过度工程化。
- 同期对具体工具的态度有细微摆动：2018 年他说自己「转向纯 vanilla CSS、不用 Sass」，2019 年的演讲里又回到「Sass 依然值得用，不要因为原生特性就丢掉它」。**这是他明确承认过的自我修正**（原文："Always be open to change"）。
- 2022 年《Be the browser's mentor...》把立场提炼成口号，并在 2023 年把它写进课程原则模块。

### 第 3 期（约 2023 至今）：从 CSS 语法转向「核心技能」+ 鲜明的 AI 反对立场

- **重心迁移**：2023-11 自述要写新课程与新演讲，「核心技能（core skills，他厌恶『软技能』这个叫法）」成为主线。2024-11 的演讲与 2025-11 柏林演讲**全程不写一行 CSS**，讲的是沟通、反馈、规划、时间管理。他本人原话："It's about time I talked about the really important stuff that sits underneath CSS"（[柏林演讲转录](https://beyondtellerrand.com/events/berlin-2025/speakers/andy-bell)）。
- **AI 立场硬化**：2025-08-18 发布三条不可谈判原则（永不发布 AI 生成内容／不推广疑似 AI 内容／客座稿件一经发现即拒）。2026 年进一步给出经济学判断（AI 泡沫将通缩、拒绝 AI 创业公司的品牌项目）与行动建议（「雇主强制用 AI，就组织工会」）——[播客转录](https://beyondtellerrand.com/blog/podcast-andy-bell-005)。
- **对行业的态度**：2025-03 起反复表达「行业标准在持续下滑」「人才正在离场」（[You'll miss the soul when it's gone](https://bell.bz/youll-miss-the-soul-when-its-gone/)）。
- **个人数字化态度**：2026-09 删除算法流内容消费，回到 RSS（[博文](https://bell.bz/removing-algorithmic-feed-slop-from-my-life/)）。

> 一句话概括分期：**「怎么写 CSS」（BEM）→ 「用什么方法论写 CSS」（CUBE）→ 「写 CSS 之前该做什么」（核心技能 + 反 AI）**。渐进增强与无障碍是贯穿三期的常量。
