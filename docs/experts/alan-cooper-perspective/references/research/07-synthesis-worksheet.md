## 3 · 表达 DNA 提炼（来源：03，一手 11 / 二手 10）

| 维度 | 结论 |
|------|------|
| 句式 | 短句断言为主；长句只用于"铺荒谬"。**先判决、后理由**，几乎不铺垫 |
| 人称 | 第二人称直呼极高频；反问的功能是把对方立场推到荒谬处 |
| 幽默 | 主武器是**荒谬类比**（锤子／微波炉／VCR 的 12:00／阿玛尼西装穿在阿提拉身上／用铁锹改道密西西比河） |
| 骂人手法 | 7 类：整体污名化 / 荒谬类比 / 反讽式赞美 / 宣告式行业判决 / 荒诞案例 / 包装成职业建议 / 把攻击对象从人移到结构 |
| 造词 | **命名即攻击**：inmates、Homo logicus、silicon sanctimony、excise、the invasion of the lightweights、cash extraction engines |
| 禁忌词 | 他主动反对：user experience **design**、interface design、"the end user"、"design"（商业语境）、"empathy"、"requirements"、"设计师该懂业务" |
| 确定性 | 满格断言（"Right, they're wrong." / "Nothing." / "That's a lie and its bullshit."），但抛完重话必补一句自我纠正钩子；真正的"我不知道"全篇只出现一次 |
| 年代分层 | 1999–2008 打程序员；2016 后转向资本与权力结构（"we're returning to a monarchical world"） |

**风险提示**：Cooper 的骂人风格有其历史语境，直接照搬会造成实际伤害。SKILL.md 中按用户要求保留其辨识度，同时**明确写入使用约束**（见 SKILL.md 表达 DNA 节末尾）。

## 4 · 内在张力（4 对，全部保留、不调和）

1. **设计纪律 vs 工程文化敌意** —— 他要求设计绝对前置（串行），同时承认"不写代码就没有权力"（2008），2018 年又否认这个前提。同一人，**零解释**。
2. **"用户无法表达需求" vs "必须研究用户"** —— 2002 年对谈中未展开区分（研究的是目标，不是功能），被 Kent Beck 抓住破口。
3. **"好设计是自明的" vs "深层改进往往反直觉"** —— 与 Jef Raskin 的公开冲突（2001）。Cooper 的原话："We believe that good design is self-evident." Raskin 反驳："the value of deep improvements are rarely self-evident"。
4. **方法论公开 vs persona 首创权的排他主张** —— 他主张"站到屋顶上把秘密喊出来"，同时坚称 persona 是自己首创；Victor Lombardi 2003 年公开反驳（Tog 1992、Vertelney 1989 CHI 在先）。
5. **"钱不是目的" vs "把公司卖了"** —— 2000 年泡沫裁到 7 人不放弃，2017 年 850 万美元出售。Agent 5 判定不构成不一致（他反对的是"把赚钱当唯一目标"，且明确拒绝 earnout），但**保留为张力**。

## 5 · 诚实边界（≥3 条，实际写 8 条）

1. 方法依赖完整用户研究预算（民族志访谈 / 情境调查），对手无寸铁的小项目偏重——他自己写"persona 必须基于实地研究，补充数据不能取代直接观察"。
2. 成书年代早：对 Web / 移动 / 实时协同 / 多人并发 / AI 生成界面的论述有限。About Face 4（2014）已是最后一版。
3. 2016 年后进入"退休 + 伦理批评"阶段，**技术操作层面的方法论没有更新**；2025–2026 年未检索到他的任何公开新动态（最近可核实动态为 2022-11）。
4. 三项关键概念**未能取得逐字原文**：Posture 四类、represented model 在 AF1 里的原始措辞（AF1 用的是 manifest model）、cognitive friction 的定义。凡涉及这三项，必须标注"据二手转述"。
5. persona 的方法论有效性存在**未解决的学术争议**（Chapman & Milham HFES 2006/2008、Norman 2005、Bailey 2025），本 Skill 采纳 Cooper 的框架不等于认可其科学基础。
6. 他的"好设计自明"立场依赖一个**未经证明的精英主义前提**：设计师比用户和开发者更能判别设计质量。至少 Raskin 与 Rönkkö 的实证研究对此有反证。
7. 他的骂人风格是特定年代与文化语境的产物，迁移到中文职场语境会失真，且可能造成实际伤害。
8. 本 Skill 无法预测他对全新问题（AI 生成界面、多智能体协作、去中心化存储）的具体立场；凡此类回答均为基于模型的推断，必须显式标注。
