## 1. 一句话判断

**这个界面不是"用了设计系统但没用好"，是根本没有令牌层——而它同时又在"变量改一次、32 个插件跟着变"这件事上握着最高的杠杆；所以我们先做那三件"改一处、全站受益、零插件风险"的事（`--muted`/`--accent` 对比度、`--line` 可见度、24 处 accent 色罩收敛），间距与字号刻度放在第二步，`z-index` 与阴影放最后。**

一句话再压缩：**先把 9 个颜色变量用对，再谈 45 个 px 值收不收。**

- **骨架 `index.html`：`rgba(90,130,200,α)` 11 处 / 10 行**，用了 **9 种不同 α**（.08/.1/.1/.12/.14/.15/.15/.16/.25/.25/.55）：

**这是我这次体检里最有行动价值的发现**：骨架那个 `<style>` **事实上已经是一个被 20 多个插件共用的组件库**，只是没人这么叫它。它的后果是双向的：

- ✅ **好处（杠杆）**：改骨架里 `.btn-primary` 一处，20 多个插件的按钮同时变——**不用碰任何插件文件**。
- ❌ **代价（风险）**：改**类名**（不是改值）会让插件静默失效，不报错、只是不工作。

**具体的静默失效风险点**（我亲自核到的）：

| 依赖方 | 依赖 | 证据 |
|---|---|---|
| `files-office2` | `.v3-content` + 写 CSS 覆盖它 | `client/index.js:41`、`:50-51`、`:20-21` |
| `files-edit-md` | `document.querySelector('.v3-content')` + `teleport to=".v3-content"` | `client/index.js:220`、`:270`、`:428`、`:237` |
| `files-comments` | `document.querySelector('.v3-content .v3-md')` | `client/index.js:112` |
| **`shell-agent-console`** | **复用 explorer-v3 的 `.v3-loading` 类** | `client/index.js:174,175,293` ← **交底 §3.4 未列此条，我新发现的** |

`shell-agent-console` 用 `.v3-loading` 是**类名复用、不是 CSS 注入**：它自己不定义这个类，靠 explorer-v3 注入的 `<style>` 生效。explorer-v3 不在场时，这里的"正在加载…"会**没有颜色也没有内边距**——静默降级，不报错。

与交底 E7「5 处共 88 行」口径的差异我核过了，**两个口径都不完整**：
· 我按**注入点个数**数 = **6 个**（分布在 5 个文件）；按**注入的 CSS 文本行数**数 = **592 行**。

### P0-1 · 把 `--muted` 提到过线，把 `--accent` 分成"当文字用"和"当按钮底用"两个值

**【问题】** 次要文字和强调文字在两种主题下**全部未过 4.5:1**。这不是"不够好看"，是**读不清**——而且被读不清的恰恰是最高频的信息：文件名旁边的大小/时间、目录树的非活动项、.empty 空态文案、面包屑。

**【证据】**
- 值定义：`privhub/frontend/index.html:15-16`（light `--muted:#7a8699`、`--accent:#4a7bd6`）、`:19-20`（dark `--muted:#8a94a6`、`--accent:#5d8de0`）
- 使用面：`--muted` 骨架 30 处（`:39,41,47,57,58,71,74,79,81,100,118,123,129,133,136,139,153,160,166,167,168,175,197,209,229,235,249,253,270->274,279`）；`--accent` 作文字 15 处
- 主要按钮：`:77` `.btn-primary { background:var(--accent); color:#fff }` → light **4.12:1**、dark **3.31:1**
- 计算值见 §2.2-A

**【改法】** 只改 `index.html:14-23` 这几行，**不动任何插件文件**：

:root {

  --muted: #5c6779;        /* 原 #7a8699 → 对 --bg 5.05、对 --panel 5.42、对 --panel2 5.72 */

  --accent: #7ba6f0;       /* 原 #5d8de0 → 对 --bg 6.01、对 --panel 5.36、对 --panel2 4.64 */

**【验收】**

**【为什么排第一】** 因为它是**唯一一个"用户投诉不出来的硬损害"**。视觉上"不够精致"用户会说，但"我 45 岁看这小字有点累"用户不说，他只会少用。而修它的成本是一顿饭的时间——投入产出比在这一项上是压倒性的。

### P0-2 · 把 24 处 accent 色罩收敛成 2 个变量

**【问题】** 同一个"选中/高亮"的淡蓝底，被手写了 **7 种不同透明度**，散在 **24 处**（骨架 10 行 + 插件 client 13 处 + 服务端 1 处）；而且这个色（`rgb(90,130,200)`）**既不是 light accent 也不是 dark accent**。后果：切换深浅主题时，这些色罩**颜色不变**，而它上面的 `color: var(--accent)` 变了——**两层是错位的**。

服务端侧还有 1 处：privhub-svc-watermark/src/index.ts:74 —— 详见 §2.2-H 的纠错段。
叠加后的实际效果（算过）：`.14` 罩在 `--panel2` 上得到 `#e8eef7`，它与 `--accent #4a7bd6` 的对比只有 **3.53:1**——**`.ptab.on` 的深蓝文字，放在这块淡蓝底上，是没过的**。

- `.badge:97`、`.tree-item.active:126` → `--accent-soft`
- `.icon-btn.on:102`、`.file-table-row.sel:163`、`.abar-item.on:212`、`.u-project-chip:280` → `--accent-soft`

- `.EasyMDEContainer .CodeMirror-selected:252`（**文本选区**）→ 单开一个 `--select: color-mix(in srgb, var(--accent) 28%, transparent)`。**选区是"文字底下那一层"，不该和"元素底色"共用同一个值。**
- `index.html:317` + `svc-watermark/src/index.ts:74`（水印）→ **不要动**。它是安全功能（`:314-315` 有注释说明曾被上传抽屉盖住），视觉上越淡越好。单开 `--watermark` 即可。**注意：改它必须同时改服务端** —— 客户端 `auth-watermark/client/index.js:37` 把服务端给的 style 以**行内样式**套上去，行内优先级高于骨架 CSS，只改 `index.html:317` 是白改。

**【成本】中**（**不是小**——24 处里有 13 处在插件里、分布在 8 个文件。骨架那 10 行是小活，插件那 13 处虽是纯字符串替换，但要点 8 个文件，`files-template` 一个占 5 处）

### P1-3 · 用「token + 一条 `:where()` 兜底规则」做一次性转换，不改类名

**【问题】** P1-1 的映射表如果一条条手改，骨架加插件约 500+ 处，且插件里 249 处字号是内联 `:style` 或 `S.*` 字符串常量，**CSS 规则根本盖不住内联样式**。

**【证据】**
- 内联样式块：`explorer-v3/client/panel.js:561,564`（`paddingLeft`、`background`）、`files-template/client/index.js:243,260,267,299,305`、`files-versions/client/index.js:108`、`files-tags/client/index.js:99`、`svc-rag/client/index.js:31-47`（整套 `S.*` 常量）
- 内联样式的优先级**高于任何 CSS 规则**（除 `!important`），所以：**令牌层对它们无效**

**【改法】** 分三步，每步独立可回滚：

1. **先只定义令牌**（`index.html` `<style>` 开头加 `:root` 块）。这一步**零影响**。
2. **骨架内部逐条替换**：用「查找 + 替换」把骨架 12–342 行里的 px 换成 `var(--sp-*)` / `var(--fs-*)` / `var(--r-*)`。这一步**只动 1 个文件**。
3. **插件侧只做两件事**，按成本从低到高：
   - 3a. **能改 CSS 的改 CSS**（`explorer-v3/client/styles.js` 100 行、`admin-console/client/styles.js` 的 CSS 主体）——这是**收益最高的一步**，因为 `styles.js` 一条规则管很多元素。
   - 3b. **内联 `:style` 的改成引用令牌**：`panel.js:561` 的 `background: store.moveState.target === '' ? 'rgba(90,130,200,.12)' : ''` → 改成 `? 'var(--accent-soft)' : ''`。**这是纯字符串替换，不改逻辑。**
   - 3c. **`svc-rag` 的 `S.*` 常量放最后**：它是一套平行体系（43 行），牵动 1043 行文件里的引用。**建议先不动**——它是"自成一体的第三方风格"，动它等于重做它的视觉，收益不成比例。

**关于 `:where()` 兜底**：可以用

```css
:where(.tree-item, .ptab, .abar-item, .file-card) { border-radius: var(--r-2); }
```

`... :where()` 的权重是 **0**，所以**任何现有规则都能盖过它**——这是"安全的兜底"，不会像 `!important` 那样造成反噬。但它**同样盖不过内联样式**。

**【验收】** 浏览器 DevTools 里逐屏检查：`Computed` 面板里 `padding`/`font-size`/`border-radius` 应当能看到 `--sp-*` / `--fs-*` 的结果。**不要靠肉眼判断"看着一样"**——刻度收敛的价值在于**后来加东西时不再多一个值**，第一次改完看着一样是成功，不是失败。

**【成本】中**（骨架 1 文件约 200 处替换；插件 3 个文件约 60 处）

### P2-1 · 收 `z-index`：现在有 1 处同值冲突、1 处跨层倒置

**【问题】** `z-index` 全是手写魔数，取值 **900 / 999 / 1000 / 1100 / 1200 / 2000**。其中：
- **同值冲突**：`:316` `.watermark-overlay` 与 `:323` `#privhub-toast-host` **都是 2000**，都 `position:fixed`，谁在上面靠源码顺序决定。
- **跨层倒置**：`:216` `.abar-item:hover::after`（图标栏 tooltip）= **1200**，高于 `:257` `.modal-mask` = **1100**。**弹窗开着时，hover 左侧图标栏，tooltip 数值上压在遮罩之上**。
- `:314-315` 的注释记录了历史：水印原为 999，被"上传队列抽屉 z-index:1200"盖住，所以改成 2000。**那个 1200 的抽屉规则不在骨架里**（属插件样式）——我未核实其定义位置。

**【改法】** 分层令牌（这一步和 P1-1 表 4 的阴影必须同批做，因为"谁沉在谁上面"同时由 `z-index` 和 `shadow` 表达）：

```css
:root {
  --z-sticky:  100;   /* 顶栏 */
  --z-fab:     900;   /* .settings-fab:173 保留 */
  --z-mask:   1000;   /* .ctx-mask:243 */
  --z-menu:   1010;   /* .ctx-menu:238 —— 必须高于它自己的遮罩 */
  --z-tooltip:1050;   /* .abar-item:hover::after:216 —— 高于菜单，低于模态遮罩 */
  --z-modal:  1100;   /* .modal-mask:257 保留 */
  --z-toast:  2000;   /* #privhub-toast-host:323 */
  --z-watermark: 2100;/* .watermark-overlay:316 —— 水印是安全功能，必须最上 */
}
```

**关键的两处判断**：
- tooltip 从 **1200 降到 1050**（低于模态遮罩）。tooltip 是辅助信息，弹窗是当前任务——**当前任务不能被辅助信息盖住**。
- 水印从 2000 **提到 2100**（在 toast 之上）。理由不是审美，是 `:314-315` 已经写明它是安全功能。**这条我建议保留原注释一起改**，别删掉那段解释。

**【验收】**
1. 打开弹窗 → hover 图标栏 → **tooltip 应被弹窗遮罩压住**。
2. 上传文件（触发 toast）同时看水印 → **水印应可见**。
3. 右键菜单打开时，**菜单必须在它自己的遮罩之上**（`:243` 的 `.ctx-mask` 是 999、`:238` 的 `.ctx-menu` 是 1000，这一对目前是对的，改的时候别改坏）。

**【成本】小**（8 个变量 + 7 行替换；但要插件侧确认那个 1200 抽屉落在哪一层——**未核实**）

### P2-2 · 把注入式 `<style>` 的作用域收进插件自己的前缀（**以及一处"文档与代码不符"**）

**【问题】** 三个具体问题，严重程度差别很大：

1. **`admin-console/styles.js` 的文件头注释声明"样式作用域限定在 `.admin-root` 之内"（`:4-5`），但实际只有 26 行带 `.admin-root`**。绝大多数规则是**裸全局选择器**：`:43` `.ad-topbar`、`:221` `.ad-btn`、`:237` `.ad-input`、`:297` `.ad-table`、`:409` `.ad-dialog`、`:434` `.ad-toasts`……

   当前没出事的唯一原因是运气：我核过，`ad-` 前缀的 84 处命中**全部落在 `admin-console/client/` 内**，没有别的插件用这个前缀。**但这不叫作用域，这叫没人撞上。**
2. **跨插件的样式写入**：`files-office2/client/index.js:20-21` 直接写 `.v3-content:has(iframe.office2-frame)` —— 一个插件的样式表在改另一个插件的元素；`explorer-v3/client/styles.js:71-73` 反过来改骨架的 `.file-table-row`；`:28`/`:52-54` 又挂在 `files-edit-md` 的 `.md-inline-root` / `.md-src` 上。
3. **6 个注入点全部无法移除**（我逐一核过：全仓 `document.head.removeChild` 0 处、`adoptedStyleSheets` 0 处；`explorer-v3` 的 3 处 `.remove()` 是下载用的临时锚点；`shell.js:101-103` 的 `beforeUnmount` 只解绑 panelbus）。同一次页面会话内没有移除机会，**只有整页刷新（新 document）才能让它们消失**。

**【证据】** 逐点生命周期核实见 §2.2-G；`@media` 与 `.admin-root` 的行号分布见下方「我校正过的一处」。

**【改法】** 分三档，**按"值不值"排**：

**第一档 · 修 `@media (max-width: 767px)` 的作用域（我建议做）**：把 `styles.js:496-507` 那 7 条裸选择器补上 `.admin-root` 前缀，与同文件 `:463`/`:474` 两条保持一致。**这是纯一致性修复，零风险、约 7 行。** 严格来说它**不改任何当前可见效果**（因为没人占用 `ad-` 前缀），它的价值是**把"文件头那句声明"变成真的**——否则下一个人（或下一个 AI）会照着那句注释去相信它。

**第二档 · 跨插件样式写入（契约级，必须主子明示，我建议缓）**：把 office2 那几条规则收进它自己的类前缀。**做法**：不去改 `.v3-content`，而是让 explorer-v3 提供一个 `.v3-content--fill` 修饰类，office2 只负责给元素加这个类。**但这要改 explorer-v3 的模板 + office2 的 JS，且直接触碰 §4.5「禁止插件用 DOM 类名操作别的插件的界面」的现行形态**——它不是视觉改动，是**契约改动**。

**第三档 · 补重复注入哨兵（我原先建议做，现在撤回）**：我一开始按"模块可能被多次 import"建议给 4 个无哨兵的注入点补哨兵。**核实后这个前提不成立**：`loadManifests()`（`index.html:838`）用的是 `await import(p.entry)`，entry 是服务端按目录名现场拼的固定路径（`privhub-shell/server/index.ts:69`：`/privhub-plugins/${ent.name}/index.js`，**无版本号/时间戳查询串**），模块缓存使顶层副作用**只执行一次**。`index.html:827` 的注释也早就写明了这一点。
→ **所以补哨兵是纯保险，收益接近零。** 我把这条撤回，标为"可选"。真要补，照抄 `admin-console/styles.js:512-517` 那套已验证的写法即可：

```js
const MARK = 'data-privhub-files-comments'
if (!document.querySelector('style[' + MARK + ']')) {
  const el = document.createElement('style')
  el.setAttribute(MARK, '')
  el.textContent = CSS
  document.head.appendChild(el)
}
```

> **前提破了一次就不该继续用它推建议** —— 这一条的撤回本身，比它作为建议留着更有价值。

**【验收（第一档）】** 改完在 767px 以下宽度打开管理控制台，DevTools 里搜 `.ad-topbar` 的规则，`Matched CSS Rules` 应显示来自 `.admin-root .ad-topbar`。**不要只看"界面没变"就算过**——这一条的目标是名称与事实一致，不是视觉变化。

**【成本】小（第一档：约 7 行；第二档：大）**

## 4. 我建议不要做的

**1. 不要引入构建链。** §1 明说无打包是既定特性，收益是"改完刷新即生效"。我们的整套建议**没有一个需要打包**——令牌是 CSS 自定义属性、注入是 `<style>`、替换是字符串查找。**引入 PostCSS/Tailwind 会拿掉"改完刷新即生效"，而换来的只是"少打几个字"。这笔账不划算。**

**2. 不要建 11 阶 × 10 色的完整色板。** 书里推荐过 8–10 阶灰、10 色 × 5–10 阶，但那是给有设计系统的团队。你们是 1 个人 + AI。**只建我们要用的**：1 套灰阶（语义别名层，见 P0-1 / P1-1 表 1–4）、1 个 accent（拆 2 用）、4 个语义色、4 档阴影、8 档间距、8 档字号、6 档圆角。**总共约 50 个变量，够用，且看得住。**

**3. 不要为了美观去改 `.v3-content` / `.v3-loading` 这类跨插件类名。** 4 个插件在上面的依赖是**静默的**（不报错、只是不工作）。任何改名/删除都必须是独立的、有明确契约说明的改动，**不能夹在"视觉优化"里顺手做**。

**4. 不要动 `svc-rag` 的 `S.*` 那套红（`#f85149`/`#3d1d1d`/`#ffa198`）。** 它确实"不对齐"，但它是 43 行自成体系的常量、被 1043 行文件引用。改它等于重做那个插件的视觉，**收益（一个插件的危险色对齐）远小于成本**。如果哪天要动，**单独开一项，不要混在全局令牌里**。

**5. 不要给节点补更多 `box-shadow`。** 你们有 35 处 1px 边框。H1 的第一动作是"先数边框、去掉一半"，不是"再加阴影"。**先把 `--line`（P1-2）调对，再谈要不要去边框。** 如果发现去掉边框后区块分不开了，那时候上 `--sh-1` 才是有依据的。

**6. 不要做主题市场 / 多主题。** H9 说得很清楚：**投资默认值，不是投资可选性。** 现在两套主题（light/dark）是够的，先把这两套做对。`--ui-zoom`（`index.html:23`、`fontzoom.js:16-17`）和 `--v3-preview-font`（`panel.js:137`）这两个用户可调项**已经是对的选择**，别扩成"字体/圆角/密度/配色"四五个开关。

**7. 不要删 `outline: none`。** 它出现在 `:44`、`:67`、`:200`、`:1105`，是给鼠标用户去掉难看默认框的。正解是 `:focus-visible`（P0-3），不是把 `outline:none` 删掉让鼠标点击时也弹框。

## 5. 我判不了的

**最大一块：我从来没看过这个界面跑起来的样子。**
我量的全是源码里的数值。对比度是算的、字号分布是数的、`z-index` 是读的。**"这套刻度落地后到底好不好看"这件事，我给不出答案**——M6 那条明确写着：刻度建好后必须视觉验收，参数正确但看着别扭就改参数。**所以 P1-1 那张映射表是"起点"，不是"答案"。**

其次是几个我确实没有依据的问题（按重要性排）：

1. **12.5px 该砍向 12 还是 13？** 我给了 `--fs-sm`(12)，理由是它离 12 更近、且 13 已经是正文基准。但**如果 `.v3-md` 预览在 12px 下读着吃力**（中文 12px 确实偏小），就该砍向 13。**这需要眼睛，我没有眼睛。**
2. **`--muted` 提到过线会不会破坏"护眼"的既定诉求？** 交底 §2.2 提到两套主题叫「两套护眼配色」——**"护眼"是用户明写的目标，而我把次要文字压深了**。这两个目标在浅色主题上是**轻微冲突**的（压深 = 对比更强 = 更"硬"）。我的判断是对比度优先（M6 边界：可访问性是用户损害），但**这个取舍该由主子拍**。
3. **`--line` 从 1.35 调到 1.49 够不够？** 我给的是"到 1.5 附近的起点"，没有硬门槛。**再深就没有依据了。**
4. **阴影那 17 处替换，深色主题会不会"到处发亮"？** 深色下的阴影要加重不透明度，但加多少是手感。**我给的 `.20/.32` 是猜的**，标 `[存疑]`。
5. **插件的 px 值里，哪些是间距、哪些是尺寸？** 我用过两个口径：**全 px 属性 79 个值**（含 `1px` 边框宽、`width`/`height`、JS 拼接的缩进值），**仅 `padding`/`margin`/`gap` 是 23 个值 / 714 次**。前者不能当"间距刻度有 79 档"讲——**口径不纯**。搞混这两个数会得出差 3 倍的结论，所以我把两个都列出来了。
6. **`shell-agent-console` 复用 `.v3-loading` 是不是有意的契约？** 我看到的是 `client/index.js:174,175,293` 三处引用，但**没有注释说明**。如果是有意复用，那它需要一个正式的共享样式契约；如果是抄的，那是事故。**我判不了，只能报。**
7. **`.md-preview` 族（20 处引用）与 `.u-table` 的运行时宿主是谁？** 骨架模板里没有（`:975-1115` 我通读过），应由插件注入，**我没找到注入方**。
8. **`--ui-zoom` 用 `style.zoom`** —— `zoom` 不是标准 CSS（虽然现在大部分浏览器支持）。**这会不会跟将来的 `rem` 或容器查询打架，我没依据。** 但我要指出一个**眼前的冲突**：如果哪天有人想引入 `rem` 做缩放，会跟 `--ui-zoom` **双重缩放**。**这是我们这条路线里的一个钉子，先钉在这里。**
9. **窄屏到底怎么处理的？** 我原先写"插件里有没有 `@media` 我没查"，现在查了：**全仓 client 侧只有 3 个 `@media`，全在 `admin-console/client/styles.js:463`(1279px)、`:474`(1023px)、`:496`(767px)**。所以：**管理控制台有响应式，文件主界面一点没有**——骨架 0 个 `@media`，而它固定了 `.appbar` 52px（`:204`）、右侧详情 `.v3-detail` 320px（`styles.js:80`）、侧栏默认 220px（`index.html:452`）、`.view-inner` max-width 1100px（`:265-268`）。**这些固定宽度在窄屏如何退让，我没有依据**——交底 U9 提到的「<640px 收敛为图标 + hover 气泡」在骨架里找不到实现。**未核实。**
10. **文件行号的口径风险（一条方法论提醒）**：`Get-Content`、`[System.IO.File]::ReadAllLines` 与 `read` 工具在本仓给出的行号**不完全一致**（同一份 `index.html`：`read` 报 1130 行 / `[IO.File]` 报 1130 行 / `Get-Content` 报 1084 行；`admin-console/styles.js`：`read` 报 518 行 / `Get-Content` 报 511 行）。本文所有行号以 **`read` 工具**为准。委托出去的并行勘察若有行号偏移，是**工具口径差异、不是发现错误**——但也意味着**跨工具汇总行号时需要复核**，我在采纳插件侧与注入侧报告时已逐条回 `read` 校对过关键项。

## 6. 我这把视角适合干什么活

**一句话**：适合干**"在一个没有设计师、没有设计系统、但有大量共享 CSS 的项目里，找出最便宜的那几处改动并写出可直接抄的 CSS"**——也就是**建刻度、数边框、调对比度、把头 402 种颜色收敛成 12 种**这一类，且**只在视觉表层动手、不碰交互结构与信息架构**的活。

反过来说：**导航该分几级、50 个插件的入口该怎么组织、标签页 30 个上限该改成什么行为**——那些交给别的视角。我们只看"它长什么样"，不看"它该有什么"。
