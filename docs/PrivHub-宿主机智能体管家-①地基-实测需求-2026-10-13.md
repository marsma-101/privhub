## 2. 红线（三道都必须遵守）

1. **绝不许用 3180 / 3181**（真实数据）。只用分配给本道的端口。
2. **必须**同时设 `PRIVHUB_TEST_PORT` 与 `PRIVHUB_TEST_ROOT`（唯一目录），
   否则会与其它道共用 `privhub/.testroot` 而互相污染（D6 锁也救不了跨进程抢同一份 keys）。
3. 不改任何源码、不改既有测试断言、不 `git commit`、不 `git push`；
   不碰 `privhub/data/secret.key`、`deploy/`、`references/engine/`。

其它工程纪律：所有 node/npm 命令在 `privhub/` 内跑（后台 Bash 从仓库根起跑，须显式 `cd`）；
用 `> 日志 2>&1; echo EXIT=$?` 取退出码（别用管道，管道下 `$?` 是 `tail` 的）；
临时文件一律放 `C:\Users\Administrator\.claude\jobs\1dc2c93b\tmp\<道名>\`；
收尾必须杀干净自己拉起的进程、删临时目录、吊销自己签发的钥匙、删自己注册的用户。

**报告口径**：每条用例给 `PASS / FAIL / BLOCKED` + **能复现的命令** + **原始输出片段**。
FAIL 必须给最小复现；BLOCKED 必须说明卡在哪（如防火墙、缺依赖），**不许拿 PASS 顶替**。

## 3. 用例

### 甲道（端口 3201）—— 真实链路 / 治理 / 开关 / 审计 / 并发

**L1 真服务端 + 真 MCP stdio 全链路**
1. 起隔离实例：`PRIVHUB_TEST_PORT=3201 PRIVHUB_TEST_ROOT=<tmp>/root3201 node tests/run-all.mjs --spawn` 之外
   —— 改用直接起服务以便长期占用：
   `PRIVHUB_ROOT=<tmp>/root3201 node --import tsx/esm src/main.ts --port 3201`（后台，记 PID）。
2. 签发：`node mcp/butler-setup.mjs --url http://127.0.0.1:3201 --password admin123 --name 实测管家 --out <tmp>/cfg.json --json`
3. 自写一个**最小 MCP 客户端**（不许复用 `tests/mcp-protocol.mjs` 里的假后端）：
   `spawn(process.execPath, ['mcp/privhub-mcp.mjs'])`，env `PRIVHUB_URL` + `PRIVHUB_BUTLER_KEY`，
   按换行分隔 JSON-RPC 依次发 `initialize` → `notifications/initialized` → `tools/list` → `tools/call`。
- 判据：`initialize` 回 `protocolVersion === '2024-11-05'`；`tools/list` 恰好含
  `privhub_health` / `privhub_butler_status` / `privhub_me`；`butler_status` 的
  `capabilities` 八项齐全且 `files === 'write'`、`key.name === '实测管家'`、`user.role === 'admin'`。
- 证据：**原始请求/响应 JSON 全文**贴报告。

**L5 钥匙治理**
- `GET /privhub/api/agent/v1/butler/key`（会话）：只列 `type=butler`；
  条目**不含** `keyHash` / `key`；`expiresAt` 存在且在未来；`localOnly` 含 `127.*`。
- 连发两把（名字不同）：互不影响，各能自检。
- 吊销一把 → 该钥匙再调 `butler/status` **立刻失败**（记实际状态码与 code），另一把仍可用。
- DELETE 不存在的 id → `404 AGENT-4041`。

**L6 开关实时生效（真实例，非测试库）**
- `POST /privhub/api/cap/save {feature:'agent.butler', level:'none'}`（会话）→ 管家自检**立刻** `403 AGENT-4039`；
  开回 → 恢复。**磁盘级**：看 `<root>/data/capabilities.json` 前后变化（先确认它是 `PHENC1` 密文）。
- 关 `agent.butler.users` → 自检仍 `ok`，但 `capabilities.users === 'none'`，其余仍 `write`。

**L8 审计落盘**
- 触发几次管家调用后，查审计（`GET /privhub/api/audit` 或直接读 `<root>/data/audit.jsonl`）：
  断言存在 `actor`（或等价字段）**以 `ai:实测管家` 开头**的 `agent-butler-status` 记录；
  另有 `agent-butler-key-create` / `agent-butler-key-revoke`（会话身份，非 `ai:`）。

**L9 并发 / 幂等（D6 锁）**
- 并发签发 12 把管家钥匙（`Promise.all`），再并发吊销其中 6 把；
  最终 `GET` 列表 = 12 条且 6 条 revoked；`data/agent-keys.json` 无损坏（服务能继续读写，无 `corrupt` 迹象）；
  与既有内容钥匙**并存不冲突**（先签一把内容钥匙再跑并发）。

### 乙道（端口 3202）—— 安全对抗（红队视角）

**L3 非本机来源拒绝（AGENT-4038）**
- 用本机 **LAN IP** `http://192.168.18.26:3202/privhub/api/agent/v1/butler/status` + 管家钥匙
  → 断言 `403` 且 `code === 'AGENT-4038'`。
- 反证：同一把钥匙打 `http://127.0.0.1:3202/...` → `200`。
- 若被 Windows 防火墙拦在门外（连不上）→ 记 **BLOCKED** 并说明，**不得**改判为 PASS。

**L4 IPv6 回环（验证「回环归一」真的生效）**
- `http://[::1]:3202/privhub/api/agent/v1/butler/status` + 管家钥匙 → 断言 `200`。
- 这一条专测本批的改动：`authAgent` 把 `::1` / `::ffff:127.0.0.1` 归一为 `127.0.0.1`。
  若 `::1` 走不通而 `127.0.0.1` 通 → **FAIL**（说明归一没生效）。
- 同时验证**不放宽**：LAN 的 IPv6 地址（`2408:...` 或 `fe80::...`，若有）打过来 → 仍 `403 AGENT-4038`。

**L7 越界矩阵**
| 凭据 | 目标 | 期望 |
|---|---|---|
| 无 | `/butler/status` | 401 |
| 内容钥匙 `type=user`（普通用户绑定） | `/butler/status` | 403 `AGENT-4037` |
| 内容钥匙 `type=admin` | `/butler/status` | 403 `AGENT-4037` |
| 管家钥匙 | 内容通道 `/agent/v1/list`（项目） | 按内容通道规则（项目可读） |
| 管家钥匙 | 内容通道写项目 `/agent/v1/write` | 403 `AGENT-4032`（项目只读，不因"管家"身份放行） |
| 管家钥匙 | 网页会话专属 `/privhub/api/admin/...` | 401/403（管家 ≠ 会话） |
| 管家钥匙 | 关掉总闸后任意 `/butler/*` | 403 `AGENT-4039` |

- 另测：管家钥匙**不能**给自己提权（`POST /butler/key` 用管家钥匙调用 → 非会话 → 401/403）。

### 4.1 实测暴露的问题与处置

| # | 问题 | 级别 | 处置 |
|---|---|---|---|
| 1 | **`AGENT-4038` 分支不可达**：`authAgent` 的通用 IP 白名单检查（`401 AGENT-4014`）排在 `requireButler` 的来源检查（`403 AGENT-4038`）之前，而管家钥匙白名单恒为 `127.0.0.0/8` ⇒ 非本机请求永远先被白名单挡下。**安全效果无损**，坏的是契约：客户端按 `AGENT-4038` 分支处理会漏判 | 契约缺陷（非越权洞） | **已修**：`authAgent` 白名单失败时按 `type` 分型 —— 管家钥匙回 `403 AGENT-4038`，其它钥匙照旧 `401 AGENT-4014`。**保留**白名单本身（它同时护内容通道，防泄露的管家钥匙被远程用来读全部项目）。新增回归 J + integrity 契约 1 条 |
| 2 | 需求 §3 L10 给的命令**缺 `PRIVHUB_TEST_BASE`**，照抄会去连 3190 而假红 | 需求文档笔误 | **已修**（见上） |
| 3 | 需求 §3 L1 说 capabilities「八项齐全」，实际是 master + 8 分项 = 9 键 | 需求文档表述不精确 | 已在本表注明，判据按"8 分项齐全 + 全 write"成立 |
| 4 | 丙道首跑全量出现 **1 处偶发失败**：`refcheck` 的「孤儿附件」断言报 `read ECONNRESET`（传输层连接被重置，非断言失败）；单跑该套件 3/3 全绿、第二次全量 0 失败 | 既有套件的偶发（陈旧 keep-alive socket） | **未改**（属既有测试机制，改动需另立批次）。已如实登记 |

## 5. 附录：怎么自己起一个「长期存活」的隔离实例

本实测用了 `reports/butler-live-2026-10-13/boot.mjs`（起停 + 健康检查）；该目录为本地证据、不进 git，
故此处给出等价的最小做法（`tests/run-all.mjs --spawn` 会随套件把服务关掉，不适合长期占用）：

```bash
# 1) 造 root：数据目录 + 三个项目 + 四个 junction（L3 插件自动发现与依赖解析都靠它们）
ROOT=/c/tmp/privhub-probe
mkdir -p "$ROOT/data" "$ROOT/data-files/公共" "$ROOT/data-files/A项目" "$ROOT/data-files/B项目"
for d in src plugins frontend node_modules; do
  cmd //c mklink //J "C:\\tmp\\privhub-probe\\$d" "G:\\program\\dsh-SQL\\privhub\\$d"
done
# 2) 起服务（新 root ⇒ 自动种子 admin/admin123；服务监听所有网卡）
cd privhub && PRIVHUB_ROOT=C:/tmp/privhub-probe node --import tsx/esm src/main.ts --port 3211 &
# 3) 用 /privhub/api/health 等就绪；收尾 taskkill /PID <pid> /T /F
```

> 要点：`PRIVHUB_ROOT` 决定数据落点、也决定 `plugins/` 去哪找 ⇒ **root 里必须有 src/plugins/frontend/node_modules 四个 junction**，
> 否则插件发现落空、账号种子也不会生成。**每道务必用不同 root 与端口**（同 root 并发会互相污染密钥库）。
