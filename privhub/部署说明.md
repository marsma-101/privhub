# 私域枢纽（PrivHub）部署说明

> 本文档说明如何把私域枢纽从开发机部署到宿主机，并正式投入使用。

---

## 〇、目录结构（整理后）

```
privhub/
├── privhub-app/     ← 私域枢纽应用：后端插件 + Vue 前端 + 数据
│   ├── server/       ← 后端接口插件
│   ├── frontend/     ← Vue 前端
│   └── data/         ← users.json / sessions.json / trash.json / audit.log
├── data-files/      ← 文件存储根（公共/A项目/B项目 等项目文件夹）
├── engine/          ← 开源引擎底座（复制的 DSH 源码，参照原结构整体移入）
├── home/            ← profile 配置（独立 DSH_HOME）
├── start.bat        ← 启动脚本（在 engine/ 内执行 pnpm dsh）
└── 部署说明.md       ← 本文件
```

> 说明：`engine/` 是复制的开源引擎底座（与 DeepSeek Harness 同源，但属于本项目自己的引擎层）。
> 项目根只保留私域枢纽自己的内容，底座整体在 `engine/` 内，参照原源码结构。

## 一、系统概览

私域枢纽是一套**完全独立**的公司内部文件管理系统，基于开源引擎底座构建，与 DeepSeek Harness 无关。

- **前端**：Vue（登录页 + 顶栏 + 左侧项目树 + 中间文件列表 + 右侧预览 + 设置）
- **后端**：底座 `webServer` 注册的 HTTP 接口（登录/注册/项目/文件/预览/用户管理）
- **存储**：项目内部 `data-files/` 文件夹（文件本体） + `privhub-app/data/`（账号/会话）

## 二、部署步骤

### 1. 前置条件

宿主机需安装：
- **Node.js 22.19+ 或 24+**
- **pnpm 11.x**（`corepack enable` 后可自动获取）

### 2. 传输项目

把整个 `privhub/` 目录（即本文件夹）通过**向日葵 / 网盘**等，原样复制到宿主机任意磁盘位置（如 `D:\公司文件系统\privhub\`）。

> 注意：整个目录一起拷（含 `home/`、`privhub-app/`、`data-files/`、底座源码、`start.bat`）。文件路径全部用项目内部相对路径，放哪个盘都能跑。

### 3. 启动

在宿主机上**双击 `start.bat`**，或命令行进入目录执行 `start.bat`。

启动后控制台会显示：

```
============================================
  私域枢纽 PrivHub 正在启动...
  端口: 3181
  本机访问: http://127.0.0.1:3181
============================================
dsh web: http://127.0.0.1:3181 (LAN: http://192.168.x.x:3181)
```

### 4. 访问

- **宿主机本机**：浏览器打开 `http://127.0.0.1:3181`
- **局域网其他电脑**：浏览器打开 `http://<宿主机局域网IP>:3181`（IP 见上面启动输出的 `LAN: http://192.168.x.x:3181`）

## 四、日常运维

### 文件存储位置

文件就放在项目内的 `data-files/` 文件夹：

```
data-files/
├── 公共/        ← 一个项目
├── A项目/       ← 一个项目
└── B项目/       ← 一个项目
```

- **加文件**：直接把文件拷进对应项目文件夹，界面刷新即可看到。
- **建项目**：管理员在界面「＋项目」新建，或直接在 `data-files/` 下手动建文件夹。

### 账号数据

账号存在 `privhub-app/data/users.json`，密码为 scrypt 盐哈希（非明文）。会话存在 `privhub-app/data/sessions.json`。

### 停止服务

在 start.bat 运行的窗口按 `Ctrl+C`，或直接关窗口。

## 五、端口与网络

### 环境与端口对照（铁律）

| 环境 | 端口 | 用途 |
|------|------|------|
| **开发环境** | **3180** | 开发机上开发、测试、用户验收 |
| **生产环境** | **3181** | 宿主机部署后正式使用 |

### 上线流程（严格按此顺序）

1. **开发**：开发机 `privhub/` 目录，`start.bat` 以 `--port 3180` 启动、开发、测试。
2. **用户验收**：用户在开发机 `http://127.0.0.1:3180` 完成功能验收。
3. **部署**：验收通过后，整目录传到宿主机。
4. **生产测试**：宿主机 `start.bat`（`--port 3181`），再跑一次生产环境验收。

> 两个端口两套环境，绝不混用。开发测试用 3180，生产才用 3181。

### 网络

| 项目 | 值 |
|------|-----|
| 绑定 | `0.0.0.0`（局域网可访问） |

> 如需改端口，编辑 `start.bat` 里的 `--port 3181`，以及 `home/profiles/privhub/cordis.patch.yml` 里的默认回退值。
>
> 账号/会话/文件存储由 `start.bat` 注入的 `PRIVHUB_ROOT` 锚定项目根，不依赖进程 cwd，因此在 `engine/` 内启动也不会污染引擎目录。

> 局域网无法访问时，检查宿主机 Windows 防火墙是否放行对应端口。

## 六、交付前清理清单

部署到宿主机**之前**，在开发机做一次清理，确保交付物干净：

- [ ] 删除测试数据：`data-files/` 里开发期造的测试文件夹/文件（保留正式的项目文件夹）。
- [ ] 删除 `privhub-app/data/sessions.json`（清空历史登录会话）。
- [ ] 确认 `privhub-app/data/users.json` 只有正式账号（无测试注册的临时账号）。
- [ ] 确认 `privhub-app/` 下的临时测试脚本（smoke-*.mjs、test-*.mjs、package.json、node_modules）可随需清理或不影响运行。
